## BLOCKER

### B1. Work item G's failure leg leaks the timer goroutine and its abandon semantics are wrong (Codex r6 M1 = AGY r6 M1 — independent collision, verified)
`d.daemonCtx` is the RAW, never-cancelled parent (#5807,
`daemon_run.go:64-87`; production passes `context.Background()`,
`cmd/xpfd/main.go:504`). Signal aborts and plain phase errors return before
any gate close (`daemon_run.go:147-178`, `:794-832`). v6's
`select { <-startupReady; <-daemonCtx.Done() }` therefore has NO live arm on
a failed/aborted startup — a fired timer goroutine blocks forever
(`store_commit.go:819-821`). Process exit masks this for normal xpfd but
not for early-return/embedded Run users. And closing `startupReady` on the
failure path would be WORSE (it would authorize rollback against partial
initialization — the exact defect G exists to close).

Redesign (folds Codex's prescription): one exactly-once startup OUTCOME,
not a one-arm channel:
- `d.startupDone chan struct{}` — initialized in the production constructor
  (`daemon.go:1086-1108`, BEFORE the executor registration at
  `daemon_run.go:136`; a nil channel would hang the executor even on
  success). Closed exactly once on EVERY startup-exit path: on success at
  the linearization point (below); on the abort/phase-error return
  (`daemon_run.go:176-178`) via a deferred close registered before
  `runStartupOrAbort`.
- `d.startupOK atomic.Bool` — stored true ONLY at the success
  linearization point.
- `executeConfirmedRollback`: `<-d.startupDone`; `if !d.startupOK.Load() {
  log; return }` — then applySem. No select, no context dependence, no
  leak: every startup outcome closes the channel; only success sets OK.
  Gate-before-applySem is unchanged (boot apply holds applySem across
  startup; gating under it would deadlock).
- Linearization point: after the last late manager initialization
  (`daemon_run.go:435-511`), BEFORE exposing HTTP (`:587`) / gRPC (`:599`)
  — Codex's cleaner point; a rollback dispatched after it is semantically
  identical to a remote commit arriving at first server contact (already
  tolerated), and no apply runs concurrent with server construction.
- Signal-during-PHASE-5 inverse case: a rollback dispatched while a
  shutdown is pending is ordinary apply-vs-shutdown behavior
  (applySem-ordered, `daemon_run_shutdown.go:50`) — noted, not a defect.
- Existing executor test fixtures (`rollback_resync_test.go:31`,
  `bootstrap_rollback_test.go:24`) construct `Daemon` directly: they must
  initialize the gate (closed + OK) — listed as a required test migration;
  a nil gate must never silently mean "ready".
- The "acquires applySem FIRST" contract comments at
  `store_commit.go:327-334` and `daemon_apply_commit.go:611-628` must be
  reworded for gate-before-applySem.

### B2. The four-link exclusion's link (iv) fails on the cross-upgrade legacy path (Codex r6 M2 — verified end-to-end)
My v6 coexistence argument ("never-committed marker and committed cluster
config cannot coexist") is FALSE:
1. A first `commit confirmed` marks the store ever-committed AT COMMIT,
   not at confirmation (`store_commit.go:458-461`), while persisting
   `FirstCommit=true` for the window.
2. Recovery accepts an empty legacy `GuardedHash`
   (`store_persist.go:149-159`) and reconstructs `confirmPrevCfg=nil`
   solely from `FirstCommit` (`store_persist.go:241-242`).
3. The ACTIVE config — a cluster config committed on pre-topology-guard
   code — constructs `d.cluster` at boot (`daemon_run_bringup.go:164`).
4. Timer fires → `PromoteRollback` returns nil → `enterBootstrapMode`,
   which does NOT stop cluster comms (`bootstrap.go:321-478`).
So a pre-#5840 first confirmed standalone→cluster commit + crash in the
window + upgrade + restart yields bootstrap-with-live-cluster-runtime, and
a later corrected re-exit can run the RACE-2 writer against live HA
readers. The exclusion proof stands ONLY for records generated by
current-version guards. v7 must: scope the proof explicitly; state that
the legacy coexistence is possible and is PRECISELY why the plan converts
every reader uniformly rather than trusting reachability (A1 covers this
path by construction); and list the behavior-level follow-ups (guard
recovery against FirstCommit+cluster records, or stop cluster comms in
`enterBootstrapMode` when `d.cluster != nil`) as OUT of scope with a
follow-up issue to file at /engineer time.
