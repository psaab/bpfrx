**Findings**

1. **MAJOR: Path A as written will not fix exact queues.**  
   Exact queues do not use the generic accumulating refill path. `maybe_top_up_cos_queue_lease` caps the local bucket at `lease_bytes`: it returns when `queue.hot.tokens >= lease_bytes`, and otherwise requests only `lease_bytes - queue.hot.tokens` [userspace-dp/src/afxdp/cos/token_bucket.rs:184]( /home/ps/git/bpfrx/.claude/worktrees/1630-research-cos-equalize-rootcause/userspace-dp/src/afxdp/cos/token_bucket.rs:184 ), [token_bucket.rs:188]( /home/ps/git/bpfrx/.claude/worktrees/1630-research-cos-equalize-rootcause/userspace-dp/src/afxdp/cos/token_bucket.rs:188 ), [token_bucket.rs:191]( /home/ps/git/bpfrx/.claude/worktrees/1630-research-cos-equalize-rootcause/userspace-dp/src/afxdp/cos/token_bucket.rs:191 ). For 100 Mbps, `lease_bytes` is the same 200 us class quantum, about 2500 B, via `rate * 200us` [shared_cos_lease/mod.rs:703]( /home/ps/git/bpfrx/.claude/worktrees/1630-research-cos-equalize-rootcause/userspace-dp/src/afxdp/types/shared_cos_lease/mod.rs:703 ) and the 200 us constant [shared_cos_lease/mod.rs:240]( /home/ps/git/bpfrx/.claude/worktrees/1630-research-cos-equalize-rootcause/userspace-dp/src/afxdp/types/shared_cos_lease/mod.rs:240 ). After sending one 1500 B frame, the queue has about 1000 B left; the next epoch tops it back only to about 2500 B, not 5000 B. That resolves the contradiction.

2. **MAJOR: the v8 lease epoch reset is not the irreducible floor, but the current acquire request policy makes it one.**  
   `acquire_v8` grants up to `min(requested, class_room, my_room)` [shared_cos_lease/mod.rs:1092]( /home/ps/git/bpfrx/.claude/worktrees/1630-research-cos-equalize-rootcause/userspace-dp/src/afxdp/types/shared_cos_lease/mod.rs:1092 ), while each epoch cap is freshly `rate * min(elapsed, 200us)` [rotate_epoch_v8.rs:215]( /home/ps/git/bpfrx/.claude/worktrees/1630-research-cos-equalize-rootcause/userspace-dp/src/afxdp/types/shared_cos_lease/rotate_epoch_v8.rs:215 ). If the worker requested a full epoch’s new credit and allowed local carry, the local bucket could carry frame remainder across epochs. Today it cannot, because the request is only to refill to one lease quantum. So Path B, “remove `.min(quantum)` and rely on `queue.hot.tokens`,” fails for exact queues unless the top-up watermark/request is also changed.

3. **MAJOR: DRR deficit outside the secondary budget is necessary but insufficient if it remains bounded by current `queue.hot.tokens`.**  
   The selectors currently use `queue.hot.tokens.min(cos_guarantee_quantum_bytes(queue))` [queue_service/mod.rs:879]( /home/ps/git/bpfrx/.claude/worktrees/1630-research-cos-equalize-rootcause/userspace-dp/src/afxdp/cos/queue_service/mod.rs:879 ), [queue_service/mod.rs:985]( /home/ps/git/bpfrx/.claude/worktrees/1630-research-cos-equalize-rootcause/userspace-dp/src/afxdp/cos/queue_service/mod.rs:985 ). Replacing that with `deficit.min(tokens)` still leaves exact 100 Mbps pinned near 2500 B tokens per visit. The fix must also let exact `queue.hot.tokens` accumulate above one lease quantum, or make the DRR/lease-deficit drive larger `acquire_v8` requests while still debiting actual sent bytes [tx_completion.rs:512]( /home/ps/git/bpfrx/.claude/worktrees/1630-research-cos-equalize-rootcause/userspace-dp/src/afxdp/cos/tx_completion.rs:512 ), [tx_completion.rs:549]( /home/ps/git/bpfrx/.claude/worktrees/1630-research-cos-equalize-rootcause/userspace-dp/src/afxdp/cos/tx_completion.rs:549 ).

4. **MINOR-to-MAJOR depending on implementation: the burst cap language is under-specified and dangerous.**  
   Large classes are already bounded per drain by `TX_BATCH_SIZE == 64` [afxdp/mod.rs:225]( /home/ps/git/bpfrx/.claude/worktrees/1630-research-cos-equalize-rootcause/userspace-dp/src/afxdp/mod.rs:225 ) and the drain loops stop at that count [queue_service/drain.rs:56]( /home/ps/git/bpfrx/.claude/worktrees/1630-research-cos-equalize-rootcause/userspace-dp/src/afxdp/cos/queue_service/drain.rs:56 ). A “small multiple of MTU” deficit cap would under-deliver high-rate queues. Use the existing per-visit frame cap/RR advancement as the latency bound, and cap only idle accumulation with a rate-scaled bound.

5. **Q5: yes, non-exact guarantee queues are affected, but by a simpler path.**  
   Non-exact queues do use `refill_cos_tokens`, which genuinely accumulates to `buffer_bytes` [queue_service/mod.rs:1034]( /home/ps/git/bpfrx/.claude/worktrees/1630-research-cos-equalize-rootcause/userspace-dp/src/afxdp/cos/queue_service/mod.rs:1034 ), [token_bucket.rs:262]( /home/ps/git/bpfrx/.claude/worktrees/1630-research-cos-equalize-rootcause/userspace-dp/src/afxdp/cos/token_bucket.rs:262 ). They are still clamped by the guarantee quantum at selection [queue_service/mod.rs:1064]( /home/ps/git/bpfrx/.claude/worktrees/1630-research-cos-equalize-rootcause/userspace-dp/src/afxdp/cos/queue_service/mod.rs:1064 ). So the quantum-remainder bug applies there too, but the exact-v8 lease top-up cap is an additional exact-only blocker.

**Bottom Line**

The measurement is not misread in the broad sense: `park_root=0` and high `park_queue` support “per-class gate, not root gate” [measurement-r1.txt:3]( /home/ps/git/bpfrx/.claude/worktrees/1630-research-cos-equalize-rootcause/docs/research/1630-cos-equalize-rootcause/measurement-r1.txt:3 ), [measurement-r1.txt:26]( /home/ps/git/bpfrx/.claude/worktrees/1630-research-cos-equalize-rootcause/docs/research/1630-cos-equalize-rootcause/measurement-r1.txt:26 ). But v2 is too narrow when it says the selector/drain quantum remainder is the discard point. For exact queues, the local bucket is also effectively watermarked to one 200 us lease quantum, so neither Path A nor Path B as currently sketched is sufficient.

Required revision: Path A must include exact-v8 lease/top-up carry-forward semantics, not just scheduler secondary-budget DRR.
