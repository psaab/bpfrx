**Findings**

1. Rollback serialization is still unsafe. v2 says the daemon-side rollback handler should call `d.applyConfig` ([plan.md](/home/ps/git/bpfrx/.claude/worktrees/1879-research/docs/research/1879-install-simplify/plan.md:559)), but `performAutoRollback` mutates `s.active/s.compiled` before it invokes the callback ([store.go](/home/ps/git/bpfrx/.claude/worktrees/1879-research/pkg/configstore/store.go:1114), [store.go](/home/ps/git/bpfrx/.claude/worktrees/1879-research/pkg/configstore/store.go:1146)). `d.applyConfig` only acquires `applySem` around apply, not around the store rollback ([daemon_apply.go](/home/ps/git/bpfrx/.claude/worktrees/1879-research/pkg/daemon/daemon_apply.go:66)). That violates the repo’s explicit commit→apply atomicity contract ([apply_serialize_test.go](/home/ps/git/bpfrx/.claude/worktrees/1879-research/pkg/daemon/apply_serialize_test.go:1), [configstore/README.md](/home/ps/git/bpfrx/.claude/worktrees/1879-research/pkg/configstore/README.md:113)). A concurrent commit can interleave after rollback changes the store but before rollback applies, leaving store=new commit and kernel=rollback. The plan needs a daemon-owned auto-rollback path that holds `applySem` across rollback promotion and apply, not just a callback to `d.applyConfig`.

2. “Synthesized bootstrap config” is not enough to re-enter bootstrap mode. Normal apply of an empty compiled config can clear FRR and VRRP: FRR `ApplyFull` clears on empty content ([manager.go](/home/ps/git/bpfrx/.claude/worktrees/1879-research/pkg/frr/manager.go:211)), and VRRP removes undesired instances ([manager.go](/home/ps/git/bpfrx/.claude/worktrees/1879-research/pkg/vrrp/manager.go:207)). But bootstrap mode promises no networkd takeover, no AF_XDP attach/dataplane load, and no FRR writes ([plan.md](/home/ps/git/bpfrx/.claude/worktrees/1879-research/docs/research/1879-install-simplify/plan.md:608)). After a failed first takeover, stale xpf networkd files and dataplane state already exist. If rollback suppresses subsystem writes, stale artifacts remain; if it calls normal `applyConfig`, it calls `d.dp.ApplyConfig` ([daemon_apply.go](/home/ps/git/bpfrx/.claude/worktrees/1879-research/pkg/daemon/daemon_apply.go:453)), and userspace apply still ensures the helper process exists ([manager.go](/home/ps/git/bpfrx/.claude/worktrees/1879-research/pkg/dataplane/userspace/manager.go:641)). The plan needs an explicit `enterBootstrapMode` cleanup/reconcile sequence: clear xpf networkd artifacts except lifeline, clear FRR/VRRP, detach/stop dataplane/helper, and suppress forwarding startup.
