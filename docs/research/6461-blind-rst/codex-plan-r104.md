1. **BLOCKER — `MaterializeOutcome` has overlapping producers with no precedence.** Every closing shared materialization is validator-refused (`docs/research/6461-blind-rst/plan.md:1301-1310`), but the same operation can also be `AdoptedPreservingDeadline` (`:1328-1352`), `OverdueSkipped` (`:1353-1381`), or `UpsertRefused` when the synced upsert encounters a non-peer predecessor (`userspace-dp/src/session/install.rs:310-315`). The exclusive six-way enum provides no precedence (`plan.md:1686-1706`). Selecting `ValidatorRefused` for an overdue or failed-upsert close loses the authority fences attached to the other outcome. Specify precedence—e.g. overdue, actual upsert failure, adoption, then successful initial validator-refused install—or split validation verdict and transition result into separate fields.

2. **BLOCKER — `UpsertRefused` is not carried through the complete consumer contract.** The type paragraph says it gates teardown/cache/commit like `OverdueSkipped` (`plan.md:1699-1703`), but the normative five-consumer list explicitly guards teardown only for `OverdueSkipped` (`:1723-1732`). More importantly, only `OverdueSkipped + MissingNeighbor` is mapped to live-backed `ExistingResolved` (`:1740-1744`, `:1837-1840`). On `UpsertRefused + MissingNeighbor`, promotion no-ops because the disposition is not `ForwardCandidate` (`userspace-dp/src/afxdp/session_glue/promote.rs:86-90`), leaving the non-peer predecessor installed. Without an explicit composition, the common arm can derive/allocate and install/publish a raw-flags `MissingNeighborSeed` (`userspace-dp/src/afxdp/poll_descriptor/mod.rs:4662-4829`), replacing the predecessor via `userspace-dp/src/session/install.rs:139`. Require `UpsertRefused + MissingNeighbor → ExistingResolved`, S2 buffer-only, with no seed transaction. `ValidatorRefused` is otherwise safe once precedence is fixed: its successful probation install makes table state agree with S2.

3. **BLOCKER — The placeholder OUT lacks staging across the purge decision.** Placeholder substitution occurs before `keep_transient` is computed (`userspace-dp/src/afxdp/shared_ops.rs:602-628`; `userspace-dp/src/afxdp/session_glue/mod.rs:1157-1197`), while the SSOT says that OUT is accumulated into the resolved displaced set (`plan.md:1754-1762`). If accumulated immediately, a purge-class close invalidates P’s cache family even though materialization never ran and P remains installed; purge deletes only the shared/canonical key (`userspace-dp/src/afxdp/session_glue/promote.rs:181-190`). That changes the master cache behavior promised at `plan.md:1661-1676`: the close bypasses cache, but master permits the next ACK to hit P before resolution (`userspace-dp/src/afxdp/flow_cache.rs:352-358`; `poll_descriptor/mod.rs:298-327`). Stage the placeholder identity and commit it only on the site-2c materialization branch; discard it for purge and non-materializing ICMP callers (`icmp_embed/nat_match_v4.rs:78-95`, `nat_match_v6.rs:100-125`, `return_resolution.rs:20-28`). The inline-current/separate-batch storage ownership itself is sound.

4. **HIGH — The three-family bound and promotion producer remain incomplete.** P + removed K + newly installed S2 already consume three identities, after which the immediately following promotion is also required to record what it displaces (`plan.md:1747-1755`, `:1777-1781`). The fixed array is safe only if it deduplicates by alias-family inputs—key, NAT, and orientation—but equality, duplicate handling, and overflow behavior are unspecified. Conversely, an `UpsertRefused → promotion` installs S2 through a direct local→local update (`userspace-dp/src/afxdp/session_glue/mod.rs:1235-1253`; `userspace-dp/src/session/mod.rs:1350-1370`, `:1373-1475`), yet the contract includes the resulting S2 family only for “install/adopt” and records only the displaced old identity for promotion. It must record both old K and resulting S2, plus P if present. The promotion API currently returns metadata/bool, not its preimage (`session_glue/promote.rs:71-140`; `session/mod.rs:1673-1675`), so its OUT contract also needs naming.
