2. **BLOCKER — `rollback_flow` is not the inverse of the proposed import reservation transaction.**

   The plan routes non-persistent port-bearing imports through `reserve_flow`, rejects reservation failures without publishing, and uses `rollback_flow` for post-reservation failures ([plan.md:1018](/home/ps/git/kimi-xpf/.claude/worktrees/6461-research-blind-rst/docs/research/6461-blind-rst/plan.md:1018), [plan.md:1086](/home/ps/git/kimi-xpf/.claude/worktrees/6461-research-blind-rst/docs/research/6461-blind-rst/plan.md:1086)). Concrete trace:

   - B has peer-owned E1 represented as flow F with translation P.
   - Replacement E2 has the same flow key but translation Q, which another B allocation already owns.
   - `reserve_flow(F,Q)` removes E1’s record and frees P before attempting Q ([allocator.rs:1671](/home/ps/git/kimi-xpf/.claude/worktrees/6461-research-blind-rst/userspace-dp/src/nat/allocator.rs:1671)).
   - Q’s occupancy reservation then fails ([allocator.rs:1682](/home/ps/git/kimi-xpf/.claude/worktrees/6461-research-blind-rst/userspace-dp/src/nat/allocator.rs:1682)). E2 is not published, but E1’s published decision now points at unreserved P. Another flow can claim P through the normal allocation path, producing the prohibited reverse-NAT alias.

3. **BLOCKER — The migration gate copies ownership into B without transferring the exact-A tokens that later release it.**

   Every `NatHoldToken` owns the exact allocator A through `Arc<PortAllocator>` ([plan.md:1290](/home/ps/git/kimi-xpf/.claude/worktrees/6461-research-blind-rst/docs/research/6461-blind-rst/plan.md:1290)) and releases that allocator through later reap/RAII paths ([plan.md:1433](/home/ps/git/kimi-xpf/.claude/worktrees/6461-research-blind-rst/docs/research/6461-blind-rst/plan.md:1433)). In-place refresh only swaps forwarding-state Arcs; it does not retokenize existing worker side maps ([snapshot_refresh.rs:319](/home/ps/git/kimi-xpf/.claude/worktrees/6461-research-blind-rst/userspace-dp/src/afxdp/coordinator/snapshot_refresh.rs:319), [snapshot_refresh.rs:397](/home/ps/git/kimi-xpf/.claude/worktrees/6461-research-blind-rst/userspace-dp/src/afxdp/coordinator/snapshot_refresh.rs:397), [loop_body/mod.rs:467](/home/ps/git/kimi-xpf/.claude/worktrees/6461-research-blind-rst/userspace-dp/src/afxdp/worker/loop_body/mod.rs:467)).

   Thus T_A may survive the cut. When E1 later reaps, T_A cannot decrement the holder copied into B because A is closed and the token has no B handle. Copying that count literally leaves a permanent B ghost reservation and eventual pool exhaustion. Omitting the unretargetable count instead lets B free/reissue P while E1’s existing session can still forward using P. The plan’s statement that a stale A holder “fails transiently and re-resolves” does not work for an RAII `Drop`, which has neither the current allocator nor a retry channel. Temporary-stop escrow can preserve the same stale A token and therefore does not resolve this ownership mismatch.

   **Required change:** use one of three explicit lifecycles: quiesce and retokenize every worker/queue/escrow holder before publishing B; make tokens reference a stable allocation indirection atomically retargeted to B; or retain a retired-A→B release-forwarding record until every pre-cut token is consumed. The current “copy, close A, no bridge” contract cannot provide both collision safety and eventual release.
