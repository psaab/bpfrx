1. BLOCKER — The strong OPENING proof is bypassed by site 2b. When the reverse half is absent, a first reverse SYN-ACK can miss normal lookup, match the forward NAT entry, and synthesize a reverse entry (`userspace-dp/src/afxdp/session_glue/mod.rs:1264-1284`; `userspace-dp/src/afxdp/shared_ops.rs:638-665,824-865`). Section 5.6 validates site 2b only for closing packets, so an unproven spoofed SYN-ACK can still pin the family. The mutual-exclusion proof is sound only for an already-installed local reverse hit; site 2b needs the exact OPENING proof plus explicit proof-failure install/publication semantics.

2. BLOCKER — The identity token lacks a complete producer contract. A cacheable fresh ForwardFlow install returns only `bool`, creates its epoch internally, and proceeds to the common cache insertion without a `ResolvedFlowSessionDecision` (`userspace-dp/src/afxdp/poll_descriptor/mod.rs:2449-2458,3900-3959`; `userspace-dp/src/session/install.rs:139-152`). Reverse synthesis likewise returns `(SessionLookup, bool)` (`userspace-dp/src/afxdp/shared_ops.rs:824-895`), while forward-wire matches carry no epoch (`userspace-dp/src/session/lookup.rs:258-292`; `userspace-dp/src/session/entry.rs:208-213`). Materialization also currently returns no installed identity (`userspace-dp/src/afxdp/session_glue/mod.rs:1092-1121`). Every successful install/adopt path must return its final token; otherwise cached data can carry `None` and never advance its anchor.

3. BLOCKER — A lookup token becomes stale during the same resolve. Lookup/materialization precedes `maybe_promote_synced_session`, but the resolved result is built afterward (`userspace-dp/src/afxdp/session_glue/mod.rs:1157-1261`). Successful promotion can change NAT/orientation and always advances `install_epoch` (`userspace-dp/src/session/mod.rs:1344-1397`). The document never replaces the pre-promotion token with the final promoted identity, so the current packet’s commit hook and newly cached entry can immediately fail their own validation.

4. BLOCKER — Cache-hit revalidation is not mechanically safe. The cited `lookup_with_origin` mutates close state, timestamps, timeout, companion state, and the wheel before returning (`userspace-dp/src/session/lookup.rs:105-218`). The current cache path also calls `touch_if_stale` before final forwarding (`userspace-dp/src/afxdp/poll_descriptor/flow_cache_hit.rs:295-301`; `userspace-dp/src/session/mod.rs:1118-1133`). A dedicated atomic helper must first compare canonical key, NAT, orientation, and epoch, then perform permitted mutations; the existing touch must be covered by the same guard.

5. BLOCKER — The token binds only the matched reverse entry, not the forward anchor store. Reverse commits are specified to use the `account_packet`-style hop, which derives a forward key and mutates whichever entry currently occupies it (`userspace-dp/src/session/mod.rs:1177-1205`). In the document’s supported stale-R1/replacement-K2 state, R1’s token can validate while K2 receives R1’s anchor sample. The commit hook needs atomic family reciprocity and forward-generation validation, or a token that also binds the authoritative forward entry.

A stale active descriptor can therefore continue forwarding while the replacement never refreshes, clears probation, or learns anchors. `Some(token)` mismatch should evict and re-resolve; intentional `None` purge/sessionless parity must remain distinct.
