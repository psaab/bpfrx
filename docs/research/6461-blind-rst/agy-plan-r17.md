#### 1. Reconcile Hold Escrow Verification (§5.2 v9.7)
* **Abandonment Leak Path**: Fully covered. Escrowed tokens are stored in `PreservedReconcileState`. On bring-up failure or abandonment, dropping/releasing `PreservedReconcileState` executes `.take()` / `Drop` on all escrowed `NatHoldToken`s, decrementing each allocation's refcount. If workers have already exited, the refcount drops to 0 and frees the allocation via standard sweep/allocator cleanup. No tokens leak.
* **Freed-Port Race Prevention**: Fully effective. Transferring ONE `NatHoldToken` per allocation into `PreservedReconcileState` *before* joining workers (`teardown.rs:54/80`) maintains refcount $\ge 1$ across worker exit and table drain. This prevents premature allocation destruction and port theft before bring-up transfers escrowed tokens back into replayed entries (`bringup.rs:421`).
