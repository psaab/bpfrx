## Verbatim review

PLAN NO

1. **BLOCKER — The admission redefinition is contradictory and the dispatch-drop residual is attacker-inducible.** Section 5.8 treats `!recycle_now` as commitment and permits later dispatch loss, while sections 5.2/9 still require wire/local-stack delivery and explicitly prohibit learning or probation clearing on redirect-inbox overflow (`plan.md:656-680`, `:1835-1842`, `:3384-3392`, `:3585-3594`). Mechanically, the postblock only queues a request (`poll_descriptor/flow_cache_hit.rs:507-548`); dispatch occurs afterward (`worker/lifecycle.rs:209-281`), where attacker-chosen geometry or load can cause MTU/build/queue loss (`tx/dispatch/mod.rs:728-747`, `:864-928`, `:1017-1277`; `umem/mod.rs:1257-1321`). An attacker can fill the redirect queue, land one in-window non-close sample, have it update the anchor but drop before egress, then use contiguous samples to walk the anchor without endpoint observation. Calling that unreachable does not preserve the stated invariant.

2. **BLOCKER — The in-poll invalidation drain cannot run at the specified ownership level.** `poll_binding_process_descriptor` owns and loops over the entire RX batch (`poll_descriptor/mod.rs:110-131`); `poll_binding` regains control only after that batch returns (`worker/lifecycle.rs:209-225`). Therefore the proposed poll-binding-level drain “before the next descriptor” cannot happen. It also contradicts the existing SSOT, where current-binding invalidation consumes only `report.displaced` inline and `WorkerScratch` feeds only post-batch sibling fan-out (`plan.md:2530-2541` versus `:2860-2877`). A delayed new-family invalidation can evict descriptor 1’s freshly cached S2, contrary to the test at `plan.md:3477-3484`.

3. **BLOCKER — The invalidation family and producer set are incomplete.** The claimed complete family omits `reverse_canonical`: reply matching accepts both reverse-wire and reverse-canonical (`session/key.rs:19-26`), and both are separately indexed (`session/mod.rs:1920-1933`) and consumed (`session/lookup.rs:222-250`). Additionally, LocalDelivery removes K before invoking the installer (`afxdp/forwarding/local_delivery.rs:90-105`; `session/lookup.rs:407-418`), so installer-only instrumentation cannot record K’s old family. HA refresh/demote also reindexes through `refresh_for_ha_transition` (`session/mod.rs:1627-1666`) although the command producer list names only upserts. Finally, no capacity/overflow contract reconciles these old+new families with the zero-allocation requirement; one fresh descriptor can install both forward and reverse entries (`poll_descriptor/mod.rs:2449-2458`, `:2777-2787`).

4. **BLOCKER — Probation adoption preserves the wrong lifecycle authority.** The new rule says materialization seeds from S2’s trusted replica close bits (`plan.md:1483-1494`), but the adoption contract preserves K’s `closing=false/reset=false` while adopting S2’s decision/metadata (`plan.md:1631-1641`), and section 9 asserts those alive flags carry (`:3413-3426`). Thus K-alive→S2-RST resurrects S2 alive; K-closing→new-S2-alive transfers stale close authority across identities. The current upsert derives timeout/closing/reset entirely from supplied flags (`session/install.rs:382-400`). Adoption must take S2’s trusted lifecycle bits and preserve only probation plus the absolute deadline.

5. **BLOCKER — The stable-ID discriminator still lacks transport to the critical promote.** Materialization consumes `resolved.shared_entry` (`session_glue/mod.rs:1092-1119`), while the specified `(SessionLookup, MaterializeReport)` has no family-ID field (`plan.md:2195-2208`). The subsequent promotion receives decision/metadata/origin/raw flags but no S2 ID (`session_glue/mod.rs:1235-1252`; `session_glue/promote.rs:99-107`). This is load-bearing when synced upsert refuses over K (`session/install.rs:310-315`): K remains installed while the dispatch carries S2, so reading the table yields K’s ID and cannot classify the promote as a different-family replacement. Carry the incoming S2 ID explicitly; successful zero-wire-ID upserts must instead carry the final freshly minted ID.

6. **BLOCKER — A different-family reverse promotion destroys the expected-forward binding.** The replacement branch explicitly zeroes `fwd_companion_id` (`plan.md:2024-2031`, `:2725-2735`), yet a reverse S2’s `expected_fwd_id` is the family proof required for every later anchor/close hop. The reachable path is shared reverse S2 → non-peer K → upsert refusal (`install.rs:310-315`) → promotion (`session_glue/mod.rs:1235-1252`, `session_glue/promote.rs:99-107`). `SessionUpdate` is specified to carry only S2’s own ID, not its expected forward ID. It must carry both. The generic SharedPromote publisher must also read back/publish the final reverse entry’s expectation; today it constructs a replica from its arguments and returns only metadata (`session_glue/promote.rs:116-140`).

7. **BLOCKER — “Promote using effective stored state” has no complete source, especially for delayed promotion.** The materialize report contains no lifecycle bits, the shared entry is consumed, and current promotion has one raw `tcp_flags` input used by both `SessionUpdate` and the published replica (`session_glue/mod.rs:1092-1119`, `:1235-1252`; `session_glue/promote.rs:99-138`). A report-only fix would still fail when probation suppresses immediate promotion and a later ACK promotes the entry. Every promotion must source the final trusted `closing/reset` state from the live post-transition entry and publish it; raw flags may govern eligibility/accounting only. `observed_tcp_flags` is unsuitable because accounting deliberately ORs refused raw closes into it (`session/mod.rs:1177-1210`).

8. **HIGH — The capacity-refused site-2b close state is not closed under cross-worker observation.** An accepted close whose reverse install fails marks only the current worker’s F; capacity refusal returns before installing (`session/install.rs:113-125`), and publication remains conditional on successful R installation (`afxdp/shared_ops.rs:857-892`). The original alive F was already shared-published/replicated (`poll_descriptor/mod.rs:2560-2615`), while lookup marking is table-local (`session/lookup.rs:105-128`, `:198-212`). Another worker can therefore match the stale alive shared F and synthesize/publish an alive R, defeating the inheritance and companion-lifetime claim (`session/expire.rs:296-320`, `:468-523`). The accepted F close state needs identity-safe propagation even when R installation refuses.

9. **MEDIUM — The accounting fallback omits non-closing OPENING-proof refusals.** A Local OPENING ACK/PSH-ACK that fails the strong proof is forwarded without installing R (`plan.md:1356-1379`). The normal accounting lookup then misses R and returns without deriving F (`session/mod.rs:1177-1205`; `poll_descriptor/mod.rs:3478-3503`). Yet the fallback producer list covers only accepted-close capacity refusal and `ValidatorRefused` close (`plan.md:1530-1546`). Every Local identity-agreeing proof/validator refusal that forwards without R needs the fallback; Shared and identity-mismatch cases should remain excluded.
