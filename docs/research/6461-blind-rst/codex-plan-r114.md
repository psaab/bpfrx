Establishment promotion occurs inside `lookup_with_origin`’s post-borrow phase (`userspace-dp/src/session/lookup.rs:129-218`), but `effective_transition` is produced only after lookup returns and materialization runs (`userspace-dp/src/afxdp/shared_ops.rs:594-613`, `userspace-dp/src/afxdp/session_glue/mod.rs:1157-1199`). Then establishment should be removed from the report consumers rather than consuming an unavailable report.

BLOCKER — Canonical-key carriage still has no mechanically valid cache shape. `FlowCacheEntry.key` must remain the packet-query key: construction stamps `flow.forward_key`, and hashing, lookup, and dedup all use it (`userspace-dp/src/afxdp/flow_cache.rs:578-581`, `:962-989`, `:1046-1065`). 3. BLOCKER — A canonical key alone is not replacement-safe. Same-key synced upsert removes/reinstalls with a new epoch (`userspace-dp/src/session/install.rs:310-351`); `update_session` can change NAT/orientation and epoch while retaining the key (`userspace-dp/src/session/mod.rs:1344-1397`). Worker `UpsertSynced` performs that replacement without flow-cache invalidation (`userspace-dp/src/afxdp/session_glue/commands/upsert_synced.rs:64-120`), while cache lookup validates configuration/FIB/RG stamps, not session identity (`userspace-dp/src/afxdp/flow_cache.rs:991-1021`). A stale cache hit can therefore clear probation, refresh, or update the anchor on a replacement family. The token must be optional and bind canonical key plus NAT/orientation and preferably `install_epoch`; re-probe mismatch must suppress authority mutation. Purged/sessionless resolves—including the deliberately cacheable purged ACK class (`plan.md:750-764`)—must carry `None`.
