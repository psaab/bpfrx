## Verbatim review

PLAN NO

1. BLOCKER — The cache anchor apply misses the dominant in-place success arm. A successful rewrite enqueues and sets `recycle_now = false` at `userspace-dp/src/afxdp/poll_descriptor/flow_cache_hit.rs:444-497`, then skips the only specified apply location at `:507-548` and returns at `:552-555`. Most cache-forwarded packets would therefore never advance the anchor. Apply in both success arms or in a common success-only postblock.

2. BLOCKER — One carried handle cannot cover reverse-direction authority mutations. A reverse hit’s canonical handle is R, needed for matched-entry probation/identity operations, while anchor learning targets F. The existing family hop reads R, derives `reverse_session_key`, then performs a second F lookup at `userspace-dp/src/session/mod.rs:1183-1205`. Carry both validated handles or pay a second hash probe; the singular-handle/“no re-hash” contract is mechanically false. Positively, the intervening existing calls only update timing/counters at `userspace-dp/src/afxdp/poll_descriptor/flow_cache_hit.rs:295-317`; they do not alter key/NAT/id.

3. BLOCKER — Validating the cached backing entry does not prove it remains the packet query’s current winner. Cache entries remain keyed by query Q (`userspace-dp/src/afxdp/flow_cache.rs:578-585`), while resolution prefers a direct primary Q over reverse-translated aliases (`userspace-dp/src/session/lookup.rs:62-68`) and ordinary local lookup over forward-wire/shared matches (`userspace-dp/src/afxdp/shared_ops.rs:602-635`). An HA `UpsertSynced` can install Q while old canonical C remains live, with no flow-cache invalidation in `userspace-dp/src/afxdp/session_glue/commands/upsert_synced.rs:64-120`. The old Q descriptor still authenticates C and forwards C’s stale decision; `touch_if_stale/account_packet` can meanwhile mutate new Q. Re-resolve the query winner or invalidate every precedence-changing install.

4. BLOCKER — FIFO adjacency is not an import-family proof. Direct import does atomically enqueue F then R (`userspace-dp/src/afxdp/ha/session_import.rs:215-223`), and the drain preserves FIFO (`userspace-dp/src/afxdp/session_glue/mod.rs:649-705`). But activation prewarm enqueues all forwards and then all reverses (`userspace-dp/src/afxdp/shared_ops.rs:345-418`), while singleton replicas are independently queued at `userspace-dp/src/afxdp/session_glue/mod.rs:838-848`. Thus legitimate pairs become UNBOUND, and unrelated adjacent `UpsertSynced` commands can falsely populate the breadcrumb. Carry an expected ID or transaction tag explicitly rather than infer provenance from adjacency.

5. BLOCKER — Different-family re-minting neither has a defined discriminator nor resets the predecessor’s authority state. `SessionUpdate` carries no incoming family ID/replacement flag (`userspace-dp/src/session/ctx.rs:62-70`), and `update_session` snapshots only origin/NAT/orientation/RG before overwriting (`userspace-dp/src/session/mod.rs:1344-1397`). Merely re-minting `session_id` leaves K’s proposed anchor/probation/companion binding and today’s sticky closing/reset/established state on S2 (`:1398-1453`). A later close can therefore validate against K’s anchor. Thread an explicit replacement classification and reinitialize all family-bound authority/lifecycle fields, or perform a real remove/install.

6. BLOCKER — Preserving an existing ID on a zero-wire-ID re-import reopens ABA. The upsert removes the same-key predecessor before selecting the ID (`userspace-dp/src/session/install.rs:295-344`), while the command drops generation/family evidence and passes only `entry.session_id` (`userspace-dp/src/afxdp/session_glue/commands/upsert_synced.rs:64-79`). A legacy peer’s new same-key/NAT incarnation can inherit K’s ID, allowing stale cache and companion tokens to authenticate S2. Zero must fresh-mint and invalidate/fail closed unless explicit same-incarnation evidence is compared.

7. BLOCKER — The node-discriminator bit has no specified producer or carriage. Session setup supplies only `worker_id` (`userspace-dp/src/afxdp/worker/loop_body/setup.rs:131-135`), and `SessionTable::set_worker_id` accepts only that value (`userspace-dp/src/session/mod.rs:766-789`). A stable physical-node source must be named and threaded through setup; role-derived active/standby state is not stable across failover. Production consumers otherwise treat the ID opaquely, but the existing high-word assertions at `userspace-dp/src/session/tests.rs:366-374` and `:394-448` also require explicit migration.

8. HIGH — “All local-origin shared publishes carry the real ID” is impossible for the local GRE tunnel path as ordered. It constructs F/R with `session_id: 0` before any worker entry exists (`userspace-dp/src/afxdp/tunnel.rs:563-615`), publishes them first (`:691-730`), and only then queues `UpsertLocal` to every worker (`:732-745`), where each table independently mints on zero (`userspace-dp/src/session/install.rs:340-344`). There is no single real ID to publish without a designated allocator or reordered authoritative install.

9. BLOCKER — Effective close inheritance contradicts itself and misses close→close retries. After an accepted RST whose reverse install is capacity-refused, F remains sticky reset (`userspace-dp/src/session/lookup.rs:123-127`). A later accepted FIN can currently install R as FIN-only/30s (`userspace-dp/src/session/install.rs:157-180`; `session/mod.rs:2161-2169`), while F remains RST/2s; live R can retain F through `userspace-dp/src/session/expire.rs:296-320` and `:468-523`. The detailed rule covers only a later non-close although §5.8 says any synth. Merge family close bits into every accepted synth, including RST→FIN and FIN→RST retries.

10. BLOCKER — Published effective flags can be lost before queued replication arrives. Site 2b publishes the shared row before enqueueing worker replication (`userspace-dp/src/afxdp/shared_ops.rs:874-892`). The queued receiver uses `entry.tcp_flags` (`userspace-dp/src/afxdp/session_glue/commands/upsert_synced.rs:64-79`), but a sibling shared-hit materialization uses the new packet’s raw flags and ignores `replica.tcp_flags` (`userspace-dp/src/afxdp/session_glue/mod.rs:1092-1115`). An ACK in that window reconstructs an alive entry from a published RST/FIN row. Effective flags must also govern shared materialization. Raw screens/cache/accounting may safely continue consuming packet flags.

Site 2b returns only `(SessionLookup, bool)` (`userspace-dp/src/afxdp/shared_ops.rs:824-895`); validator refusal and accepted capacity refusal therefore remain indistinguishable. The resolution shape has no fallback field (`:563-578`), the poller hoists only `install_failed` before reducing the result (`userspace-dp/src/afxdp/poll_descriptor/mod.rs:509`, `:883`), and unchanged `account_packet` returns `()` on both success and miss (`userspace-dp/src/session/mod.rs:1177-1210`). Specify an identity-bound optional target, initialization/hoisting, and a mutually exclusive accounting branch.

Accounting runs only for `ForwardCandidate | FabricRedirect` at `userspace-dp/src/afxdp/poll_descriptor/mod.rs:3478-3503`; LocalDelivery, host-denial, MissingNeighbor, and earlier exits receive no charge. Scope the invariant to accounting-eligible forwarded dispositions or define disposition-specific admitted hooks.
