## Verbatim review

PLAN NO

1. **BLOCKER — UNBOUND lazy binding defeats the generation fence.** HA import can reject forward F because unrelated local K occupies its key while successfully installing reverse R (`userspace-dp/src/afxdp/ha/session_import.rs:215-223`; `userspace-dp/src/session/install.rs:310-315`). Binding R later merely because derived key+NAT matches K adds no family evidence: exact tuple+NAT reuse is the ABA case `install_epoch` was introduced to distinguish. The reverse→forward hop would then write R’s anchor sample into K (`userspace-dp/src/session/mod.rs:1177-1205`). This also contradicts the remaining “exact tuple+NAT needs no token” assertions in `plan.md:1211-1218` and `:3143-3150`. An imported UNBOUND R must remain fail-closed unless supplied actual paired-family identity.

2. **BLOCKER — companion epochs cannot be maintained safely across promotion and replication.** A successful promotion changes F’s epoch and may change NAT/orientation (`userspace-dp/src/session/mod.rs:1344-1397`), but `SharedPromote` publishes and replicates only F (`userspace-dp/src/afxdp/session_glue/promote.rs:99-139`; `userspace-dp/src/afxdp/session_glue/mod.rs:838-848`). Each sibling then upserts F with another locally generated epoch (`userspace-dp/src/afxdp/session_glue/commands/upsert_synced.rs:64-79`; `userspace-dp/src/session/install.rs:322-351`), without updating R. A bound R consequently mismatches forever; rebinding it by tuple+NAT recreates finding 1. The problem is sharper after `UpsertRefused`, where promotion can overwrite unrelated K with S2. The plan needs a real family identifier or paired atomic transition—not an undefined “proven same-family” rebind.

3. **BLOCKER — `MatchProvenance` conflates source provenance with transition outcome.** `ForwardWire` is a match source, while `Materialized` and `Promoted` are later transitions. A shared forward-wire hit can materialize and then promote before the final token is constructed (`userspace-dp/src/afxdp/shared_ops.rs:614-635`; `userspace-dp/src/afxdp/session_glue/mod.rs:1194-1254`). Recording `Materialized`/`Promoted` loses the required `ForwardWire` no-anchor-learn marker; retaining `ForwardWire` leaves the promised final-token semantics undefined. These must be orthogonal fields, or the plan must provide an explicit source-preserving composition rule.

4. **BLOCKER — capacity-refused close can later manufacture an alive reverse half that indefinitely retains the marked forward half.** On an accepted close, reverse installation may fail at capacity while F is still marked (`userspace-dp/src/session/install.rs:123-125`). A later non-close reverse packet against ESTABLISHED F retries master-verbatim and installs R from that packet’s raw non-closing flags, yielding `closing=false` with the established timeout (`userspace-dp/src/session/install.rs:157-180`), then publishes and replicates it (`userspace-dp/src/afxdp/shared_ops.rs:866-893`). At F’s 2s/30s deadline, active R retains F (`userspace-dp/src/session/expire.rs:296-320,468-523`); reverse traffic refreshes R (`userspace-dp/src/session/lookup.rs:150-171,198-218`), so F’s Close emission can be postponed indefinitely (`userspace-dp/src/session/expire.rs:342-377`). The retry must inherit F’s sticky closing/reset state or decline R installation.

   The initial failed install itself emits no Open because publication is correctly conditional on `installed` (`shared_ops.rs:866-893`). It does, however, lose accounting for the accepted close: `account_packet` probes the absent reverse key and returns without charging F (`userspace-dp/src/session/mod.rs:1177-1210`; caller `userspace-dp/src/afxdp/poll_descriptor/mod.rs:3494-3502`).

5. **HIGH — the cache revalidation/performance contract is not mechanically realizable as written.** The proposed early identity check occurs after current validity checks around `flow_cache_hit.rs:94-133`, but successful admission does not occur until rewrite/enqueue at `:427-497` or request construction/enqueue at `:507-548`. Between them, `touch_if_stale` and `account_packet` already probe and mutate the session table (`:295-317`; `userspace-dp/src/session/mod.rs:1118-1133,1177-1209`). Final-admission compare-then-mutate therefore needs another lookup or a carried, identity-validated stable handle; neither carrier nor safety contract is specified.

   The “same key/same warm line” argument is also false for aliases: `FlowCacheEntry.key` remains the packet query key (`userspace-dp/src/afxdp/flow_cache.rs:578-585`), whereas the token key is canonical, and translated/forward-wire lookup uses distinct indexes (`userspace-dp/src/session/lookup.rs:62-102,253-292`). Specify a handle carrier or count and benchmark the additional canonical/companion probes.

6. **HIGH — the ACK-knowledge proof still conflicts with rules 1 and 5, and the claimed site-2b table is not total.** The strong-proof rule says any exact-proving ACK-bearing segment authenticates both samples and drives establishment (`plan.md:934-948`), while closing segments may neither learn nor promote (`:875-878`, `:983-1002`). Site 2b correctly limits establishment to proof-passing non-closes (`:1377-1400`). State explicitly that a closing exact ACK supplies read-only validation evidence only.

   Separately, the table says Shared/non-close installs master-verbatim, matching `userspace-dp/src/afxdp/shared_ops.rs:638-665,824-865`, but `plan.md:1355-1357` and the test at `:3137-3142` say unqualifiedly that Shared refuses. The closing-SYN-ACK paragraph also assumes an OPENING proof without scoping it to an OPENING F. An implementer still has contradictory instructions.

7. **HIGH — the reactive site-2b reverse constructor has no `fwd_companion_epoch` producer contract.** The plan explicitly covers the positional fresh-flow reverse install and HA import, but the reactive path obtains a `ForwardSessionMatch` containing only key/decision/metadata and calls the ordinary installer with no forward epoch (`userspace-dp/src/afxdp/shared_ops.rs:638-665,824-865`; current shape `userspace-dp/src/session/entry.rs:208-213`). It must specify Local match → carry the exact matched F epoch, Shared match → UNBOUND, including identity re-probe before installation.

8. **MEDIUM — footprint tests do not enforce the advertised footprint.** The plan claims a 49-byte session-entry increment and a 96-byte niche-filled `Option<MatchedToken>`, but tests allow `SessionEntry` growth through 56 bytes and `FlowCacheEntry` growth through 104 bytes, and never assert `size_of::<Option<MatchedToken>>() == 96` (`plan.md:3181-3188`). Rust layout includes alignment and tail padding; raw field sums from `userspace-dp/src/session/key.rs:9-17` and `userspace-dp/src/nat/mod.rs:90-103` do not establish slab stride. Either assert exact before/after sizes or report the allowed worst-case memory totals.

9. **LOW — zero is not formally excluded as an epoch.** All four production epoch writers use `next_epoch` (`userspace-dp/src/session/install.rs:140,323`; `userspace-dp/src/session/mod.rs:1384,1642`), but it is plain `u64 += 1` (`session/mod.rs:761-763`). Optimized overflow can therefore produce the reserved zero value; the nearby session-ID allocator explicitly skips zero (`:784-789`). Make epoch allocation skip zero or use `NonZeroU64`.
