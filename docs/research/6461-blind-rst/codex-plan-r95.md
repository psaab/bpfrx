1. **BLOCKER — the post-purge non-close cold-neighbor path is not master-verbatim.** Master purges and releases P1 but retains `hit.lookup` (`userspace-dp/src/afxdp/session_glue/mod.rs:1178-1196`; `userspace-dp/src/afxdp/session_glue/promote.rs:181-207`). The plan instead classifies the purged lookup as `ExistingResolved` and suppresses that work (`docs/research/6461-blind-rst/plan.md:433,1581-1604,2137-2155`). Consequently it buffers and replays released P1 (`poll_descriptor/mod.rs:5057-5067`; `userspace-dp/src/afxdp/neighbor_dispatch.rs:272-348`) and can immediately reinject P1 (`poll_descriptor/mod.rs:5126-5138`; `userspace-dp/src/afxdp/tx/dispatch/slow_path.rs:199`) without reacquiring its allocation. Non-close post-purge outcomes must retain master’s seed transaction.

2. **BLOCKER — the documented #6600 extension is not bounded by expiry.** `SyncedSessionEntry` contains no deadline (`userspace-dp/src/afxdp/worker/mod.rs:375-401`). Worker GC reaps only the local session, NAT/BPF/conntrack state, and cache (`userspace-dp/src/afxdp/worker/loop_body/mod.rs:1481-1522`); peer-synced expiry emits no Close (`userspace-dp/src/session/expire.rs:342-344`) and does not remove the shared row. Shared removal requires an explicit synchronized delete or transient purge (`userspace-dp/src/afxdp/ha/session_import.rs:243-320`; `userspace-dp/src/afxdp/session_glue/promote.rs:181-207`). After every local expiry, another close can therefore resolve and retain the same shared conflicted-P1 row indefinitely. Sibling workers can additionally release the allocator’s unrefcounted same-flow reservation (`userspace-dp/src/nat/allocator.rs:1664-1674`; `worker/loop_body/mod.rs:1490-1505`) while retained closes continue using P1. This contradicts the “first non-close or expiry” bound at `plan.md:1855-1864` and makes FIN/RST retention worsen the pre-existing #6600 state.

3. **BLOCKER — even the “first non-close” fence can preserve conflicted P1 indefinitely through flow cache.** FIN/RST bypasses cache, but a subsequent pure ACK/PSH-ACK is eligible (`userspace-dp/src/afxdp/flow_cache.rs:354-394`). That ACK can purge the shared/local row while retaining its P1 decision (`session_glue/mod.rs:1178-1196`), then cache the resulting sessionless descriptor (`poll_descriptor/mod.rs:3900-3959`). Future packets consult cache before session resolution (`poll_descriptor/mod.rs:298-327`). The cache has no idle TTL, and an inactive-owner redirect can have no lease fence; repeated hits remain MRU (`flow_cache.rs:121-155,991-1039`). Master would have purged on the earlier uncacheable close, making this ACK a genuine miss with fresh owned state. The proposal thus newly converts the close→ACK sequence into potentially indefinite stale-P1 forwarding.

4. **BLOCKER — overdue-K in-place adoption lacks an index-safe, provenance-complete transaction.** The plan changes only K’s decision/metadata while preserving its timing and wheel placement (`plan.md:1291-1303,2032-2038`). Shared publication can replace decision/metadata wholesale (`userspace-dp/src/afxdp/shared_ops.rs:897-916`). Moreover, “adopt S2 wholesale” is inconsistent with retaining K’s origin, session ID, epoch, counters, and hold state; ordinary synced upsert replaces those fields (`userspace-dp/src/session/install.rs:345-433`), and origin controls promotability/emission authority (`userspace-dp/src/session/entry.rs:242-269`). A dedicated atomic reindex/adopt helper and exhaustive field contract are required.
