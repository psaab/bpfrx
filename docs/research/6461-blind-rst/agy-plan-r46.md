### Q1 (rejection-set lifecycle): SOUND
- **Authoritative-absence vs mid-repair snapshot**: Sound (`plan.md:1625-1644`, `1781-1798`, `3811-3824`). Under v9.9.37, a repair does not complete on a raw snapshot alone; it is bounded by `repair_cutoff_epoch` and terminates with a `JOURNAL_END(repair_id, journal_epoch, terminal_seqno)` marker that serializes all post-cut deltas. If an E1-absent repair completes and validates `JOURNAL_END`, the snapshot plus post-cut journal represents complete sender state at `JOURNAL_END`. If E1 is absent from both, E1 is authoritatively absent on the peer, so cancelling the pending rejection entry at `JOURNAL_END` is correct.
- **GC-notify -> retry window**: Sound (`plan.md:1760-1778`, `1781-1798`, `userspace-dp/src/afxdp/nat/allocator.rs:1349, :2138, :2292`). When lease GC frees port $P$, it notifies the pending rejection set to retry E1's import. If a third flow $E3$ re-claims $P$ before E1's retry executes, E1's retry reservation fails again. The plan explicitly specifies that *every* reservation failure (including retries outside repairs) arms/latches the durable cohort-scoped pending-rejection set, so E1 re-arms correctly.

### Q2 (JOURNAL_END / JOURNAL_ACK): SOUND
- **Negotiated discharge clause**: Sound (`plan.md:3800-3804`, `3811-3816`, `4104`, `pkg/session/sync_bulk.go:282`, `pkg/session/sync_conn_read.go:205, :249`). `JOURNAL_END` and `JOURNAL_ACK` carry the immutable triple `(repair_id, journal_epoch, terminal_seqno)` and are the **only** discharge mechanism for capability-negotiated peers. Legacy `BulkEnd`/`BulkAck` discharge is retained strictly for unnegotiated legacy peers based on `repair-vN`/`reset-vN` version bits.
- **Fresh-repair-ID-after-expiry vs late duplicate**: Sound (`plan.md:1840-1845`, `3817-3824`). The completed-repair receipt is keyed by the full triple and retained for the retransmission lifetime. When a new repair attempt is initiated after expiry, the sender mints a *fresh* repair ID ($R2 \neq R1$). A very-late duplicate $R1$ arriving after receipt expiry matches neither the receipt map nor the current active repair ID ($R2$), making it non-mutating and discarded without executing as a new repair or discharging an active obligation.

### Q3 (old-family companions + teardown latch): SOUND
- **Old-family record capture time**: Sound (`plan.md:2554-2570`, `userspace-dp/src/afxdp/ha/session_import.rs:104, :115, :187`). During initial import of $E1$, `session_import.rs:104` synthesizes $E1$'s reverse companion $R1$, publishes the forward entry at `:115`, and publishes $R1$ at `:187`. When $E2$ subsequently replaces $E1$ at quarantine time, $R1$ is already published in the maps. Capturing the immutable old-family record at quarantine time correctly captures $R1$.
- **Teardown-failed latch recovery**: Sound (`plan.md:1826-1839`, `4104`, `userspace-dp/src/task/loop_body/mod.rs:332`, `userspace-dp/src/coordinator/worker_manager.rs:141-154`). If an old worker hangs in `loop_body/mod.rs:332` past the quiesce deadline, the latch prevents in-process rebind/reconcile to prevent race conditions against lingering worker commits (`poll_descriptor/mod.rs:2578`). A process restart terminates the stuck process and clears the in-memory latch, making process restart a necessary and documented operator recovery action.

### Q4 (replace CAS + reset lane + capability versions): SOUND
- **Registry query trust**: Sound (`plan.md:1516-1551`). The `replace(slot, T1, T2, token_epoch)` CAS uses a strictly monotonic, per-node $u64$ token epoch ($T2$). When Go queries the registry after a lost ACK, it checks for the presence of the exact monotonic epoch value $T2$ in the slot (`plan.md:1536`). An earlier aborted attempt carried a lower epoch ($T0 < T2$), preventing false matches against stale attempts.
- **Exempt lane constraint & authentication**: Sound (`plan.md:1350-1367`, `3780-3796`, `4104`, `pkg/session/sync_auth.go:314`, `pkg/session/sync_conn.go:12, :244, :319`). The exempt lane is a dedicated control lane evaluated before slot installation (`barrierActive`). Only pre-slot control messages (`RESET_GEN`/`RESET_ACK`) are handled on this lane; standard session deltas are blocked. Authentication is established during the initial connection handshake (`sync_auth.go:314`), and `RESET_GEN`/`RESET_ACK` frames carry the peer's node incarnation `(direction, node_incarnation, reset_generation)`, binding the exchange to the peer's current incarnation.
