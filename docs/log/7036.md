# #7036 — a message guard that pins bytes cannot see a claim become false

`TestNATTerminalActionMessageContent_6820` asserted ten substrings with
`strings.Contains`. That binds the presence of bytes. Two mutations were
measured green against it, and both are recorded in the issue:

- **M-A** — append `THE PRECEDING SENTENCE IS FALSE: configuration order
  chooses the survivor.` immediately after the survivor claim.
- **M-B** — delete `and never looking the pool up, and the dataplane applies
  the same ` from the DNAT mechanism sentence.

Every asserted substring survives both. **M-A is the one that matters**: the
message asserts a claim and then explicitly denies it, and a guard whose entire
subject is whether that sentence is TRUE could not see it.

The two directions are not symmetrical accidents. An **addition** is invisible
to a containment check *by construction*. A **deletion** is invisible whenever
the deleted text is not itself one of the asserted substrings — which is most
of the message.

## The fix is equality, and here that is the right trade

Pinning a message exactly is normally over-tight. Not here. These are
operator-facing contracts that four consecutive rounds got wrong:

| round | what was false |
|---|---|
| #6820 r3 | the survivor clause read "not the one you configured first or last" — literally false for a 2-action rule, where one action IS first and the other IS last |
| #7035 | the unscoped "the survivor is not chosen by configuration order" was false in exactly the case that prints it: with duplicate `then` CONTAINERS the #3850 reset makes the LAST container supply the counted fields, so container order selects which contradiction you get |
| #7034 | the parenthetical ended "this rejects contradictory actions inside one block" — a completeness claim that is false for every token-packed spelling |
| #6820 r7 | (this issue) the guard meant to prevent the above cannot see any of it |

Each former `Contains`/`NotContains` check is now a consequence of the equality
rather than a separate assertion — including the two that keep the SNAT and
DNAT messages from converging. The DNAT builder short-circuits on `isOff` and
never resolves the pool, so *"every one of them is published to the dataplane"*
describes a path a DNAT rule does not take; a sentence shared between the two
kinds is necessarily false for one of them.

The rationale each clause was added for is preserved in a comment block above
each golden, because that comment is now the only place the history lives.

**Updating a golden is a deliberate act.** The failure message says so, and says
to CLASSIFY the diff first: a reworded clause and a clause whose CLAIM changed
look identical in a diff that is merely accepted.

### Two method notes, both of which cost a cycle

**The M-A anchor breaks across a `+` seam.** The first attempt searched for
`rather than by the order the actions were written.` and matched nothing: the
sentence is built from concatenated fragments, and the clause ends mid-literal
at `"order the actions were written. (Duplicate \`then\` CONTAINERS "+`. A
plain-text anchor over Go source has to be wrap-insensitive or it silently
plants nothing — and a mutation that never applied reports as a guard that
caught nothing.

**The cell log is not always readable through the default filter.** The golden
contains an em dash, and the shell's output filter reported `stream did not
contain valid UTF-8` and returned EMPTY counts — which reads exactly like a
cell that collected no tests. `rtk proxy` on the same file showed
`1` collected and `1` named FAIL. A count of "" is not a count of 0.
