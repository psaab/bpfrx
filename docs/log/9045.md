# #9045 / #9046 — two gates that reported success without measuring

- **Timestamp**: 2026-09-05
  - **Action**: widened the `pkg/dataplane` race leg and gave it the canary the
    other two legs already had; widened the ledger merge-completeness lint past
    HEAD and stopped it reporting "nothing checked" as a PASS.

    **#9045.** `test-race-dp` raced `./pkg/dataplane/ -run 'ArmedGate|PreArm'`,
    which matched 15 of 463 tests and none of the package's goroutine-driven
    probes. The decisive measurement is on one of them:
    `TestPersistentNATTable_AllConcurrentSaveNoRace` has **zero** `t.Error` /
    `t.Fatal` in 47 lines. Its only possible failure is the race detector
    firing, so excluded from the race leg it is not a weak test — it is a test
    that cannot fail, and it was green for exactly that reason.

    The canary keys on the test's OWN body launching a goroutine, not on the
    file. The originating report swept test FILES containing `go func` and got
    33 tests; `persistent_nat_test.go` holds fifteen ordinary table tests
    beside one probe, so the file predicate over-reports by 24. Body-level
    gives **9**, and all 9 are now inside the pattern.

    It reads the Makefile line by PACKAGE PATH rather than position.
    pkg/daemon's canary reads "the FIRST -run line", which forced a Makefile
    comment warning that this leg "must stay BELOW the pkg/daemon one" — a
    positional coupling a harmless reordering breaks silently.

    Mutation: reverting the pattern reds it naming 3 of 9 excluded; deleting
    the `./pkg/dataplane/` line reds it saying the package is no longer
    race-gated. Two positive controls guard the two ways it could pass having
    measured nothing (zero tests found; zero probes classified). The widened
    leg itself runs clean — `ok 35.7s`, 0 data races.

    **#9046.** The merge-completeness lint inspected HEAD only, so a merge that
    dropped a ledger shard was catchable only while HEAD was exactly that
    merge; one commit later it is invisible, because plain `ledger-lint`
    structurally cannot see a missing row. Now walks the last 25 merges.

    The second half is the more interesting one. On a non-merge HEAD it
    returned 0 and the caller printed `PASS: ledger-merge-completeness (…
    nothing to check)`. The author knew — a comment says the words are there so
    that "checked nothing" and "checked and clean" do not look the same. **But
    a PASS line still increments `passed=157`, and the total is what gets
    read.** A disclosure that does not survive aggregation is not a disclosure.
    Exit 3 now means "we could not look" and maps to SKIP.
