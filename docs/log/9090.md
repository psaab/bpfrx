# #8967's scraper — reading a file BY NAME survives the change that breaks it

- **Timestamp**: 2026-09-05
  - **Action**: anchored `applyTailMentions8967` so a moved apply tail is
    distinguishable from an absent starter.

    Prompted by lane-8015 losing an entire census to the silent form of this:
    their scraper read the elision predicate's file by name, the campaign split
    the predicate into `compact_normalize_scope.go`, the OLD FILE STILL EXISTS,
    the regex matched nothing, and the census reported a stable confident
    `edges=0 ADMITTED=0 MISSING=0`. **Re-running never catches it — the zero is
    perfectly stable.** What caught it was a positive control comparing the
    scrape against the predicate itself: two sources for one fact, disagreeing.

    Blast radius measured across the tree:

    ```
    in-tree refs to compact_normalize_8662.go by name : 3, all PROSE
    in-tree tests reading a source file by name       : 27
      WITH a zero/vacuity guard                       : 21
      WITHOUT                                         : 6
    ```

    So nothing committed is silently zero on that file, and the guard practice
    is established in-tree — lane-8015's probe was a worktree instrument that
    had not acquired it.

    **But one of the 6 is mine.** `applyTailMentions8967` reads
    `daemon_apply_tail.go` by name and returns `strings.Contains(src,
    "d."+starter+"(")`. If the apply tail moves, the read SUCCEEDS and every
    starter reads absent.

    It is the WEAKER form — the caller asserts `!applyTailMentions8967(...)`,
    so it fails loud rather than passing silently. What the anchor buys is a
    correct DIAGNOSIS: without it the message reads "knob X is gated at comms
    start but its starter is not called from the apply tail", which is FALSE
    and sends the reader to the knob instead of to the move. Same class as
    #9006 and #8992 — loud, and pointing the wrong way.

    Mutation: pointing the scrape at a real `pkg/daemon` file with no `Daemon`
    methods (`cli_rbac.go`) reds it with "no longer contains any Daemon method
    ... do NOT read the result below as a finding about any knob". A first
    attempt mutated the receiver type instead and only broke the build, which
    tested nothing.
