- **File(s)**: `userspace-dp/src/afxdp/poll_descriptor/policy_revalidation.rs`,

## The defect

`zone_policy_deny_on_session_hit` revoked only on `Deny`:

```rust
if !matches!(result.action, crate::policy::PolicyAction::Deny) {
    sessions.mark_policy_revalidated(&canonical_key);
    return None;
}
```

`PolicyAction` is three-valued (`policy.rs`: `Permit` / `Deny` / `Reject`), so
`Reject` took the PERMIT exit: the session kept its entry, its NAT translation
and both directions of forwarding, AND was stamped `policy_revalidated` for the
generation, so no later packet of that generation re-asked. An operator
narrowing a rule `permit` -> `reject` got the new verdict for NEW flows only.

It is asymmetric with every other adjudication site in the crate, all of which
test `Permit` POSITIVELY:

| site | spelling |
| --- | --- |
| `poll_descriptor/mod.rs:2442` (admission) | `if let PolicyAction::Permit` |
| `poll_descriptor/mod.rs:4172/5318/5428` | `!matches!(.., Permit)` |
| `poll_descriptor/flowless_verdict.rs:146` | `!matches!(.., Permit)` |
| `poll_descriptor/host_inbound_policy.rs:212` | `matches!(.., Permit)` |
| `forwarding/fabric.rs:715` | `!matches!(.., Permit)` |
| `forwarding/mod.rs:152` | `matches!(.., Permit)` |
| `policy.rs:3587` (terminal-action test) | `Deny \| Reject` |
| **`policy_revalidation.rs:257`** | **`Deny` alone** |

`policy-rematch` — the only commit-time mitigation — is off by default
(`pkg/config/types_security.go`), so on a stock box nothing else covered it.

## Remedy census (the defect SHAPE, not just this site)

Grepped every non-test `PolicyAction::Deny` / `PolicyAction::Permit`
adjudication in `userspace-dp/src`. `policy_revalidation.rs:257` was the ONLY
site collapsing the three actions into a Deny test; the parse-side collapse of
the same shape was already closed by #3365 (`UnknownPolicyAction` — an
unrecognized action token no longer falls to `Deny` through a catch-all arm, and
its doc records the same fail-OPEN-for-reject reasoning). No further member of
this class exists in the tree, so nothing new was filed for it.

## The decision the issue asked for: reject tears down SILENTLY

A revoked-by-reject session emits no ICMP unreachable, no TCP RST, no log and no
counter — byte-identical to the `Deny` teardown. Two reasons, both written into
the module header:

1. The derivation is side-effect-free by contract. Minting a reject reply needs
   the frame, the TX pipeline and the deny-event emitter — the whole class of
   side effect the contract excludes.
2. Nothing operator-visible is lost. The teardown also evicts both directions'
   flow-cache slots (`collect_revoked_flow_cache_keys`), so the NEXT packet of
   that 5-tuple is a session MISS, takes the full admission path, evaluates
   `Reject`, and emits the reject reply + RT_FLOW deny record from
   `reject_reply.rs` — the one site that owns them. The reject semantics arrive
   one packet later from one place rather than being duplicated here.

## Why the shipped cells could not see it

`forwarding_with_lan_permit(permit_lan: bool)` sampled the TERMINAL-ACTION axis
at exactly two points — the rule *present as `permit`* and *absent* — and both
agree with a revoke arm spelled `!matches!(.., Deny)`. `reject` appears nowhere
in the file. The fixture is now action-parameterised
(`forwarding_with_lan_rule(Option<&str>)` +
`drive_one_packet_with_action`), which makes the third point reachable through
the same real poll body.

### The Rust kill detector was positive-controlled in four directions

`cargo test` prints `error: test failed, to rerun pass ...` on a KILL, so a
naive `^error` VOID detector scores every kill as a VOID. The scorer used here
(`/var/tmp/xpf-score-rust.py`) reads libtest's NAME-attributed
`test <path> ... ok|FAILED` lines instead, and was run against four synthetic
logs before being trusted:

| synthetic log | verdict |
| --- | --- |
| 60 passes + 1 named FAILED + `error: test failed` | `KILLED by=[target]` |
| `error[E0308]` + `could not compile`, nothing collected | `VOID BUILD_FAIL` |
| 60 passes, `RUNEXIT=124` | `VOID TIMEOUT` |
| 1 test collected | `VOID TOO_FEW_TESTS(1<50)` |
