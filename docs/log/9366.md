# 9366 — equal-flow-enforcement refused two of the three rate forms

- **Timestamp**: 2026-09-06
- **Action**: gate on whether the scheduler expresses a rate in ANY first-class
  form, not on the absolute byte field alone.
- **File(s)**: `pkg/config/compiler_validate_strict_cos.go`,
  `pkg/config/parser_class_of_service_test.go`.

## The defect

```go
if sched.EqualFlowEnforcement && (!sched.TransmitRateExact || sched.TransmitRateBytes == 0) {
```

`transmit-rate percent <n> exact` and `transmit-rate remainder exact` both set
`TransmitRateExact = true` and leave `TransmitRateBytes` at **0** — their value
lives in `TransmitRatePercent` / `TransmitRateRemainder`. So the second disjunct
fired and the commit was refused, with an error telling the operator to supply
the exact transmit rate **they had just written** as a percentage or a
remainder. A wrong diagnostic, not merely a missing one.

## Why this is a defect and not policy — three independent corroborations

1. **The dataplane already resolves both forms.** `forwarding_build/cos.rs`
   derives `guarantee_enabled` from
   `cos_effective_transmit_rate_bytes(...).or_else(remainder)` — `Some` for
   percent and for remainder — then gates `equal_flow_enforcement` on
   `guarantee_enabled && transmit_rate_exact`. **This Go gate was the sole
   blocker** on a shipped, documented fairness feature.
2. **The schema deliberately admits it**: `validateCoSRateTail` /
   `coSRateSiblingSuppliesValue` allow `exact` to trail a percent operand.
3. **`surplus-sharing`, one field away, already accepts the percent form**, so
   the asymmetry was not a stated policy.

The gate predates #4228 Gap 2 (percent) and #6846 (remainder), which made both
forms first-class, and was not revisited.

## Extracted rather than inlined

`schedulerExpressesATransmitRate9366` exists so each form can be driven
directly. The predicate it replaces was a single `Bytes == 0` test — **exactly
the shape that silently excludes forms added later**, since both newer forms
leave `Bytes` at zero. A named predicate makes the omission of a fourth form a
visible edit here rather than an invisible one at the call site.

It mirrors the dataplane's own resolution order deliberately: the two must
agree, or a config the compiler accepts builds a lease the dataplane declines to
arm — the silent direction.

## The pre-existing cell held; only its wording moved

`TestCompileClassOfServiceEqualFlowEnforcementRequiresPositiveExactRate` red on
its **message substring**, not its behaviour: all three of its rows still
reject. The assertion was updated rather than dropped, because a rejection
reached through the WRONG branch reads as a working guard when only the failure
is checked.

## Direction

**Fail-closed.** The commit was refused, so there was no traffic effect, no
dataplane state and no silent enforcement bypass — the cost was a usable feature
being unusable and an error that misdirected the operator.

how a working guard gets deleted.

Narrowness rows: `percent` **without** `exact`, and no transmit rate at all,
must still be refused. Without them the change is satisfied by a gate that
accepts everything.
