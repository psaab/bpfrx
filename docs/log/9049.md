# 9049 — an http-get probe that scored its own timeout as a success

- **Timestamp**: 2026-09-06
- **Action**: stop discarding the body-drain error, and measure RTT to the
  response rather than to drain completion.
- **File(s)**: `pkg/rpm/rpm.go`, `pkg/rpm/http_probe_drain_9049_test.go` (new).

## Two defects, one line apart

```go
io.Copy(io.Discard, resp.Body)   // error dropped: `_, _ =`
rtt := time.Since(start)         // body-transfer time billed to RTT
```

1. **A false success.** A body read that hit `http.Client{Timeout: 10s}`
   returned `rtt ≈ 10s, err = nil`, and the caller scored the probe a SUCCESS. A
   timed-out response was indistinguishable, *in the probe's own verdict*, from a
   fast complete one — the probe reported the path healthy exactly when it was
   not.
2. **Measurement distortion.** RTT was measured after the drain, so a fast server
   with a slow body reported transfer time as round-trip time: in the case the
   issue measured, 704 µs of true responsiveness reported as 2.0 s, a ~2800×
   distortion folded into MinRTT / MaxRTT / AvgRTT and the jitter figure an
   operator reads to judge a path.

The issue's own corrections are kept: the drain was never unbounded
(`Client.Timeout` covers body reads), and no RTT threshold exists in the
`thresholds` schema, so the inflated figure does not drive `services
ip-monitoring` actuation. The report's "slows remediation" arm is unsupported and
is not claimed.

## Decisions

**RTT is taken where `client.Do` returns** — status line and headers in hand.
That is what "round trip" means to the operator reading the number, and it
matches what every other probe in this file measures.

**Reaching the 1 MiB drain limit is NOT a failure.** `io.LimitReader` returns EOF
at the boundary, so a large healthy body drains to the limit and the probe
succeeds — the server answered, which is what the probe asked. Treating a big
body as a failed probe would score a healthy path down for a property the probe
does not measure. Its own cell pins that, and the fail-everything mutant reds
three cells.

**A drain failure returns the header RTT, not zero.** The round trip really did
take that long; the caller's loss accounting is separate from its timing
accounting.

## A fixture that deadlocked, and what replaced it

The first version used a handler blocking on a channel to reproduce the
production trigger (the 10 s client timeout firing mid-body). It **hung the whole
package**: `httptest.Server.Close()` waits for outstanding handlers, and the
`defer` that released the handler was registered *earlier*, so it ran *later* —
LIFO deadlock. It also cost ten seconds per run.

Replaced with a server that promises `Content-Length: 1024` and writes 5 bytes,
so `io.Copy` takes an unexpected EOF. **Identical code path — the discarded
`io.Copy` error — deterministic, and in milliseconds.**
