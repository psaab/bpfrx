# #6967 — refineBootEpoch and the "indistinguishable states" premise

- **Timestamp**: 2026-08-28
  - **The premise is false at `20a6068b4`.** #6967 says the `!epochOrderable`
    branch is reached by two situations it "cannot tell apart from inside", and
    that "no predicate over the currently available inputs separates them".
    Measured, driving `refinedEpochFile` directly:

    | scenario | file afterwards |
    |---|---|
    | intact predecessor, clock stepped back **2h** (#6967's own example) | **PRESERVED** |
    | intact predecessor, clock stepped back 29 days | **PRESERVED** |
    | intact predecessor, clock stepped back 40 days | HEALED — the residual |
    | **year-2191 value, correct clock** | **HEALED** |

    #6711's `bootEpochPreserveMaxSkew` (30 days, `heartbeat_epoch.go:198`) is the
    predicate: "could a real backward step explain this gap". The two situations
    land on OPPOSITE outcomes, in the directions the issue asks for.
  - **Why that matters for the suggested fix.** The issue proposes persisting a
    writer/incarnation tag so the states stop being indistinguishable. Over an
    already-discriminated pair that is a SECOND discriminator: for the 2h case it
    branches on a condition whose outcome never differs — a revert wearing the
    shape of a fix. The measurement is committed as a test rather than written
    down, so a change that collapses the two outcomes reds with the reason
    attached.
  - **Independently re-derived**, not taken from the issue's own triage comment:
    the comment measured at `63ef1fad6`, this is a fresh probe at `20a6068b4`.
  - **What the tests add.** `TestBackwardClockStepDoesNotDestroyTheEpochFile6711`
    already covers the stepped-back axis (2h / 1 week preserve, 1 year heals).
    It does not contain #6967's other half — a corrupt value read by a CORRECT
    clock — so on its own it shows one situation behaving, not two being told
    apart. `TestCorruptAndBackwardSteppedAreDistinguished_6967` adds that half
    and asserts the CONTRAST as one line;
    `TestPreserveBandBoundaryIsWhereItSays_6967` pins the edge at 29 and 40 days,
    which is also the honest statement of the residual.
  - **Also stale in the issue**: the #6963 dependency. #6963 was closed as
    superseded by #5084, so it introduced nothing; the identity does exist
    (`pkg/cluster/sync_boot_incarnation.go`), but it is documented
    compare-for-equality-only, and a boot-id tag alone would not separate
    "intact" from "garbage" anyway — corruption confined to the epoch field
    leaves a valid tag. That needs integrity, not identity.
  - **Disposition**: close. The residual — a backward step beyond 30 days still
    heals over an intact predecessor — is real but is a different, much smaller
    problem than the one filed, and whether it justifies a persistence-format
    change in the #1960 rolling-upgrade class is a live question rather than a
    given. Recorded in `pkg/cluster/README.md` alongside the #6969 triage.
