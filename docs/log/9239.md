# 9239 — a withdrawn delegated prefix keeps being advertised

- **Timestamp**: 2026-09-06
- **Action**: make the DHCP lease-change recompile classifier see the PD
  *transition* rather than the post-state.
- **File(s)**: `pkg/daemon/daemon.go` (new `pdForRAPresent atomic.Bool`),
  `pkg/daemon/daemon_dhcp.go` (memo at the callback + predicate parameter),
  `pkg/daemon/dhcp_pd_withdrawal_9239_test.go` (new),
  `docs/embedded-radvd.md` §4.4, plus the mechanical `, false` at the existing
  predicate call sites in tests.

## The defect

`dhcpLeaseChangeRequiresRecompile` asked `len(DelegatedPrefixesForRA()) > 0`.
The callback runs AFTER `commitLease` deleted the withdrawn prefix, so the final
withdrawal and a box that never had PD produce the same empty set — and the one
event that most needs RA re-applied reads as needing nothing.

Nothing else catches it: on a lifeline-only composition the classifier picks the
management-only branch (routes, DNS, IPsec — not RA); the authoritative periodic
RA reconcile is cluster-only by its own doc comment; and the mode-agnostic 30s
loop retries only DEAD senders, while this one is alive with stale desired state.

## The fix

The predicate stays PURE and takes `hadPDForRA` as a parameter. The single
production caller, `onDHCPAddressChange` — which runs once per lease-change
event — owns the state transition via one `Swap`.

A config commit that removes the DHCPv6 client can leave the memo set with no
callback to clear it. The cost is one conservative full apply on the next lease
change, which clears it. That direction is deliberate: the failure being guarded
is a box advertising a prefix upstream has withdrawn.

## Validation

Three cells, and the third is the one that matters.

The first two call the predicate directly and bind only the FUNCTION. Mutating
the CALL SITE to pass a literal `false` left them green — verified, and it killed
zero cells in the entire package. `TestPDWithdrawalDrivesTheRealCallback9239`
drives the real `onDHCPAddressChange` and observes which branch ran, and it is
the only cell that kills that mutant.

Two traps hit while writing it, both worth recording:

1. **The first wiring mutant was VOID, not survived.** Dropping the argument
   leaves `hadPDForRA` unused, so the package does not compile and no `--- FAIL`
   line is emitted — which reads exactly like an escape. Re-run with `_ =
   hadPDForRA` so the mutant actually builds.
2. **The cell was initially vacuous.** `applyActiveConfig` clears the published
   management-VRF set under `NoDataplane`, and an empty set makes the predicate
   return true through a conservative branch unrelated to prefix delegation. Both
   later passes were being answered by that branch, so the cell was green with
   the wiring cut. The fixture now re-establishes the precondition before every
   pass, so each verdict is attributable to the fix.
