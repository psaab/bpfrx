# #9168 — two kernel RX counters with a complete consumer and no producer

## Defect, re-verified at the base commit (`4467d86c5`)

`kernel_rx_dropped` and `kernel_rx_invalid_descs` are plumbed end to end:

```
userspace-dp/src/afxdp/binding_state/mod.rs      the atomics
userspace-dp/src/afxdp/binding_state/snapshot.rs snapshot fields
userspace-dp/src/protocol/binding.rs             wire encoding
pkg/dataplane/userspace/protocol_binding.go      Go decode
pkg/monitoriface/monitor.go:783-784              "  Kernel RX dropped:    %20d          [%d]"
pkg/dataplane/userspace/format/status_sections.go the status section
```

Nothing writes the producer end. The worker loop sampled `statistics_v2()`
once per second per binding and stored **one** of the six counters it returns:

```rust
if let Ok(stats) = b.xsk.device.statistics_v2() {
    b.live.rx_fill_ring_empty_descs
        .store(stats.rx_fill_ring_empty_descs, Ordering::Relaxed);
}
```

**Measured, with a positive control on the absence claim** (an absence claim
from a grep needs one):

```
TEST     — writers of the two atomics:
  grep -rn 'kernel_rx_dropped\|kernel_rx_invalid_descs' userspace-dp/src/ \
    | grep -E '\.store\(|\.fetch_add\('     -> exit 1, no output

POSITIVE CONTROL — same search shape, sibling counter:
  grep -rn 'rx_fill_ring_empty_descs' userspace-dp/src/ \
    | grep -E '\.store\(|\.fetch_add\('     -> exit 0, 2 hits
     coordinator/tests.rs:1907   (a test)
     worker/loop_body/mod.rs:1549 (the production writer)
```

So `show` / `monitor` reported a permanent hard **0**. That is the
observability form of a fail-open: `Kernel RX dropped: 0` is what an operator
wants to see, and it is what they see while the NIC drops every packet.

## Fix

`BindingLiveState::publish_kernel_xdp_statistics` is now the one site that
turns a sample into atomics, and the worker loop hands it the whole
`XdpStatisticsV2`.

It DESTRUCTURES exhaustively rather than reading three fields. That is the
part that answers the issue's acceptance ("a future field added to the wire
cannot ship unwritten"): the defect was a field with a complete consumer and
no producer, a consumer test passes on a hard zero, and a producer that
forgets a field compiles. With the exhaustive binding, a new kernel counter is
a compile error at the one site that could otherwise drop it.

Three of the six (`tx_invalid_descs`, `rx_ring_full`, `tx_ring_empty_descs`)
are deliberately not carried — no atomic, no snapshot field, no wire field, no
reader anywhere in the tree. Adding them is a wire change, not a store, and a
counter with no reader is the same as no counter. They are named in
`UNPLUMBED_KERNEL_STAT_FIELDS` so the omission is checked, not described.

## The fixture defect this caught, in its own words

The wiring guard's first run failed with `left: 3, right: 1`. Both extra hits
were `statistics_v2()` inside doc comments — including the comment that
explains this very fix. A text guard that counts its own explanation is
measuring the comment, and the failure could have gone the other way just as
easily: deleting the call while leaving a comment mentioning it would have
kept the count at 1 and the guard green.
