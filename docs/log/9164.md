# 9164 — a feed's query-string credential reached journald

- **Timestamp**: 2026-09-06
- **Action**: redact the configured URL and substitute it into the transport
  error, at both the stored and the logged sink.
- **File(s)**: `pkg/feeds/feeds.go`,
  `pkg/feeds/feed_credential_redaction_9164_test.go` (new).

## The defect

`recordFailure` stored `ferr.Error()` verbatim and logged the error **object**.
Go's transport error quotes the URL it dialled:

```
fetch failed: Get "https://127.0.0.1:1/list.txt?token=BEARER_TOKEN_ABC123": dial tcp ...
```

and this repo says outright that this is the common shape — *"dynamic-address
feeds routinely carry per-tenant bearer tokens in the URL"*. `config.RedactURL`
was already called two sites away and simply not here.

## Why not the obvious fix

Wrapping `ferr.Error()` in `RedactURL` is what it looks like it wants, and it is
wrong: that helper is sound on **a URL** and not on arbitrary text, and an error
string is a prefix plus a quoted URL plus a trailing diagnostic. Redacting the
URL we already hold and substituting it is sound by construction — `fs.url` is
the operator's configured string, exactly the input `RedactURL` was written for.

## Two spellings, and that is a measurement

`net/http`'s `stripPassword` rewrites a basic-auth **password** to `***` before
formatting, so the error contains a string that is **not** `fs.url`. Replacing
only the raw URL misses every password case — and leaves the **username**, which
`stripPassword` does not touch. Replacing only the masked form misses the
query-token case, which is the one this product actually has. Both are replaced,
and the masked form is built from the same URL so it cannot drift from what the
transport prints.

## Two of my own gaps, both the lesson I have been giving other lanes

**The wiring was unbound.** My first three cells drove
`redactFeedURLInError9164` directly, and a mutant restoring
`fs.lastError = ferr.Error()` at the call site **survived all of them**. A
redaction helper nothing calls redacts nothing.

**The journal was unbound, and it is the whole channel.** `LastError` has no
operator-visible renderer — the CLI and gRPC show paths print only the
already-redacted configured URL, and Prometheus reads neither. What carries the
secret off the box is the `slog.Warn`. A mutant logging the raw `ferr` while the
stored field stayed redacted survived even the call-site cell. **Storing and
logging are two sinks and each needs its own binding.**

**And my wiring fixture was wrong before it was right**: it omitted `Manager.now`,
so `recordFailure` panicked on UNMUTATED code — which also made that mutant score
meaningless, since a cell failing for a fixture reason "kills" every mutant
equally.

## Validation

| mutant | result |
|---|---|
| sever the call site — store the raw error | applied (1→0), killed by 1 |
| log the raw `ferr` object (the journald half) | killed by 1 |
| drop the password-masked spelling | killed by 2 |
| always rewrite, even with no credential | **survives — EQUIVALENT** |

The last is not a gap: with no credential `RedactURL` returns the input, so the
replacement is a no-op either way and the early return is an optimisation, not a
behaviour. Recorded as equivalent rather than left looking like an escape.

The acceptance table covers `{userinfo password, username, query token, no
credential}` and asserts, for each, that no secret survives **and** that
`fetch failed` / `dial tcp` / `connection refused` and the host all do — a
redaction that eats the diagnostic is a different defect, and an operator reads
this field precisely when the feed is down. The no-credential row asserts
**byte-identical** passthrough.
