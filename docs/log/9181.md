# #9181 — `protocols bgp group`: a packed run whose TAIL is a CONTAINER loses everything

- **Timestamp**: 2026-09-06 (lane-8388)
  - **Action**: fixed the COMPILER half. The census half is lane-8526's, and
    the measurement below is the datum it needed.

    ```
    set protocols bgp group G peer-as 65001 neighbor 10.0.0.1
      -> neighbors=0, no error
    ```

    `neighbor` nests under `peer-as`, so the two-pass group walk never sees a
    child named `neighbor` and pass 1 stamps nothing. **The group is configured
    with nobody in it** — which reads as intentional in a way a missing value
    does not.

    ## Three spellings asserted, and it found a second broken one

    team-lead's #9017 lesson — a leaf verified on ONE spelling is necessary and
    not sufficient; they shipped a declaration that worked on the flat-set and
    compact-body paths and left `family any filter F { … }` still minting zero
    filters. Applied here BEFORE the fix:

    ```
    flat SPLIT      neighbors=1        hier NESTED     neighbors=1
    flat PACKED     neighbors=0        hier ONE-LINE   neighbors=0
    ```

    **The hierarchical one-line braced form fails identically and was not in
    the report.** Same nested-chain AST, so one fix covers both — but only a
    cell that ASKS about both can say so. None of my previous eight #8939 cells
    tested the compact spelling.

    ## A correction to the issue's own example

    ```
    flat  peer-as 65001 neighbor 10.0.0.1               SCHEMA-REJECT
    hier  group G { peer-as 65001 neighbor 10.0.0.1; }  rejected, unknown modifier
    flat  default-originate description "d1" peer-as 65001   ACCEPTED
    ```

    The container-tail case is **`lenient-only`** — it reaches the compiler via
    `Store.Load` and `Store.SyncApply`, not the keyboard. The operator-typed
    case is the FLAG-FIRST ordering, because `default-originate` is args:0 and
    untyped and the container is open-world (#9148's conjunction). The defect
    is real on both channels; only the severity story moves.

    ## The census records this fix as NOTHING

    ```
    before   losers=36 walked=68 vacuous=44 unmeasured=76
    after    losers=36 walked=68 vacuous=44 unmeasured=76
    ```

    > **A real defect was fixed and the instrument recorded a zero delta.** The
    > row stays `vacuous` because the fixture declares no `neighbor` and group
    > settings only materialise inside `BGPNeighbor`, so a loss and an empty
    > container read identically.

    That is 9181's census-half premise demonstrated rather than argued, with a
    before/after on one tree. It also means this change cannot conflict with
    the vacuous-row enumeration: it does not touch the fixture at all.

    Mutation: reverting the expansion reds three of four subtests. The
    **nested-braced arm correctly SURVIVES** — it is the mutant-that-must-
    survive, since a segmentation bug would break the spelling that already
    worked. Verified with a before/after grep count rather than the exit status.
