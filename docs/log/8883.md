# 8883 — a packed multi-leaf run injected its own keyword

**Action**: `firewallMatchValues` skips a repeat of the leaf's own keyword; two
cells in `multi_leaf_absorbs_keyword_8883_test.go`.

## Defect

    system { name-server 1.1.1.1 name-server 8.8.8.8; }
      -> [1.1.1.1 name-server 8.8.8.8]

A DNS resolver whose address is the literal string `name-server`, silent at
strict commit and on the tolerant ingress. Both braced spellings give
`[1.1.1.1 8.8.8.8]`, so the spelling and not the values changed the result.

## The remedy is PER-READER, which is the durable finding

`packedStatements` on the container is measured insufficient: a `multi` leaf
absorbs the run before any split. The fix belongs in the VALUE READER — and
there is more than one.

Fixing `firewallMatchValues` (71 callers) corrects:

    system name-server, system domain-search, ssh key-exchange, bgp export

and does NOT correct:

    ntp server            (own loop, compiler_system.go)
    nat source pool address (own loop, compiler_nat_helpers.go)

Both still inject. So the 86 `multi` members do not share one remedy, and a
guard green on `name-server` says nothing about the rest. The cell says so.

## Blast radius, measured

71 callers changed; pkg/config, pkg/configstore, pkg/daemon and
pkg/refactoraudit all green, zero failures.

## Why the assertions are on contents

Injection ADDS a member, so a length check reads three members as more coverage
than two. Every assertion is on the member list, plus one naming the specific
injected token so that a failure for an unrelated reason cannot pass a weaker
check.
