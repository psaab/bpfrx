# #8895 — the sweep's WARNS verdict was unsound

- **Timestamp**: 2026-09-05
  - **Action**: `gated()` in the brace-elision sweep asked "does the elided
    spelling produce ANY warnings?" and scored WARNS — which the #8859 criterion
    reads as HANDLED, the operator is told. That is a different question from
    "is the operator told about THIS drop". Any container carrying a standing
    advisory (a parity notice, a deprecation, an accepted-only warning) answered
    it for free, so a real silent drop inside such a container read as handled.
  - **Measured** on `aggregated-ether-options -> lacp`, byte-identical warning
    in both arms:

    ```
    braced  warnings=1  "aggregated-ether-options configured but accepted-only
    elided  warnings=1   — xpf does not implement 802.3ad link aggregation"
    ```

    The operator is told LAG is unimplemented. They are not told `lacp active`
    was discarded.
  - **Fix**: compare the warning SETS between the two arms — only a warning
    present in the elided arm and absent from the braced one is about the drop.
    The liveness rule applied to the warning channel: a warning in both arms is
    standing and proves nothing.
  - **Error direction**: this could only score a real drop as HANDLED, never the
    reverse, so it under-reported.
  - **The branch had no control, which is why the rule survived.** The sweep's
    own header recorded that the WARNS branch has no member and that "nothing
    here proves it still fires". Added both controls: a standing warning must
    NOT score WARNS, and a warning unique to the elided arm MUST.
  - **Numbers unchanged** — the WARNS branch had no members, so no published
    row changes. 55 pairs: 31 SILENT, 2 STRICT-REJECTS, 0 WARNS, 21 SAME,
    1 NO-REFERENCE.
  - **Found by lane-8388** on #8876 batch 11; reproduced here before changing
    anything.
  - **File(s)**: pkg/config/compact_elision_sweep_test.go,
    pkg/config/sweep_warns_soundness_8895_test.go
  - **Review round 2 (the lead's mutation)**: the first version of these cells
    was green under a full revert of the fix. Neither called `gated` — both
    re-implemented the set comparison and asserted the re-implementation was
    correct, which verifies an algorithm and binds no wiring. Worse, the file
    held a SECOND copy of the predicate inside the reachability cell, still on
    the old logic, so the cell whose job was to prove the WARNS arm fires was
    validating the rule the sweep had stopped using.
  - **Fix**: hoisted one package-level `sweepGateVerdict8859(braced, elided)`;
    the sweep, the reachability table and both soundness cells all call it.
    Reverting it to the counting form now reds two cells by name.
  - **And the old positive control was itself unsound**: the reachability rows
    asserted `security alg h323` scores WARNS — but that advisory is STANDING,
    identical in both arms. It only ever passed under the rule being removed.
    That row now expects SILENT and is the mutation-killer.
  - **The WARNS arm has no natural member, measured not assumed**: its only
    mechanism (#6662's packed-login notice) sits behind a spelling the STRICT
    path rejects first, so the pair scores STRICT-REJECTS. Recorded in the cell
    rather than papered over with a manufactured fixture.
