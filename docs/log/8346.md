# 8346 — one ledger file per run

- **Timestamp**: 2026-09-03
  - **Action**: Moved the harness ledger from a single appended
    `test/results/ledger.jsonl` to `test/results/ledger.d/<run_id>.json`, one
    shard per gate run. Two writers never touch the same path, so concurrent
    lanes are conflict-free by construction rather than by a merge driver. The
    emitter writes under a temp name in the same directory and renames, so a
    reader globbing while a gate finishes never sees a half-written shard;
    rename(2) is atomic where the old append needed flock. The 10 existing rows
    were migrated byte-identically, verified by run_id set equality.
  - **File(s)**: `test/incus/harness-result.sh`,
    `test/results/ledger.d/*.json`, `test/results/ledger.jsonl` (removed)

- **Timestamp**: 2026-09-03
  - **Action**: Taught the comparator the layout: `load_ledger_text` reads a
    shard directory OR a legacy single file and returns the same JSONL text, so
    the storage change does not touch the band arithmetic at all — pinned as an
    equivalence (the band over the sharded rows equals the band over the same
    rows as one file) rather than as a number. `lint_shard_names` enforces that
    a shard's filename equals the run_id it contains, which is what makes the
    layout conflict-free and what lets the merge guard read ids off a git tree
    without parsing.
  - **File(s)**: `test/incus/ledger_compare.py`,
    `test/incus/ledger_compare_test.py`

- **Timestamp**: 2026-09-03
  - **Action**: Kept #8349's completeness guard armed across the migration.
    `run_ids_at_rev` unions BOTH layouts at every revision — the legacy file via
    `git show` and the shard directory via `git ls-tree`. Without the legacy
    source a parent predating the migration reads as the EMPTY SET, `missing` is
    empty, and the guard passes vacuously — loudest on the one merge most likely
    to drop rows, this change's own. The set logic was split into
    `lint_merge_completeness_ids` and the text-taking signature kept as a public
    door, so #8349's cells keep exercising it rather than being decommissioned.
  - **File(s)**: `test/incus/ledger_compare.py`,
    `test/incus/ledger_compare_test.py`

- **Timestamp**: 2026-09-03
  - **Action**: Fixed two defects the migration itself introduced, both found
    by cells rather than by reading. (1) The dirty-flag exclusion matched
    `ledger.jsonl$`, a path that no longer exists, so every row would have been
    stamped `-dirty` again; the cell had to move to a shard fixture with it or
    it would have passed while guarding nothing. (2) Under one file per run the
    load order is sorted-random-hex, not write order, so the comparator's
    load-order tie-break made "which row is newest" a function of the filenames
    for same-second rows; the tie-break is now `run_id` (deterministic and
    storage-independent) and new rows carry millisecond timestamps so real runs
    do not tie.
  - **File(s)**: `test/incus/harness-result.sh`,
    `test/incus/ledger_compare.py`, `test/incus/harness-result-selftest.sh`

- **Timestamp**: 2026-09-03
  - **Action**: Removed the `merge=union` rule and its rationale from
    `.gitattributes` rather than retargeting it — one file per run needs no
    driver, and #8348 showed a driver can be disarmed from a file nobody reads.
    Corrected the ledger docs, which claimed the lint made a bad merge "a red
    gate and not silent corruption": it sees a damaged row and cannot see a
    missing one, and an overstated claim about a detector is worse than none
    because it stops the next person looking.
  - **File(s)**: `.gitattributes`, `docs/harness-ledger.md`,
    `docs/engineering-style.md`, `scripts/run-selftests.sh`, `Makefile`
