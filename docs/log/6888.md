# #6888 — heartbeat readLoop discards the UDP source address

- **Timestamp**: 2026-08-27
  - **Action**: pinned the heartbeat read loop to the configured control-link
    peer, dropping foreign-sourced datagrams before unmarshal / cluster-id
    validation / MAC verification. `peerAddr` was a field on the SENDER only, so
    the address had to be plumbed into the receiver: a new required constructor
    parameter (not a setter — the compiler then proves every construction site
    decided what to pass), wired from `startHeartbeatLocked` where `peer` was
    already in scope beside the sender's use of it.
  - **Measured, not assumed — address only, never port.** The peer's sender
    socket binds port 0 (`net.JoinHostPort(localAddr, "0")`), so it sources from
    an ephemeral port that changes every restart. Confirmed read-only on the
    live loss cluster under a `with-cluster.sh` lock cell: fw0 listens on
    `10.99.12.1:4784` and sources from `:40745`; fw1 listens on
    `10.99.12.2:4784` and sources from `:50923`. **An address+port pin would
    have rejected 100% of legitimate heartbeats and taken down every cluster.**
  - **Fail-open cases, each with its own cell**: nil `peerAddr`, `peerAddr` with
    nil IP, nil source, source with nil IP. A pin that rejects when it does not
    know what to accept is strictly worse than no pin.
  - **Counted, not silently dropped**: `foreignSrc` on the receiver, surfaced as
    `HeartbeatStats.ForeignSrcDropped`, plus a 30 s rate-limited warning naming
    the source and the configured peer. The issue's strongest argument is that a
    misconfigured third node is currently invisible; an uncounted rejection
    reproduces that one layer down.
  - **File(s)**: pkg/cluster/heartbeat.go, pkg/cluster/heartbeat_manager.go,
    pkg/cluster/heartbeat_peer_pin_6888_test.go, pkg/cluster/README.md
  - **Framing**: NOT an authentication fix. Frames are HMAC-verified in
    `admitFrame` and an attacker without the PSK could never get one admitted
    whatever source it carried. This is cheapest-point filtering,
    misconfiguration visibility, and partial constraint under a leaked PSK.
