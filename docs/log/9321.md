# #9321 — RT_FLOW structured records interpolated operator names into RFC 5424 SD-PARAMs unescaped

- **Timestamp**: 2026-09-06
  - **Action**: added `escapeSDParamValue` (RFC 5424 §6.3.3: `"`, `\`, `]`) and
    applied it to every value `formatStructuredMsg` interpolates into the
    `[junos@2636.1.1.1.2.129 …]` element.
  - **File(s)**: `pkg/logging/ringbuf.go`,
    `pkg/logging/format_rtflow.go` (new — see the split note below),
    `pkg/logging/sdparam_escape_9321_test.go` (new), `pkg/logging/README.md`

    A policy named `p1" injected-param="1` forged a SECOND SD-PARAM in every
    record shipped off-box; a `]` closed the element early so a strict collector
    read the remainder as MSG and lost the record.

  - **#6585's exemption is deliberate and the fix must not undo it.** I read
    #6585's acceptance criteria before choosing a remedy, as instructed. Its
    guard (`termsafe.SanitizeForDisplay` at `SyslogClient.Send`) is scoped to
    CONTROL BYTES on purpose: its third criterion is an explicit over-reach
    guard that "ordinary multi-word and UTF-8 attribute values are unchanged on
    the wire", and it protects the RFC 3164 FRAME, which three printable bytes
    cannot damage. Widening it would have mangled every other consumer of that
    sanitizer — gRPC show output, IPsec error text — for a property only the SD
    element has. #6585 closed frame integrity; #9321 closes SD-element
    integrity. Two boundaries, both needed, and the escape lives at the second.

  - **Escaped ONCE, before the type switch**, after the empty-value fallbacks (a
    fallback is itself a param value) and before the arms (several values are
    interpolated twice per record — `appName` is both `service-name` and
    `application`). Byte-scan rather than rune-scan: all three characters are
    ASCII and every byte of a multi-byte UTF-8 sequence is >= 0x80, so a byte
    scan can neither split a rune nor match inside one.

  - **The address/port values are escaped too, and the reason is not paranoia.**
    `splitAddrPort` returns its input VERBATIM when `net.SplitHostPort` fails, so
    "an address cannot contain a quote" is a claim about a parser, not about the
    data. The helper's fast path makes escaping free on values that need none,
    so the cheap rule and the total rule are the same rule — and a total rule is
    the one a newly-added field inherits.

  - **A CELL OF MINE WAS VACUOUS AND THE MATRIX FOUND IT.**
    `TestARbracketInANameCannotTerminateTheElement9321` passed under the
    identity mutant (R1) — it was absent from R1's RED list. The cause was my
    ORACLE, not the assertion: the first parser scanned a PARAM-VALUE only for
    `"` and `\`, so an unescaped `]` inside a quoted value looked like ordinary
    content and the element never appeared to close early. That is the lenient
    reading; §6.3.3 says the character MUST be escaped, so its presence is
    MALFORMED INPUT, and collectors differ in recovery (rsyslog terminates the
    element there). The oracle now does both — records the violation AND ends
    the element — so the cell asserts the fact ("this record is malformed")
    without depending on a guess about any one collector.

    Two general lessons, both of which the coordinator had already named: a
    fixture that cannot express the property under test passes identically with
    and without the fix; and an oracle written by reversing the producer agrees
    with the producer by construction. This oracle implements §6.3.3's READING
    rules instead.

  - **Byte-identity is pinned against golden strings CAPTURED, not
    transcribed.** The three goldens come from running the unmodified formatter
    at `origin/master` (77240ec4e) in a throwaway worktree and pasting its
    stdout. A golden transcribed from the format strings would only prove that
    my transcription agrees with itself.

  - **Coverage is by reflection.** `TestEveryStringFieldIsSDParamSafe9321` walks
    every exported string field of `EventRecord`, poisons each with `a"b\c]d`,
    and asserts the element keeps its exact param-name list and closes at the
    end — so a string field added later is poisoned automatically. It also
    asserts the poison actually REACHED an SD-PARAM (29 values across the three
    record types), because a reflection walk that reaches nothing is a green
    that asserts nothing.

    The two columns are the vacuity finding, not decoration. R1 and R4 gained
    four red cells each and R5 gained five when the oracle stopped treating an
    unescaped `]` inside a quoted value as ordinary content — the same cells,
    the same production code, a different oracle. **R5 is the row that shows why
    it mattered**: with the lenient oracle a fix that escaped everything EXCEPT
    the zone names scored one red; with the strict one it scores six.

    R3 is the row the helper's implementation shape exists for. Escaping `"`
    first and `\` second doubles the backslash just inserted, so `a"b` emits
    `a\\"b` — which a conforming parser reads as a literal backslash followed by
    an UNESCAPED quote: the injection restored *through* the fix.

    R6 is the call-site severance. My unit cells call `formatStructuredMsg`
    directly and would all have survived it; only the end-to-end cell (raw frame

    maps `daemon_system.go` fills from the compiled config) reds, alongside the
    existing #3409 cell.

  - **The `go test ./...` gate caught a modularity regression the package gate
    could not.** `TestTouchedFileCrossedModularityThreshold`

    sink emits. The same seam #5661 used to lift `agent_ber.go` out of
    `agent.go`. Verified as PURE CODE MOTION programmatically, not by eye: the
    moved block is byte-identical to lines 1075-1332 of the pre-split file, and
    the ringbuf.go remainder is byte-identical to that file minus exactly that
