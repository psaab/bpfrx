## The defect

```go
// Only clear if this loop is still the registered one: a stop
// followed by a restart must not have the OLD goroutine's exit
// clear the NEW loop's cancel.
if d.ipsecSASync.loopCancel != nil && loopCtx.Err() != nil {
```

`syncIPsecSAPeriodic` has exactly **one** return — `case <-ctx.Done()` — so
`loopCtx.Err() != nil` is **always** true there. The guard reduced to "always
clear": precisely what its own comment forbids.

A stop-then-restart while the old goroutine is still in flight then had A's exit
clear B's cancel, leaving loop B **unregistered** — a later knob-OFF silently did
nothing (the publisher keeps advertising after the operator disabled it) and a
later knob-ON started a **second** publisher, which is the leak the file's own
`launches` counter exists to make observable.

A generation counter rather than the cancel func because **Go cannot compare func
values** — only against nil, which is the comparison that was already there and
already insufficient.

## The sibling, with its exposure stated accurately

`stopClusterComms` called `resetDHCPLeaseSyncLoop` and had no IPsec counterpart,
so a comms teardown left the handle set and the next `ensure` took its
already-running early return against a cancelled context.

Recorded as measured rather than as filed: `daemon_apply_tail.go` calls
`ensureIPsecSASyncLoop` on **every** apply, outside the transport-change branch,
so recovery was bounded by "until the next commit" — **not** "needs a knob
toggle". The window is sub-millisecond unless the goroutine is blocked in a
strongSwan vici query, the only realistic widener.

## Extracted to avoid a flaky cell

The defect needs an **overlap** — A exiting after B is registered — and a
sequential stop/restart passes on the broken code. Reproducing the overlap by
racing a real goroutine would make the cell timing-dependent, and **a low-rate
flake is worse than no cell**: it passes for its author and fails for someone
else in an unrelated package. `clearIPsecSALoopIfCurrent` is a pure function of
the generation, so both orderings are exact.

## My fixture masked the property it was testing

Mutant C — removing the generation bump from the reset — **survived**, because my
cell bumped the generation *itself* after calling the reset. With the fixture
supplying the bump, whether the code supplied it changed nothing. **A cell that
does the work the code should do is testing its own arithmetic.** Removing my
manual bump made it discriminate.
