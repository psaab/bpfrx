# #9019 — the NAPI bootstrap derived its probe target from IPv4 only, and skipped silently

- **Timestamp**: 2026-09-06
  - **Action**: made the probe-target derivation family-complete and the skip
    observable.

    `bootstrapNAPIQueuesLocked` queried `RouteList(link, FAMILY_V4)` and
    `NeighList(idx, FAMILY_V4)`, each additionally filtered through
    `.To4() != nil`, then `continue`d on an empty target with no log, no
    counter and no status field. An interface with no v4 gateway route and no
    v4 neighbour was therefore skipped unconditionally — a v6-only segment
    always — and the skip was indistinguishable from a successful probe.

    Both lookups now ask for `FAMILY_ALL`, and the derivation moved into a pure
    `deriveNAPIProbeTarget(routes, neighs)` applying v4 gateway → v4 neighbour →
    v6 gateway → v6 neighbour. **Order is part of the contract**: an interface
    that derived a target before derives the SAME one now, so this widens the
    probed set and changes the target for no existing box. A remaining skip is
    counted (`NAPIProbeTargetSkips`, mirroring `LearnedRouteCapHits`) and logged
    with the interface name; the other silent `continue` (link-lookup miss) is
    counted too.

    **The seam exists for the measurement, not for tidiness.** "The v6 path is
    silently skipped" is an ABSENCE claim, and an absence observed against a
    harness that was never wired up measures the harness. Extracting a pure
    function lets the v6 rows run beside v4 rows that demonstrably DO derive a
    target in the same run, so a broken fixture reds the v4 controls instead of
    quietly passing the v6 ones. The table asserts a floor on how many rows
    returned a live target for that reason.

    **One survivor, recorded as EQUIVALENT rather than as a gap.** Dropping the
    `To4() == nil` clause from the v6 arms survives the suite. That is correct:
    the v4 arms run first and return for any `To4() != nil` address, so the v6
    loops cannot see a v4 address however they are written. The clause is
    defensive redundancy that only becomes load-bearing if the arm ORDER
    changes — which the ordering rows do red. My first version of that code
    comment claimed the cell made the discriminator "falsifiable"; it does not
    and cannot, and both the comment and the cell's doc now say so. Verified by
    re-running the mutation unfiltered after it produced no output, since a
    build failure and a clean pass look identical through a filtered result
    line — the same trap that produced a false survivor on #9007 and a void cell
    on #9018.

    Four mutants killed: M1 (v6 arms removed — the original defect), M3 (v6 arms
    hoisted above v4 — reds the ordering rows AND the v4-in-v6 cell), M4
    (NUD_FAILED exclusion dropped from the v6 neighbour arm), M5 (the skip stops
    incrementing the counter, i.e. back to silent).

    NOT done: the issue's suggested LAST-RESORT target (the link's own address
    or a link-local all-nodes destination) for a segment with neither a gateway
    nor a neighbour. A datagram to this box's own address is handled locally and
    generates no hardware RX event, and a multicast probe's efficacy is
    unmeasured here — this file's entire history is a warning against adding or
    weakening a probe path on a source reading rather than a measurement. Such a
    segment is now COUNTED as unprobed, which is the actionable part. The
    issue's third item (per-queue liveness instead of the box-wide
    `xskLivenessProven`) is also untouched.
