# 9019 — the NAPI probe-target skip, and the counters nobody read

- **Timestamp**: 2026-09-06
- **Action**: complete #9019 by surfacing the counters. The derivation half had
  already landed (`575973541`); the observability half had not.
- **File(s)**: `pkg/api/metrics_dataplane_silent_skips_9019.go` (new),
  `pkg/api/metrics_dataplane_silent_skips_9019_test.go` (new),
  `pkg/api/metrics.go`, `pkg/api/metrics_descriptors_global.go`.

## What was already done

`575973541` made both netlink lookups `FAMILY_ALL` and added
`deriveNAPIProbeTarget`, which applies the priority v4-gateway, v4-neighbour,
v6-gateway, v6-neighbour — so an interface that derived a target before derives
the SAME one, and the v6 arms are reached only where the old code had given up.
A remaining skip increments `napiProbeTargetSkips` and is logged with the
interface name. That is a good fix and it is not what this entry is about.

## What was missing, and why it is the more interesting half

#9019's acceptance asked for a counter **and** a status surface. Measured:

```
NAPIProbeTargetSkips  -> referenced by its own file, its own test, one comment
LearnedRouteCapHits   -> referenced by its own file, its own test, one comment
                         (that comment is in napi_probe_target_9019.go, which
                          copied its shape)
```

**Zero consumers outside their own package.** Not in Prometheus, not in a status
field, not in a CLI command. Two exported counters, added by two fixes each
asked to make a silent skip observable, and neither could be observed.

That is worse than having no counter, because the counter reads as the remedy.
The visible half of the acceptance was satisfied — something increments — while
the box stayed exactly as silent as before. Both were found by grepping for the
consumer rather than by reading either fix, which is the general lesson:
**adding the producer is the part that gets reviewed; adding the reader is the
part that gets forgotten, and nothing distinguishes the two states from inside
the file that produces.**

## What landed

`xpf_napi_probe_target_skips_total` and `xpf_learned_route_cap_hits_total`, both
always emitted including at zero (#3464 / #8312 convention: a counter that
appears only on first fire cannot be alerted on and cannot distinguish "never
skipped" from "not scraped" — and zero is the normal state for both, so it is
the reading that must be trustworthy).

Both are emitted **before the dataplane gate**. For the neighbouring
admission-refusal and authz-denial counters that is convention; here it is
load-bearing, because these describe a dataplane that came up INCOMPLETELY, and
gating them on a healthy dataplane would hide them in exactly the case they
exist for.

## Validation

The cells drive the collector's real `Describe`/`Collect`, never
`emitDataplaneSilentSkips` directly — calling the emitter would reproduce the
original mistake, proving the emitter works while the collector still never
calls it. The harness leaves `srv.dp` nil on purpose, so `Collect` takes the
early return at the dataplane gate and the counters must still arrive.

Three distinct mutants, each killed by one cell:

| mutant | result |
|---|---|
| drop the `Collect` wiring | killed |
| drop the `Describe` wiring | killed |
| move the emit to the END of `Collect`, after the dataplane gate | **killed** |

The third is the one that proves the no-dataplane harness is doing real work
rather than decorating a comment.

Stated limitation, in the test: the increment seams are unexported, so pkg/api
cannot move either counter and cannot watch the value change. It binds the
emitted number to the accessor; that the accessor moves on a real skip is pinned
next door by `TestNAPIProbeTargetSkipIsCounted9019`. The pair spans the two
packages the value crosses, and neither half is sufficient alone.

`go test ./...` green.
