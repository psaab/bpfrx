# #6954 — body-budget tier ladder: privilege scope under custom login classes

- **Timestamp**: 2026-08-28
  - **Action**: Confirmed the issue. `mutationBodyTierCeilings`' guarantee
    ("exhausting it is not a way to deny someone more privileged than you") is
    a statement about TIERS; reading it as a statement about PRINCIPALS needs
    the premise that reachable tiers grow with privilege, which holds for the
    system-defined classes and not for a custom `system login class`. Corrected
    the table's comment and the `pkg/api/README.md` drain row to state the real
    property plus its scope, and bound both to production with three new cases:
    the guarantee asserted pair-by-pair over the built-in classes (with an
    anti-vacuity floor), the same predicate shown to FAIL for two committable
    custom classes, and an end-to-end REST case where a `permissions configure`
    principal's flood answers 429 to a strictly-more-privileged
    `permissions [ configure view ]` principal's view-tier request. Sharpened
    the issue's reachability: the flood costs 8 MiB (the victim's view ceiling),
    not the 48 MiB the flooder's own configure ceiling allows.
