## The claim that was wrong, and I wrote it

`TestUnadmittedTopLevelPairsAreAdjudicated8925` justified covering only
top-level pairs:

> A deeper pair is reachable only through a parent that is itself either
> admitted (so the parent's body is folded and the child is reached) or listed
> here.

**False.** Elision is a **per-level** decision. `security nat { ... }` folds
because `(security, nat)` is admitted; whether `nat source { ... }` folds is a
*separate* question answered by `(nat, source)`. An admitted parent gets you to
the child's brace — it does not fold the child's brace.

A stated blind spot is a claim, as falsifiable as any other. This one survived
about an hour, and only until someone tried it.

## The confirmed drop

    security { nat { source { pool p1 { address 10.9.0.1; } } } }   pools=1
    security nat { source { pool p1 { address 10.9.0.1; } } }       pools=1
    security nat source { pool p1 { address 10.9.0.1; } }           pools=0  <-- drop
    (empty config)                                                  pools=0

The doubly-elided spelling compiles to **exactly what an empty config
produces** — the source NAT pool vanishes. Both spellings accepted at strict
commit, no warning. Fixed by admitting `nat source`.
