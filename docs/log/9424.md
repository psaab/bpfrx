# 9424 — bracketed interface address list keeps only the first address

- **Timestamp**: 2026-09-07
- **Action**: Reproduced in an owned worktree off `origin/master`.
  `family inet { address [ 10.0.0.1/24 10.0.0.2/24 ]; }` compiled to ONE
  address through all four channels in both AST shapes, on inet and inet6,
  with `Warnings=[]`. The two-separate-stanzas control compiled both. The
  mechanism is `namedInstances` reading slot 0 only (`Keys[1]`), the canonical
  #2419 shape; #6662 and #7653 swept `namedInstances` callers and did not
  reach this site.

- **Timestamp**: 2026-09-07
- **Action**: Chose ACCUMULATE over the REFUSE remedy its sibling class used
  (#8794 / #9246 / #8810). Those refused because expanding would have invented
  a semantics the platform lacks; a logical unit with two addresses is
  ordinary, and the two-stanza control compiles exactly it.

- **Timestamp**: 2026-09-07
- **Action**: Implemented. `unitAddressInstances` accumulates the packed tail
  (hierarchical) and the child chain (flat set); the discriminator is taken
  from the SCHEMA — the address node's own `keyValidator` and its declared
  children — so it cannot drift from the grammar. Malformed tokens are
  recorded on `InterfacesConfig.MalformedAddresses` and refused by a strict
  gate appended at the END of the uniform-gate phase (the gate order is
  observable), with the #1960 lenient downgrade.
