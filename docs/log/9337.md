# 9337 — the privileged leg 42 guards deferred to did not exist, and running it found a live fail-open

## Summary

`pkg/memlockcensus` (#8371) enumerates 42 test guards that go inert without BPF
privilege and defers enforcement to "a privileged CI leg, gated on
`XPF_REQUIRE_MEMLOCK_GUARDS=1`". That leg did not exist — `.github/` holds only
`instructions/`, there is no CI in this repository, and nothing set the
variable. Running the guards for the first time found:

- a **live fail-open** in the #7468 atomic retain, on the deferred-publish path;
- a **census remedy that names the wrong capability**, and a readiness predicate
  that reports READY in an environment the guards cannot run in;
- **11 red or void cells** in `./pkg/dataplane/...`, including a hang that
  consumed a whole 15-minute package budget and voided every cell after it.

All fixed here, plus `make test-memlock-guards` (a prerequisite of `make
test-root`) so the deferral names something real.

## 1. The fail-closed publish defect (production)

### The red the issue starts from was a FIXTURE defect

```
addr_only_commit_failclosed_4959_test.go:302:
  publishedSnapshot = 1 after a successful deferred publish, want 8
```

**The `want 8` assertion is correct** — `syncSnapshotLocked` sets
`m.publishedSnapshot = m.lastSnapshot.Generation` immediately after a successful
publish, and nothing changed that contract. The cell was wrong for a different
reason: `ensureEgressZoneProtocolLocked` re-probes the helper with a `status`
request whenever no matching version has been OBSERVED, and that probe consumed
the fixture's single queued control-server response. The `apply_snapshot` the
cell exists to exercise then got none and timed out.

The tell was in the timings all along: **3.01 s per sub-test**, i.e. one
`controlRoundtripDeadline`, for a unit test with no I/O.

Seeding an observed matching version (`lastStatus.ConfigSnapshotProtocolVersion
= ProtocolVersion`, `helperStatusObserved = true`) makes the single response go
to the `apply_snapshot`. The success cell then passes.

### And the refusal cell had been passing through the WRONG BRANCH

With the fixture corrected, the sibling `rejected_deferred_publish_disables_ctrl`
still passed — but the log said why:

```
WARN userspace: helper refused the snapshot; classifier maps rolled back to the
     retained snapshot and transit continues on it
     retained_generation=8 refused_generation=8
```

`retained == refused`. The #7468 retain was rolling the classifier maps back to
the plan the helper had just refused. It reached `ctrl.Enabled=0` only because
the unit harness loads no classifier maps, so the "rollback" failed with
`userspace_ingress_ifaces map not loaded` and fell into the ctrl-disable
fallback. **In production the maps ARE loaded, the rollback succeeds, and ctrl
stays Enabled=1.**

### The mechanism

`retainPreviousClassifierPlanLocked` used `m.lastSnapshot` as "the snapshot the
helper is still enforcing". That holds at every publish site but one:

| site | `m.lastSnapshot` at publish time |
|---|---|
| `applyCompiledSnapshot` normal path | assigned AFTER the publish → still previous-good |
| route-overlay / policy-scheduler / deferred-worker-arm | assigned after a successful publish, together with `publishedSnapshot` |
| **`applyCompiledSnapshot` pendingXSKStartup branch** | **assigned BEFORE returning; `syncSnapshotLocked` then publishes `m.lastSnapshot` ITSELF** |

So on the deferred path an in-band `{"ok":false}` "rolled back" to the refused
plan — a no-op dressed as a rollback that reports success — and the shim kept
steering transit to XSK against a plan the helper never accepted while the
helper enforced the previous-good one. That is the #4959 fail-open,
reintroduced by its own remedy.

`pkg/dataplane/README.md` already stated the precondition the code did not
check: ctrl stays enabled on a retain *"because the maps then match what the
helper is enforcing"*. On this path they do not.

A second, later-reachable case shares the defect: after a deferral,
`m.lastSnapshot` is generation N while the helper still holds the older
`m.publishedSnapshot`. The NEXT ordinary Compile would then "retain" onto
generation N — a plan the helper never received either. A predicate spelled
"retained is not the refused snapshot" is true there and still wrong, which is
why the fix is an equality against `m.publishedSnapshot` rather than an
inequality against the refused plan.

### The fix

`classifierPlanRetainable` takes `publishedGeneration` and retains only when it
names the retained snapshot (and is non-zero — nothing published means the
helper holds no plan of ours). Otherwise the #4959 ctrl-disable stands.

### Severity

Not merely an outage. The classifier maps decide which ifindexes are redirected
to XSK versus passed to the kernel, plus local-delivery and interface-NAT
ownership. An interface that the NEW plan drops is absent from
`userspace_ingress_ifaces`, so with ctrl still enabled the shim `XDP_PASS`es it
into the Linux stack, where `ip_forward=1` forwards it with no zone policy
evaluated — while the daemon reports the previous-good snapshot as enforced.
That is the same class `pkg/dataplane/README.md` calls *"a policy BYPASS, not
merely an outage"* for the detach-ordering divergence one paragraph over.

### New seam, and why

`failClosedCtrlMapHook` (mirroring `disableCtrlMapHook` #5486 and
`helperStatusCtrlMapHook` #6994) makes "a rejected publish drove ctrl to 0"
observable without CAP_BPF. Unprivileged, `m.bpfShim.Map` returns nil and the
fail-closed write silently no-ops — precisely the state in which a guard cannot
tell fail-closed from never-tried. `pkg/memlockcensus`'s own doc names moving an
assertion below the privilege boundary as the PREFERRED remedy over recording
another conditional guard; this does that for the #4959 property.

## 2. The census names the wrong capability (item 2 — premise CONFIRMED)

Reproduced independently, three states on this host:

```
A) plain user            RemoveMemlock: FAILED    NewMap: FAILED
B) root                  RemoveMemlock: OK        NewMap: OK
C) memlock rlimit raised, dropped back to uid 1000:
   memlock cur=18446744073709551615
   RemoveMemlock: OK   <- the OLD predicate: "all 42 registered guards execute"
   NewMap:        FAILED (map create: operation not permitted)
```

State C is the trap: following the census's own advice ("Run as root or with
CAP_SYS_RESOURCE") produces an environment it calls READY and the guards cannot
run in — they stop skipping and start FAILING, at map creation, with an error
that looks nothing like the defects they exist to catch.

`probeGuardReadiness` now performs the first operation every guard performs (a
trivial `ebpf.NewMap`) and reports THREE states, with different text for "they
SKIP" and "they FAIL" — those call for different actions. Verified in state C:
the census now refuses it up front instead of reporting READY.

Guarded by `TestReadinessIsNotMemlockAlone9337` (a unit truth table on the
measurement — the state cannot be produced from inside a test process without
CAP_SETPCAP, and a check that only runs where the defect is absent is not a
check) and `TestRemedyTextNamesTheCapabilityTheGuardsNeed9337`.

### The hang

`TestManager_ArmedGate_DetachRetainedClaims` waited forever on `<-probeArrived`.
The goroutine dump named the mechanism exactly:

```
goroutine 256 [sync.Mutex.Lock, 14 minutes]:
	(*Manager).xdpLinkFor(...)  link_maps.go:147
	(*Manager).DetachXDP(...)   loader.go:796
```

`DetachXDP` **did** block on `m.mu` — but at `xdpLinkFor`, which carries no
`muAcquireProbeHook` pre-lock fire, so the arrival proof never fired.

It was not always so. Before `01409c1f` (2026-08-22, "guard the link maps behind
m.mu and hand out snapshots") `DetachXDP` read `m.xdpLinks` unlocked and its
first contended acquisition WAS the probed `lookupMapLocked` inside
`setXDPAttachedFlag`. That commit moved a plain acquisition ahead of the probed
surface and silently converted a valid arrival proof into an unbounded deadlock.
The cell needs a real BPF map, so it skips unprivileged — nothing could see it.

Two changes, because they answer different questions:

1. `xdpLinkFor` fires the probe. Restores the proof. All the `armedGateDirectLockSet`
   attribution legs still pass, so the pin did not drift.
2. The wait is BOUNDED with a named failure. **A hang's blast radius exceeds its
   own cell** — its budget belonged to every later cell, and the two extra
   defects above are exactly what it was hiding. The hook's doc comment now
   records that the probed set is a claim about the CALLERS, and that moving a
   plain acquisition ahead of a probed one turns every such wait into a deadlock.

### Diagnostics improved rather than only the cells

- `assertUserspaceXDPDegradedPathStat` now names the reasons that DID fire. The
  shim's degraded gates are an ordered chain, so "stat X = 0" is almost always
  "an earlier gate diverted the packet" — which the counter set states directly.
  Diagnosing it from the bare message cost a full read of `userspace-xdp/src/lib.rs`.
- `TestReconcileProxyARP_V6InstallsPneighLive` installs a pneigh entry it owns
  and requires the probe to see IT first. A prober that cannot see proxy entries
  and a reconcile that installed nothing report the same thing, and that reading
  is exactly the defect found here. Both directions mutation-checked: reverting
  the channel to `NeighList` fires the CONTROL message ("the PROBE is broken, not
  the code"); severing the production v6 install fires the OTHER message, with
  the control visible in the same dump.

## 4. `make test-memlock-guards` (item 4)

No CI workflows were added — that decision is not in scope. The target:

- refuses to run without CAP_BPF, and says CAP_SYS_RESOURCE alone is not enough;
- **derives the package set FROM the registry**, and fails loudly if the
  derivation yields nothing (a target that runs nothing and reports success is
  the failure it exists to prevent);
- verifies **BY NAME** that every registered `Test...` row produced a `=== RUN`
  line — the discipline `test-shim-run` already records: a `-run` predicate is a
  claim about names and fails silently in the only direction that matters;
- pins `TMPDIR=/tmp`, because several guards bind an AF_UNIX socket under it;
- is a prerequisite of `make test-root` (#9052's root-capable aggregate), so it
  is reachable by a name someone already knows rather than by remembering it.
