# 8886 — a packed run inside intact braces

**Action**: `splitBracedPackedChildren8886` in `compact_normalize_8662.go`;
three cells in `braced_packed_run_8886_test.go`.

## Defect

    dead-peer-detection { interval 20 threshold 5; }
      -> interval=20 threshold=0

Every statement after the first loses its value, on a clean commit. The
container's brace is PRESENT and nothing is elided — the operator omitted a
semicolon. All three tracked elision populations require an omitted container
brace, so none of them counts this shape.

## Fix

Reuse `splitPackedStatements8768` on the container's own Children, gated on the
same `packedStatements` opt-in, so ONE flag governs both spellings of a packed
run. Before this a container could be adjudicated fixed for the elided form and
stay silently lossy for the braced one.

The split is reachable here because the CONTAINER is the node being visited, so
its Children slice is in hand. In #8880 it was the parent's slice, which the walk
does not hold — that fold had to decline instead.

## What the un-opted control can and cannot see

The opt-in is enforced TWICE: in the new function and again inside
`splitPackedStatements8768`. Measured by mutation: removing EITHER gate alone
leaves the control GREEN; it reds only when BOTH go. So it asserts the property
(an un-opted container is untouched), not either gate, and a green there is not
evidence that a particular gate is present.

## Validation

Two-sided before/after on an opted-in container: `threshold=0` before,
`5` after, with the separated spelling unaffected in both. Mutation removing the
split reds the assertion by message. A no-brick cell holds the tolerant ingress —
which does schema-validate and downgrade, so the property is "no new REJECTION",
not "no new validation".

pkg/config, pkg/configstore, pkg/refactoraudit, pkg/daemon: green.
