# #7041 — dead-leg HTTPS retry re-runs the cert load diagnostic

- **Timestamp**: 2026-08-28
- **Action**: Verified the issue's three premises by reading the code at head,
  then reordered `ReconcileHTTPS`'s default arm to bind before it builds.
- **File(s)**: `pkg/api/listener.go`, `pkg/api/README.md`,
  `pkg/api/tls_deadbind_cert_reload_7041_test.go` (new)

## Premises checked before building to them

The issue names `buildHTTPSServer(addr, slot)` in the default arm; the code has
since been refactored and the arm now calls `planHTTPSLeg(addr)`, which wraps
`buildHTTPSServer`. The substance is unchanged. All three premises hold at head:

1. `ReconcileHTTPS` default arm calls `planHTTPSLeg(addr)` BEFORE
   `s.listen("tcp", addr)` — build precedes bind.
2. `s.certGen = generateSelfSignedCert` has no cache; `generateSelfSignedCertAt`
   calls `tls.LoadX509KeyPair` and then `warnStaleLoadedCert(cert, bindHost)` on
   every successful load.
3. A serving leg short-circuits at `case s.httpsLeg.serving() && ...: return nil`,
   so the repetition happens only while the leg is NOT serving — which is exactly
   the state the #6827 liveness disjunct re-enters on every commit.

## Fix chosen

The issue offered two candidates. Took the first (bind first, build second)
rather than dampening the diagnostic:

- It removes the repeated work rather than hiding its output, so there is no
  dedup key to get wrong and nothing is keyed on warning text.
- It is the same reachability argument as #7039: a leg that cannot bind serves no
  client, so nothing can be verifying against that certificate yet.
- The suppression is bounded in TIME, not permanent — the first commit that binds
  emits the diagnostic.

## Consequences asserted rather than left implicit

- **Listener cleanup.** Binding first means a cert failure happens with a socket
  already held. It is closed on that path; retaining it would hold the port and
  turn a transient cert fault into a permanent `EADDRINUSE` on every retry —
  manufacturing the never-converging state this change exists to stop.
- **Error precedence.** With BOTH the bind and the cert failing, the reported
  error is now the BIND error, not the cert error. Measured, not assumed.

## Tests

`pkg/api/tls_deadbind_cert_reload_7041_test.go`. They drive the REAL production
loader (`SetTLSCertDirForTest` routes through `generateSelfSignedCertAt`) against
a seeded temp dir and count the actual operator-visible warning text, rather than
counting `certGen` calls — a call count is a probe keyed to the implementation
that happens to emit the warning, not to the property an operator experiences.
`seedStaleFor` asserts its own precondition (a load MUST warn) so the counting
cells cannot pass by counting an absence that was never possible.

Because the fix is a suppression, each silence cell is paired:

| cell | asserts |
|---|---|
| `TestFailedHTTPSBindDoesNotReloadTheCertificate_7041` | 3 commits on a failing bind emit the diagnostic 0 times |
| `TestFirstHTTPSBindFailureStillReportsTheBindError_7041` | the bind error is STILL returned on every attempt (passes at master too) |
| `TestHTTPSCertDiagnosticReturnsWhenTheBindRecovers_7041` | silent while down, then EXACTLY once on the commit that binds |
| `TestHTTPSCertFailureAfterBindClosesTheListener_7041` | the held socket is closed exactly once; leg retained |
| `TestBindErrorWinsWhenBothFail_7041` | the precedence change, pinned |

**Red at master:** the defect cell reported 3 occurrences across 3 commits, and
the recovery cell reported 2 while the bind was down. The must-still-report cell
PASSES at master — correct for a pairing that has to hold on both sides.
