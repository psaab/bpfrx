# 9128 / 9129 — the quoted packet's fragmentation fields, both directions

- **Timestamp**: 2026-09-06
- **Action**: carry a quoted packet's fragmentation fields across the embedded
  ICMP translation, in both directions, as one change.
- **File(s)**: `userspace-dp/src/nat64.rs`, `userspace-dp/src/nat64_tests.rs`.

Both issues asked for this as a single change (#9128's fix direction: *"Pair it
with the v4→v6 mirror as ONE change"*), and they are the same defect approached
from opposite ends.

| | before | after |
|---|---|---|
| **#9128** v6→v4 | `out[4..8]` pinned to ID=0, DF=1 | ID from the Fragment Header's low 16 bits, DF cleared, M→MF, offset copied |
| **#9129** v4→v6 | no IPv6 Fragment Header emitted at all | 8-byte Fragment Header chained when the quote is fragmented |

The outer translators in both directions already did this correctly (#2008 H16,
#2488); only the embedded twins did not.

## Scope, which is what makes these Low rather than High

A non-first fragment is refused upstream in BOTH directions —
`ipv6_is_non_first_fragment` (#2290) going v6→v4, and `parse_embedded_v4`
(#1852) going v4→v6. Both filter on **offset only**, so an `MF=1, offset=0`
FIRST fragment passes, and that is the reachable case.

The fix copies the offset anyway, so neither arm is correct only by virtue of a
guard living somewhere else. A narrowness row asserts that: if a non-first quote
ever does reach the v6→v4 arm, its offset must be copied rather than zeroed.

Both issues' loud headline claims were already refuted at filing (#9128's "errors
cannot be correlated to sockets" — the ports are preserved and #6472 even
restores the translated port, which is what socket demux keys on; #9129's
"payload overwrite / memory-corruption" — `parse_embedded_v4` refuses the quote
first). What lands here is the RFC 7915 §5.1/§5.2 conformance gap that survived
both refutations. **This PR claims nothing about corruption.**

## The one non-obvious part: growing the output could have DROPPED the error

`quote_in` in the v4→v6 direction is already clamped to
`MAX_EMBEDDED_LEN - NAT64_HEADER_DELTA`, precisely so `40 + l4_len` lands on
`MAX_EMBEDDED_LEN` at the maximum. An 8-byte Fragment Header pushes a maximal
quote past that, `dst.get_mut(..total)` returns `None`, and the whole ICMP error
is dropped.

**That would be a worse outcome than the defect** — an unfaithful translation
becomes a missing error, and a missing PMTUD error is a black hole. So the quote
is shortened by the 8 bytes instead, which is always legal for an ICMP error
(the file already relies on that for its existing clamp) and keeps the leading
tuple a receiver demuxes on. Its own cell pins this, and the bound is taken from
`dst.len()` rather than the constant so it cannot drift from the caller's buffer.

## Validation

Three cells, each with a reference arm asserting the UNFRAGMENTED case is
byte-identical to the pre-fix behaviour — without it, "the fragmented case now
carries fields" could pass against a translator writing garbage.

Three mutants, each killed by only its own cell:

| mutant | reds |
|---|---|
| v6→v4 back to pinned ID=0/DF | the #9128 cell only |
| v4→v6 never chains the Fragment Header | both #9129 cells only |
| drop the shorten-instead-of-drop clamp | the oversized-quote cell only |

Full `cargo test` green (5379 + the auxiliary suites); `go test ./...` green.
