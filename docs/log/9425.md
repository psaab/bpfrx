# #9425 — `alarm-without-drop` lost on a substituted and on an inherited state

## Are the two members one fix? No.

Checked before writing either, because the issue asks. They share a THEME (a
configured `alarm-without-drop` does not survive into a state the dataplane
substitutes or inherits) and nothing else:

| | Member 1 | Member 2 |
|---|---|---|
| Zone state | INERT — no `ScreenState::zones` entry at all | RESOLVED — a live entry with inherited sub-state |
| Lost because | the flag never reaches the helper for that zone | the flag reaches it, but a latch set BEFORE the commit outranks it |
| Site | Go wire builder + `ScreenState::alarm_without_drop` | `ZoneScreenState::reconcile_substate` |
| Consequence | every substituted malformed-packet check hard-drops, indefinitely | session-miss ACKs hard-drop, bounded to 64 s |

Neither fix touches the other's code path, and each is red under its own
mutation with the other applied. They ship together because the issue is one
cohort, not because one covers both.

## Member 1

An inert zone (profile DEFINED, zero checks enabled) gets no `screens` entry —
`buildScreenSnapshots`' `enforcesAnyCheck` gate skips it — so
`ScreenState::alarm_without_drop`'s `zones` lookup missed and returned false.
Since #7888 that zone DOES produce drop verdicts (`missing_profile_verdict`
substitutes `conservative_default()`), so the lookup missed exactly where a
verdict existed to suppress.

`set security screen ids-option p alarm-without-drop` and nothing else is both
the canonical route into the inert state (`docs/feature-coverage.md:448` records
that it passes STRICT commit with zero warnings) and an explicit request for
audit mode. The operator got the exact inverse.

- The flag now travels on `ScreenMissingProfileRef.AlarmWithoutDrop`, populated
  ONLY for the inert set (the undefined set has no profile that could have
  declared it), decoded into a new `InertProfileRef` struct rather than a second
  parallel map — two structures keyed the same way can disagree silently.
- `ScreenState::alarm_without_drop` falls back to `inert_profile_refs` when the
  resolved lookup misses. That reuses the whole existing consumer path: the
  substituted checks still RUN, still increment `substituted_default_drops`,
  still WARN, and the consumers turn the Drop into a log-only alarm + forward.
- **#7888 is not contested.** It chose drop over PASS for an inert zone; this
  changes drop vs ALARM, for a zone that explicitly asked.

### Protocol version 10 -> 11

The #8892 gate demanded it and the gate is right. "Purely additive needs no
bump" is a TRUE rule that would have licensed this exact regression: the
acceptance gate is exact equality, so an unbumped field is silently IGNORED by
an old helper rather than refused — and an old helper decoding `false` keeps
hard-dropping, which IS the defect. Both planes moved together
(`ProtocolVersion`, `CONFIG_SNAPSHOT_PROTOCOL_VERSION`), and the three
version-TRACKING constants in the test tree moved with them.

## Member 2

`syn_cookie_active_until_secs` was inherited untouched by `reconcile_substate`
(#4969 preserves per-zone state across commits; #2446 invalidates only the
cookie GENERATION). `validate_syn_cookie_ack_on_session_miss` checks
`syn_cookie`, the threshold, the protocol and `locally_active` — never
`alarm_without_drop`. So a zone latched cookie-active under a live flood kept
dropping parse-valid session-miss ACKs as `Invalid` for up to 64 s after the
operator committed `alarm-without-drop` *to stop the drops*.

The defect is in the COMPOSITION of two individually deliberate mechanisms. The
freshly-configured-audit case was already guarded (`syn_flood_gate` does not set
the latch under audit; pinned by
`syn_cookie_alarm_without_drop_forwards_session_miss_ack_l10`) and is untouched
— that guard cannot reach the transition, because the latch was set before it.
`reconcile_substate` now clears the latch when the NEW profile is in audit mode,
which is idempotent with that guard: audit mode never sets the latch, so under
audit the only value it can hold is one inherited from a pre-audit epoch.

  — **REACHABILITY.** `alarm_without_drop` returning true is half a claim; a

  cannot tell. This drives the real consumers on BOTH the flow and flowless
  paths and asserts FORWARD + one alarm counted, each leg carrying its own
  no-modifier baseline in the same run — because "audit forwarded it" and "the
  substitution produced no verdict at all" otherwise read the same, and the
  second is the #7888 fail-open this must not reintroduce.

  satisfy a struct-level assertion while emitting nothing. Carries the

- `TestUndefinedProfileRefCarriesNoAuditFlag_9425` (Go) — the builder-side half
  of the shared-struct control, on the tolerant compile path (the undefined

Member 2:

- `enforce_to_audit_transition_clears_the_cookie_latch_9425` — with a POSITIVE
  CONTROL before the commit (a bogus ACK must be `Invalid`), so the assertion
