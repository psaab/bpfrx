# 9060 — the legacy gRPC session walk could not be aborted

- **Timestamp**: 2026-09-06
- **Action**: add cancellation to the legacy `GetSessions` walk, and refuse to
  return a cancelled walk's partial result as success.
- **File(s)**: `pkg/grpcapi/session_walk_cancel_9060.go` (new),
  `pkg/grpcapi/server_sessions.go`,
  `pkg/grpcapi/session_walk_cancel_9060_test.go` (new).

## Which of the three missing guards actually matters

The REST walk has three; the legacy gRPC walk had none. They are not equal, and
the issue's own analysis separates them:

- **Offset ceiling — inert here.** `Total` counts every matching row, so the
  v4+v6 walk runs to EOF on every legacy call regardless of offset. A cap would
  change nothing.
- **Count cap — cannot be fixed here alone.** Surfacing a `capped` flag needs a
  field that does not exist in `proto/xpf/v1`, and silently truncating without
  telling the client is worse than not truncating. Left for that proto addition.
- **Cancellation — the live defect**, and what lands here.

## Why cancellation is the one

The walk holds one of `MaxConcurrentSessionWalks = 4` slots and **that limiter is
shared with REST**. Four abandoned legacy calls block every REST *and* gRPC
session scan until each finishes on its own — a poller that times out keeps
paying, on a surface it did not call.

Both shipped clients take this path: `cmd/cli/show_flow.go` sends `Limit:100`
with no `PageSize`, `pkg/cli/session_filter.go` sends `Limit:10000`, and only
`PageSize > 0` reaches the bounded cursor walk. This is ordinary
`show security flow session`, not an exotic call.

The contention is real — the map is the shared conntrack hash the Rust helper
writes on session **install** — but the report's per-packet claim is refuted and
is not made here.

## A partial result is not a success

A cancelled walk yields a truncated list **and** a `Total` that understates the
table, so a client reading it as an answer concludes sessions disappeared. The
same reasoning as the iterator-error arms beside it (#2469). It returns the
context error rather than `Internal`, so a caller can tell *"you went away"* from
*"the walk broke"*.

## A survivor that is correct

Deleting the sampler's `if cancelled { return true }` early return **survives**,
and that is right: latching comes from the captured flag never being reset —
`ctx.Err()` cannot go back to nil — so the early return is a fast path guarding
nothing. Both the code and the cell now say so, because the alternative was
shipping a comment that claims a line does something it does not.

## Validation

| mutant | result |
|---|---|
| v4 callback stops checking | killed |
| return the partial result as success | killed |
| probe every entry instead of sampling | killed |
| drop the early-return fast path | **survives, correctly** — documented |

The third matters: a change that made the check exact would *look* like an
improvement, and the reason it samples is that a `ctx.Err()` read per entry adds
lock traffic across a multi-million-entry table. The interval matches REST's
deliberately — two walks sharing one limiter should abandon a dead client on the
same timescale.
