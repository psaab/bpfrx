# #9111 — the #3204 L2 group/broadcast refusal reached one of three reply builders

- **Timestamp**: 2026-09-06
  - **Action**: moved #3204's L2 group/broadcast refusal from
    `build_reject_rst_frame` into `parse_tcp_reply_source`, the single function
    all three TCP reply builders call first, so the SYN-cookie SYN-ACK and
    ACK-RST legs are covered too.

    `write_reply_eth_header` copies the inbound L2 DESTINATION into the reply's
    own L2 SOURCE (`out[6..12] = frame[0..6]`), so a reply built for a
    group-addressed frame egresses with a group/broadcast SOURCE MAC — switches
    learn it against this port, or MAC-flap and err-disable it. #3204 named this
    hazard in a 12-line comment and guarded ONE builder. The two SYN-cookie legs
    were left reachable, and they are armed exactly when the zone is over
    `attack-threshold` — i.e. during the DDoS the feature exists for.

    **The guard went to the choke point rather than being copied twice.** A
    whole-tree census found `parse_tcp_reply_source` has exactly THREE non-test
    callers, and all three are the reply builders — so it is the natural single
    site, and a fourth reply builder inherits the refusal instead of having to
    remember it. That is the property the per-site version lacked and the reason
    this defect existed. The old per-site check is replaced by a pointer note so
    the #3204 history stays attached to the leg it was written for.

    Verified the move is not a regression as well as a fix: mutating the guard
    away reds the two PRE-EXISTING #3204 cells alongside the three new ones, so
    the original leg is still covered through the new location.

    Two mutants, complementary, each verified to BUILD before scoring and each
    restore verified by reading the file back. Removing the guard reds five
    cells (2 x #3204 + 3 x #9111) and leaves both unicast controls GREEN;
    forcing the guard to fire on every frame reds the two unicast CONTROLS and
    nothing else. The second matters because the defect is reachable only
    through the SYN-cookie challenge — a guard that refused everything would
    "fix" the finding by disabling the feature, and only the control row
    distinguishes the two.

    HA wire: nothing moves. No session key, no wire struct — this decides
    whether a synthesized reply frame is emitted at all.
