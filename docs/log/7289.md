  - **Premise checks first, because the issue's own body hedges four
    reachability claims and two of the spec's items rest on stale facts.**
    Verified at `origin/master` `9baa81bf5`, by property:
    - `preflightCheckIfindexCaps` **cannot** be hoisted — TRUE. `pendingXDP` has
      exactly ONE production writer, `compiler_iface.go:501` inside

    - `CompileConfig`'s later phases — they return `nil, err` for the RESULT on
      every phase error, so an abort there has no `pendingXDP` to prove coverage
      against. That is why R1 is scoped to the aborts that hold a result, and it
      is consistent with the body calling those phases "effectively unreachable
      post-#6894".
    - The hazard is worse than the issue states. The issue says an abort leaves
      the gate classifying `armCoverageUnknown`. That is true only on a box's
      FIRST apply. On any later one the cell still holds the previous
      generation's report (`Ran=true, Uncovered=0`), so the gate classifies
      **Complete** and logs "arm coverage complete" for an apply that just
      failed to attach anything — an affirmative claim of coverage sourced from
      a different apply.
  - **Decision note — why the real proof and not a synthetic verdict.**
    Publishing a hand-built "everything uncovered" report on abort is the
    obvious implementation and it is wrong: a re-attach can fail while the
    PREVIOUS shim is still attached and still adjudicating that interface, so
    that implementation disarms a box whose forwarding was never unadjudicated —
    a brick, not a fence (#1960). `ProveArmCoverage` reads LIVE kernel and bpf
    state and answers both directions correctly. It is also the only publisher:
    `publishArmCoverage` is deliberately reachable only from inside the proof so
    a stashed report cannot be published, and that guard is left intact.
  - **Decision note — no undo log, deliberately.** The issue's title implies
    one. An undo for live host state is itself fallible, and one that fails
    mid-rollback leaves a third state worse than the two it was reconciling. The
    issue's own r1 also established that converge-forward cannot terminate for
    this class: the reachable trigger is a driver refusing an XDP attach, which
    is PERSISTENT, and #5679's self-heal is scoped to TRANSIENT errors in its
    own sentence. So the answer for the reachable class is to close the surface,
    not to retry it and not to undo it.
  - **Test note**: three cells, mutation-checked. Deleting the publish reds the
    republish cell AND the control; unwiring the attach abort in `loader.go`
    reds the AST wiring guard; and the synthetic-report implementation — which
    PASSES the republish cell — reds the control. The wiring guard exempts
    exactly one abort (CompileConfig's own nil-result check) and asserts that
    shape rather than skipping an index on faith.
