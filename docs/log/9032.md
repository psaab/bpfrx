# #9032 — native-GRE local-origin sessions were published with routing_domain 0

- **Timestamp**: 2026-09-06
  - **Action**: stamped `routing_domain` on the local-origin GRE session key in
    `build_local_origin_tunnel_tx_request`, from the tunnel's own logical
    ifindex via the shared `forwarding::ingress_routing_domain`.

    #7160 made `routing_domain` part of session identity and stamped it at what
    its own comment calls "THE single site that populates
    `SessionKey.routing_domain` for a received frame", inside the AF_XDP
    descriptor loop. This producer reads packets off the TUN and never reaches
    that site, so `parse_session_flow_from_bytes` left the domain at 0 and the
    session was PUBLISHED under domain 0 — a different identity from the one the
    same flow receives when it arrives on a wire.

    The domain was already available and already in use one line below: the
    function resolves the tunnel's logical ifindex into
    `decision.resolution.egress_ifindex` and passes it to
    `forwarding.egress_zone_id(...)`. A locally-originated packet has no ingress
    interface, so the tunnel's egress interface IS the interface whose routing
    instance the flow belongs to. The shared `ingress_routing_domain` helper is
    reused rather than re-spelling the map probe, so this cannot drift from the
    wire path.

    **HA WIRE: this one DOES change a published value, and that is the point.**
    Unlike #9030 and #9034, `flow.forward_key` here becomes
    `SyncedSessionEntry.key` and goes onto the session-sync wire. No field is
    added or redefined — the wire FORMAT is unchanged — but the VALUE for this
    producer moves from 0 to the real domain, which is precisely the correction:
    every other producer already emits the real domain, and this one disagreed
    with them. Rolling-upgrade exposure is bounded and self-correcting: during a
    mixed-version window an old node publishes such a session under 0 while a
    new node keys it under N, so a synced local-origin GRE session can miss
    until both nodes are upgraded. It affects ONLY native-GRE local-origin
    sessions on boxes that actually use routing instances —
    `ingress_routing_domain` short-circuits to 0 on `!has_routing_domains`, so a
    deployment without routing instances is bit-identical to before, which the
    control cell pins.

    Two mutants, complementary rather than redundant, each verified to BUILD
    before scoring and each restore verified by reading the file back: removing
    the stamp reds the domain cell and leaves the control GREEN; hardcoding the
    stamp to 7 reds the CONTROL and leaves the domain cell green. A single
    mutant could not have distinguished "stamps the right value" from "stamps
    some value", which is what the pair is for.
