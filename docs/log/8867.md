# #8867 — the packed spelling of a typed leaf skipped SchemaValidate entirely

- **Timestamp**: 2026-09-05
  - **Action**: normalize compact stanzas on a CLONE before the typed-leaf walk,
    so a value authored in the packed spelling is validated. The walker descends
    `.Children`, so a statement packed onto a container line sat below every
    modelled depth and no validator fired — while the compiler normalizes the
    same pairs and therefore COMPILED the value. Every typed-leaf contract was
    optional at the operator's choice of spelling.
  - **Measured**: of 161 validator-bearing typed leaves reachable at an admitted
    pair, 146 were rejected braced and ACCEPTED packed; 15 were validated on
    both. The 15 are the control that makes this a claim about the packed path
    rather than about validation in general.
  - **Precedent**: this is #6672 generalised. That change already un-packs
    `chassis cluster` immediately before the same walk, for the same reason —
    "one splitter, both consumers". The class was recognised for one container
    and never applied to the rest.
  - **Load path**: cannot blackout a boot. #1319 PR 2 already downgrades a
    typed-leaf violation to a warning on the tolerant Store.Load / SyncApply
    ingress; only the operator-driven commit path is strict.
