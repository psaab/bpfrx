## Design for the remaining upgrade-path conversion

Frame mapping, preserving #6628's 4-frame choreography and its switch-point
discipline:

1. `I -> R` Noise msg1 (`e, psk`) in the existing Hello frame.
2. `R -> I` Noise msg2 (`e, ee`) in the existing Proof frame. R now holds both
   CipherStates but has authenticated NOTHING — msg1 carries no payload and so
   no tag — and must switch nothing, exactly as today.
3. `I -> R` a confirm frame carrying `HMAC(i2r, "upgrade-confirm" || h)` where
   `h` is the handshake hash. Reading msg2 DID authenticate R (its tag verifies
   under the PSK-mixed key), so I may switch its write direction after this
   write, as today. The MAC is what proves I's possession to R.
4. `R -> I` Ack. R recomputes the frame-3 MAC against its candidate readKey and
   installs it only on success; then writes Ack and installs writeKey. I
   installs readKey on the Ack.

Role for the mid-stream case should come from NODE ID (lower id initiates), not
from the nonce comparison `upgradeIAmResponder` uses today: a nonce is
peer-supplied, and role must not be an attacker-chosen input to our own key
derivation. Both nodes know both ids.

Out-of-order risk to state and test in the PR: with `Split()` there are two keys
rather than one shared derived key, so there are two install points per
direction instead of one. The invariant to preserve is unchanged — each side
installs at the boundary the peer installed at — but it now has to hold for two
independent values.
