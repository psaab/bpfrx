# #9023 — duplicate named blocks silently discarded the earlier one

- **Timestamp**: 2026-09-05
  - **Action**: merged repeated named blocks into the first occurrence for
    `snmp trap-group` and `forwarding-options sampling instance`, on BOTH
    compile paths, with a warning. Junos merges repeated stanzas; the compiler's
    `m[name] = x` made the last block win.
  - **Measured before**: `trap-group` lost its `targets` (1 → 0);
    `sampling instance` lost its `input rate` (100 → 0). Both compared against
    the same configuration written as ONE block, which is the property asserted.
  - **Both paths, unlike #8752** — that fold is tolerant-only because the #3473
    gate rejects a duplicate policy name and merging first would destroy a
    diagnostic worth keeping. **There is no such gate here**: `sampling
    instance` accepts a duplicate silently on the strict path, so tolerant-only
    scoping would have left the operator-typed case losing data.
  - **Two corrections to the filing**, both measured:
    1. The issue's title says the loss is silent **on the strict path**. For
       `snmp trap-group` the strict path REJECTS — but for an unrelated reason:
       the zero-target gate (#2990) runs per BLOCK, so the `version v1` block
       trips it alone. The operator who wrote `targets 10.0.0.1` was told
       **"no targets configured"** — true about a block they did not intend to
       exist, and describing a symptom of the duplication rather than the
       duplication. Merging first makes that gate see the group the operator
       described, and it stops firing.
    2. Only `sampling instance` is silent on both paths.
  - **Validation**: unwiring the merge reds the conservation cell on both rows
    and the warning cell on both. The strict-acceptance cell reds only for
    `trap-group` — `sampling` was always accepted, so that subtest documents a
    pre-existing fact rather than binding the change, and says so. A
    non-vacuity cell proves an unlisted container (`security-zone`) is
    untouched, so the merge cannot be passing by rewriting everything.
