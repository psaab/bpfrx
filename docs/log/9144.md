# #9144 — MonitorInterface pinned the config snapshot taken at stream open

## Summary

`MonitorInterface` took `cfg := s.store.ActiveConfig()` once at stream open and
its 1s tick loop used that snapshot for the life of the stream. The interface
SET and the COUNTERS were never stale — `TrafficSummaryInterfaces` walks netlink
fresh every tick and reads counters by live kernel name. What was stale is the
config-derived DISPLAY NAME, so a commit that re-points an alias left LIVE
counters rendered under a name the config no longer assigns.

## Measurements

- **Timestamp**: 2026-09-06
- **Action**: reproduce, at `origin/master` 8fef2034f, driving the real
  `configstore` through a real commit:
  ```
  BEFORE commit:                       kernel lo is displayed as "reth0"
  AFTER commit, PINNED snapshot:       kernel lo is displayed as "reth0"   <-- stale label
  AFTER commit, RE-READ:               kernel lo is displayed as "reth9"
  ```
  The fixture aliases `lo` (live on every host) as a RETH member so the
  config-derived label is genuinely in play.

- **Action**: verify the issue's narrowing rather than accepting it.
  `monitoriface.TrafficSummaryInterfaces` calls `ListTrafficInterfaces()` FIRST
  (a fresh `netlink.LinkList()` per tick), builds from the LIVE kernel set, and
  consults cfg only in `applyConfiguredSummaryChoices` to pick a display name;
  `finalizeTrafficSummaryInterfaces` falls back to the kernel name. So the set is
  live, the counters are live, and the defect is a MISLABEL — confirmed by
  reading the code, not inherited from the issue.

- **Action**: check whether #9051's remedy transplants. **It does not**, and the
  reason is structural rather than a preference:

  | | #9051 (authorization) | #9144 (config snapshot) |
  |---|---|---|
  | property re-checked | UNIFORM — `(peer identity, method)`, both held by the interceptor | handler-SPECIFIC — a kernel-name resolver, a RETH predicate, an RG lookup, a display-name mapping, all derived inside the handler body |
  | enforcement action | uniform: cancel the stream | none is uniform — cancelling an operator's `monitor interface` on someone else's commit is plainly wrong |

  An interceptor cannot re-derive closures that live inside a handler. So the fix
  belongs in the handler, and #9051's "putting it in the loops silently omits the
  next stream" concern is answered by SCOPE instead.

- **Action**: scope census. Five server-streaming RPCs exist. `Ping` /
  `Traceroute` are self-terminating. `proxyMonitorInterface` forwards.
  `MonitorPacketDrop` DOES read the active config at open — but only to VALIDATE
  the request's zone/interface filters and resolve `reqIfaceAliases`; pinning the
  interpretation of what the operator ASKED FOR is correct there, and it renders
  no config-derived label. **`MonitorInterface` is the only stream that renders
  live data under a config-derived label pinned at open.**

## Deliberately NOT refreshed

The issue warns the fix can half-land. Both open-time uses were decided, not
skipped:

- **`singleKernelName`** (single-interface mode) stays resolved at open. The rate
  columns are deltas against `baselineSingle` / `prevSingle`, which are counters
  of a SPECIFIC kernel device. Re-resolving mid-stream would silently swap the
  device under those baselines and render garbage rates — replacing a wrong label
  with wrong numbers, which is strictly worse.
- **`isRethName` / `rethRG`** feed the serve-local vs proxy-to-peer dispatch,
  settled once before the loop. The stream has no mechanism to start proxying
  mid-flight, so re-evaluating them would change a value nothing reads.

**M2 is the one that mattered.** Every other cell calls
`monitorSummaryInterfaces` directly, so all of them stay green when the tick loop
stops calling it — the helper would be correct and unreached, a whole
contribution cut with the suite green. Only the cell that drives the real handler
across a real mid-stream commit can see the call site.

**M5 is the anti-vacuity check.** The summary path consults the config only for
interfaces resolving to a LIVE kernel device, so a fixture whose names have no
live counterpart would exercise nothing and pass identically with and without the
fix. Breaking the alias's priority reds every cell, which is the evidence that
the fixture is load-bearing rather than decorative.
