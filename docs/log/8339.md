# 8339 — a dangling application leaf permitted every port

- **Timestamp**: 2026-09-02
  - **Action**: A recognized value-taking leaf left with no value on an
    application's DIRECT body committed on the STRICT path and then
    matched every port. `applicationDirectLeaves` synthesises a 1-key
    childless node, `nodeVal` returns `""`, `resolveAppPort` passes it
    through, and `portInSpec("")` returns true for EVERY port. So
    `protocol tcp destination-port` — one token short, an ordinary typo
    — turned a single-port application into an all-TCP permit, with the
    config rendering exactly as typed.
    The guard existed for inline `term` bodies since #6564 and had no
    direct twin.
    **Extended rather than duplicated, but only where the two genuinely
    share.** The DETECTION cannot be shared: the term path consumes
    `keys[i+1]` from a flat key run, so dangling is `i+1 >= len(keys)`;
    the direct body reads the node's own value, so dangling is
    `nodeVal(prop) == ""`. The CONTRACT can and must be: which keywords
    require a value is a property of the Junos statement, not of the
    shape it was typed in. `valueTakingTermLeaves` became
    `valueTakingApplicationLeaves`, one set governing both switches,
    with a coverage gate per switch. Two sets would have drifted exactly
    as the two guards did.
    **The exclusions are derived, not assumed**: `description` takes a
    value but a dangling one drops a cosmetic field and widens nothing,
    so refusing it would add commit failures with no security benefit;
    `term` is a container whose name is consumed by descending. Both are
    pinned by the over-correction control.
    A branch that DISCARDS the parent app struct (#6524, term-bearing
    bodies) required the verdict to be carried onto each generated term,
    or it escapes the gate entirely while every other test passes.
    Golden `4406` gained three `"IncompleteDirectLeaves": null` lines and
    nothing else — checked by diffing rather than regenerating blind,
    which also confirms no fixture config trips the new guard.
    Four mutations. M4 (adding `description` to the contract) initially
    read as ESCAPED; the `sed` had not matched, so that run was a VOID
    rather than a pass. Re-run with the mutation verified as applied, it
    reds the over-correction control.
