- **Timestamp**: 2026-09-03
  - **Action**: The smoke's FIRST version was a void I built myself, and
    it is the most instructive part of this work. I instrumented the
    actuation with `slog.Debug` and counted that line in the journal —
    but the daemon logs at INFO, so the line can never appear. Its "0
    republishes" was structurally indistinguishable from a dead
    listener, and would have read as a clean fail on a possibly-correct
    change. Caught by refusing to read a suspicious zero as a result and
    checking whether the instrument could see anything at all: zero
    DEBUG lines in the journal, full stop.
    Fixed with an observable rather than a louder log. The
    `xpf_route_listener_{marks,republishes}_total` PAIR answers "is the
    listener alive, and is it bounded?" — a question nobody could ask
    before, and whose absence is plausibly why #7409's window went
    unnoticed long enough to need this issue. The rewritten smoke
    asserts the metrics EXIST before reading them, so a missing metric
    reports as a void rather than as a zero.
    Cluster smoke, numbers stated before the run (marks >= 40,
    republishes 1..6): **80 route events -> 3 republishes**, control
    socket serving at ~0.12s throughout, daemon healthy.
