# #9114 — the screens were keyed on the shim's fragment sentinel, not the packet's protocol

- **Timestamp**: 2026-09-06
  - **Action**: `extract_screen_info` now recovers a non-first fragment's real
    protocol instead of passing the shim's `PROTO_FRAGMENT_NO_L4` (255) sentinel
    through to the screens — from the IPv4 header's protocol byte, and from the
    IPv6 FRAGMENT HEADER's own NextHdr field.

    `userspace-xdp` substitutes the sentinel before `parse_l4` because a
    non-first fragment has no L4 header to read. That value rode `meta.protocol`
    through `stage_screen_check` into the screens unchanged, so every
    protocol-keyed screen was evaluated against a protocol that was not the
    packet's.

    **MISS, NOT OVER-MATCH — established by censusing the consumers before
    changing anything, because those are different defects with different
    fixes.** Eight protocol-keyed sites exist. Three test for the real protocol
    and therefore never fired: `check_icmp_fragment` (`stateless.rs:232`),
    `icmp-flood` (`zone.rs:297`) and `udp-flood` (`zone.rs:305`). The rest test
    `== PROTO_TCP` (`stateless.rs:46`, `mod.rs:846`, `:1127`, `extract.rs:425`)
    or `!= PROTO_TCP` (`mod.rs:1263`), and every one of those DECLINES on the
    sentinel — which is correct for a fragment carrying no L4 header, and
    `check_tcp_flag_screens` carries its own explicit non-first-fragment guard
    immediately below its protocol test. So nothing over-matched; three screens
    silently did not run.

    The IPv6 half needed a different source from the IPv4 half: the ext-header
    walk `break`s out on a non-first fragment BEFORE it would assign `nexthdr`,
    so at that point `nexthdr` is still 44 (Fragment). The real protocol is the
    fragment header's own NextHdr byte, which is present on every fragment —
    that is the field's purpose — and is in bounds because the fragment offset
    at `offset + 2`/`+3` was just read.

    Both recoveries are GATED on the sentinel, so an ordinary packet's protocol
    is passed through untouched and a caller that legitimately knows better (a
    decapsulated inner packet) is not overridden.

    **The pre-existing fragment fixtures could not have caught this**: they pass
    the REAL protocol as the caller argument, a packet shape the shim never
    emits for a non-first fragment. The new cells pass the sentinel, as the shim
    does.

    Three mutants, an orthogonal matrix — each kills exactly one cell and no
    other, each verified to BUILD before scoring, each restore verified by
    reading the file back: removing the v4 recovery reds only the v4 cell;
    removing the v6 recovery reds only the v6 cell; making the recovery
    UNGATED reds only the pass-through control.

    HA wire: nothing moves. No session key and no wire struct — this corrects an
    input to the screen evaluators.
