# 9040 — RSS reshaping was gated on a driver NAME, not on a capability

- **Timestamp**: 2026-09-06
- **Action**: replace the `driver == mlx5_core` gate with an `ethtool -x`
  capability probe; make restores fail open and writes fail closed.
- **File(s)**: `pkg/daemon/rss_indirection.go`,
  `pkg/daemon/rss_indirection_test.go`,
  `pkg/daemon/rss_capability_probe_9040_test.go` (new),
  `docs/afxdp-packet-processing.md`.

## What the remaining half of the issue actually was

The unconditional half landed in #9262 (the cap names itself at bring-up, the
drops are exported). What was left was recorded on the issue as **a product
decision**: widen the reshape to every driver, or refuse the plan outright.

**I took neither arm, because the issue's own "what would settle it" option 1
dissolves the decision instead of making it.** A per-interface capability probe
turns "which global policy" into a per-interface answer, and the answer is
derived rather than chosen.

The clamp was never the gap. `computeWeightVector` is already driver-generic —
it clamps `active` to `min(queues, BindingQueuesPerIface)` for anything it is
called on. The gap was one level up, in `applyRSSIndirection`, which matched the
driver name and skipped everything else, so a non-mlx5 NIC never reached the
generic clamp and transit on its unbound queues was dropped.

## Why a probe and not just a wider gate

`ethtool -X` support varies by driver — i40e/ice/bnxt accept the table write,
virtio-net may not — and this path deliberately swallows its errors:

> Never returns a non-nil error — D3 regressions must not break interface
> bring-up.

So dropping the gate would have produced a reshape that **silently succeeds on
some drivers and silently fails on others** — the same class of defect this
issue is about, re-created one layer up. Reading the table first identifies the
unsupported case *before* the write, which is what makes the swallowed-error
path stop mattering.

It costs nothing on the path it replaces: `applyRSSIndirectionOne` already read
this table for its idempotency check, so a supported interface issues exactly
the same ethtool invocations as before.

## Two things the existing cells caught, and both were right

**A double probe.** My first version read the table up front and
`maybeRestoreDefault` read it again — two ioctls for one question, on a path
whose purpose is to avoid unnecessary NIC churn. A call-count cell caught it;
the bytes are threaded through instead.

**Probing too early.** Several cells assert that a NIC needing no work issues
*zero* ethtool calls. They are right to: this runs on every daemon start and
every reconcile. The probe is now lazy and memoized — after the free sysfs
checks, before every write.

## The asymmetry, which is the substance

**A restore fails open; a write fails closed.**

#5250 exists because an unreadable signal silently became "do nothing" and left
a concentrated table live. Probe-gating a restore would re-create that defect
one level up, so neither the #5250 unknown-queue-count restore nor the kill
switch is probe-gated. A wrongly attempted restore is a logged no-op; a wrongly
attempted reshape is a silent misconfiguration.

For the same reason the kill switch now sweeps **every allowlisted interface**:
**the restore set must equal the potential-apply set.** Leaving the driver gate
on the restore while widening the apply path would strand a concentrated table
on exactly the non-mlx5 NICs the new apply path can write — reachable only by an
operator trying to back out, which is the worst time to find a defect.

## Re-anchored cells, not deleted ones

Five cells pinned the driver-name contract. Their goal — never touch a NIC xpf
does not own — is carried by the **allowlist**, which is the userspace-dp AF_XDP
binding set; the driver name was a second guard that also blocked the legitimate
case. They now assert the narrower true contract: no `ethtool -X` **write**
against an interface whose table could not be read.

Two of them (`NonMlxDriver_WorkersEqualsQueues_NotTouched`,
`EmptyDriver_...`) scripted a **stale concentrated table** and asserted it was
left alone. **That expectation was itself the defect**: #805/#5124 restore a
stale table whenever workers >= queues, and those NICs were exempted from the
repair for no reason but their driver name.

## Validation

| mutant | result |
|---|---|
| restore the driver gate (the original defect) | killed by 5 cells |
| accept an unparseable table as supported | killed |
| probe-gate the #5250 restore (a restore failing closed) | killed |
| probe-gate the kill-switch restore (restore set != apply set) | killed |

Each verified to **build** before scoring; each restore verified by reading the
file back. The new cells carry reference arms: the probe must actually have been
issued, or the assertion "no write happened" is satisfied by the old
skip-on-driver behaviour wearing the new contract's clothes.
