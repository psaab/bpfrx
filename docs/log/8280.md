# #8280 — give the cluster smoke pool-mode NAT coverage

- **Timestamp**: 2026-09-02
  - **Action**: added a pool-mode source-NAT rule to the shared cluster config
    and three assertions to `test-failover.sh`, so the smoke executes the NAT
    port allocator at all. Before this, every `source-nat` rule on the cluster
    was `interface;` mode, which is ADDRESS-ONLY and returns before any port
    allocation — measured on #7174 M13: a NAT-allocator change passed the full
    smoke 17/17 while the smoke never executed a line of it.
  - **File(s)**: docs/ha-cluster-userspace.conf, test/incus/test-failover.sh,
    pkg/configstore/ha_cluster_conf_8280_test.go
  - **Non-interference, proven not asserted**: `POOL_NAT_SMOKE=0` disables the
    phase, and the run returns **exactly 17 passed, 0 failed** — the same count
    as before the pool rule existed. Full run: **20 passed, 0 failed**. 37 PASS
    artifacts collected across the two runs, 0 void tells.
  - **What the new assertions ENTER**, because a cell that passes without
    entering the state buys nothing: fw0's `allocate_translation ->
    AddressOccupancy::claim` (the assertion is on the TRANSLATED address, which
    only the allocator can hand out — "a session exists" would have passed on
    interface mode); fw1's `handle_upsert_synced -> reserve_flow ->
    occupancy.reserve() -> claim_offset`; and, after a full primary ->
    secondary -> primary cycle, a FRESH claim walking the recycle FIFO in the
    post-churn state, with sessions CLEARED first so a survivor cannot satisfy
    it vacuously.
  - **Two bugs found on the way, both filed rather than absorbed.**
    - #8296: the first version of the `proxy-arp` stanza sat under `security`
      instead of `security { nat }`. It COMMITTED CLEAN, rendered back verbatim
      through `show configuration`, and was inert — no NTF_PROXY entry, pool
      return traffic blackholed, no error anywhere. With a control, `CheckText`
      also accepts `flooby { wibble 42; }` under `security`.
    - #8297: both cluster nodes install the NTF_PROXY entry for a NAT pool
      address regardless of RG ownership, so the upstream sees one IP at two
      RETH virtual MACs and pool-mode TCP never completes a handshake. The
      discriminating control: same host, same second, `.230` (interface mode)
      reaches 5.95 Gbit/s while `.240` (pool mode) times out; ICMP through the
      same pool works 3/3, which clears translation, routing and the reverse
      path.
  - **Test note**: my own first guard was a `strings.Contains(text, "proxy-arp
    {")` check — it passed on the misplaced, inert config. Rewritten to assert
    the PARSED `cfg.Security.NAT.ProxyARP`, and mutation-proved: moving the
    stanza back out reds the new version and passed the old one.
  - **Owed**: the traffic-survival assertion across the role change, once #8297
    lands. Asserting it now would fail for a reason unrelated to the allocator.
