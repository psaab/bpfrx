# 9064 — eleven documented console commands were refused to a restricted class

- **Timestamp**: 2026-09-06
- **Action**: declare the operational-tree leaves that take real arguments.
- **File(s)**: `pkg/cmdtree/tree.go`,
  `pkg/cmdtree/documented_commands_canonicalize_9064_test.go` (new).

`pkg/cmdtree/tree.go` is the declared SSOT for the operational tree, and the
console RBAC canonicalizer **fails closed** on anything it cannot resolve.
Leaves taking real arguments were declared as bare leaves, so a restricted login
class was refused commands the CLI's own `usage:` strings document — 11 of 21.

Declared: `ping count|source|size`, `traceroute source`, `show system rollback`
and its `compare` child, `clear dhcp client-identifier`, both NAT `rule-set`
leaves, and the `groups` / `apply-groups` config stanzas, which were **absent
from the stanza map entirely**.

This is #8304's family — that change added the `AcceptsArgs` opt-in and applied
it to two members, and its own test file says *"the class is wider than both"*.
Which is how the remaining nine survived, and why the new cell is a
**completeness gate over the documented commands** rather than a regression cell
for seven declarations.

## Two false claims not carried

The originating report said `ping X routing-instance vrf1` and the traceroute
twin were broken. **They resolve** — the `DynamicFn` admits the trailing word.
Both are now asserted as controls, so a future "fix" cannot add a redundant
`AcceptsArgs` that would mask a real regression in the dynamic path.

## Two narrowness rows of mine that were wrong, and how I found out

I first asserted that `ping 1.1.1.1 nonsense 5` and
`show system rollback nonsense extra words here` must be REFUSED. Measured on
master before the change:

```
ping 1.1.1.1 nonsense 5                -> OK   (already, not this change)
show configuration firewall anything   -> OK   (the shipped #8304 semantics)
```

`AcceptsArgs` means precisely that trailing words are **arguments the
canonicalizer does not validate** — validation is the dispatcher's job. The
first assertion was never true; the second would have required un-declaring the
leaves this issue is about. **Both were asserting a contract the tree does not
have.**

I also listed bare `ping` / `traceroute` as things that must not resolve. A bare
command node is a valid tree path; whether it is *usable* with no arguments is
again the dispatcher's question.

What the narrowness rows assert now is the thing that actually is the gate: an
unknown command **word** is still refused, and a declared leaf has not widened
its **parent**.
