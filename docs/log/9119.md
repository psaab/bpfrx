# 9119 — the exclusive lock could not be re-asserted, and wiped its own work

- **Timestamp**: 2026-09-06
- **Action**: give `EnterConfigureExclusive` the self-reentry arm its shared-mode
  sibling has had since #4476.
- **File(s)**: `pkg/configstore/store_lock.go`,
  `pkg/configstore/exclusive_reentry_9119_test.go` (new).

## Measured asymmetry

```
fresh lease, same holder   -> ErrConfigLocked, staged edits kept
stale lease, same holder   -> nil, and IsDirty() flips true -> FALSE
shared-mode control        -> nil, staged edits kept
```

The second row is the damaging one. `reclaimStaleLockLocked` discards the
candidate for *any* entrant past the idle lease — #4476's explicit design — and
here the entrant is the holder itself. So an automation client that re-asserted
its own exclusive lock after a stall silently destroyed its own staged
candidate.

## Two placement decisions, both load-bearing

**Before `reclaimStaleLockLocked`, not after.** Placed after, the reclaim wipes
before the self-check can spare it, and the stale-lease row above is unchanged.
The ordering *is* the fix for that row; a mutant that only moves the arm is
killed by its cell.

**Matches on `exclusiveHolder`, NOT `effectiveHolderLocked()`.** The issue's
prose asks for the effective holder; its own suggested patch uses
`exclusiveHolder`, and the patch is right. With the effective holder, a
SHARED-mode holder calling `EnterConfigureExclusive` gets `nil` back while the
lock stays shared — the caller believes it upgraded to exclusive and did not. A
silent failure to acquire the *stronger* lock is worse than a refusal, so that
call still falls through and is refused, exactly as before this change.

## A vacuous assertion the mutation caught

`holder != ""` looked guarded by a row asserting an empty holder is refused. It
was not: that row ran against an **exclusive** lock, where `"" != "admin-session"`
refuses on the string compare alone and the guard is never consulted. **Dropping
the guard killed zero cells.**

The guard only bites when `exclusiveHolder` is *also* empty — a lock held in
SHARED mode. There `"" == ""` matches, and an anonymous caller would get `nil`,
refresh another session's lease, and believe it held an exclusive lock nobody
granted. The case now sets that precondition explicitly and asserts it before
measuring, and the mutant dies.
