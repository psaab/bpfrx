- **Timestamp**: 2026-09-07

  netdev name before it reaches the managed section; belt the operand as a

## Re-measured at HEAD, not taken from the issue

The issue's evidence SHA was `0f665fa42`; this work is on `19b082fe8`. The
defect reproduces unchanged. A throwaway harness drove all four config channels
plus a real `ApplyFull` against a temp `frr.conf`:

```
protocols { ospf { area 0.0.0.0 { interface ge-0/0/1.0; } } }
  configstore.CheckText        ACCEPT
  config.CompileConfig         ACCEPT
  config.CompileConfigLenient  ACCEPT
  config.SchemaValidate        ACCEPT
  compiled OSPF iface = "ge-0/0/1.0"
  rendered ->  interface ge-0/0/1.0
                ip ospf area 0.0.0.0
```

IS-IS rendered `interface ge-0/0/1.0`; RIP rendered ` network ge-0/0/1.0`;
OSPFv3 rendered both ` interface ge-0/0/1.0 area 0.0.0.0` and the `interface`
block. `interface all` rendered the literal operand `all`. The dash-form
control (`interface ge-0-0-1`) rendered the real kernel name on the same four
ACCEPTs, which is what makes this a spelling-dependent silent failure rather
than a broken feature.

The injection half reproduced too: `interface "ge-0/0/1.0 zzz"` and
`interface "ge-0/0/1.0; foo"` are ACCEPTED on all four channels and rendered
raw into the managed section.

## The fix, and where it is bound

`FullConfig.IfNameResolver`, wired by the daemon's `assembleFRRConfig` — the
sole production `FullConfig` constructor — to `Config.ResolveKernelIfName`.
`buildManagedSection` applies it once, producing COPIES (never in place: those
pointers are the active compiled config, #9141), for the global block and for
every routing instance. The legacy standalone-CLI apply path
(`pkg/cli/apply.go`) wires the same resolver.

A nil resolver is IDENTITY. That is deliberate and load-bearing: `frr_test.go`
alone holds 86 direct `generateProtocols` calls, and the whole suite stays
byte-identical.

The token belt (`validFRRInterfaceOperand`, the #6795 predicate) is applied in
the same pass and is NOT conditional on a resolver being present. A reference
that fails it is dropped with a `slog.Warn` rather than rendered — one
malformed line fails the entire frr-reload (#1880/#2223), so rendering it would
convert one bad interface into a total routing outage.

## Two things the fix un-hid

**A collision the raw spelling was masking.** `generateInterfaceSettings`
suppresses `ip ospf network point-to-point` when the OSPF config sets an
explicit network-type, keying that suppression on the OSPF interface NAME while
`InterfacePointToPoint` is keyed by KERNEL name. With `ge-0/0/1.0` vs
`ge-0-0-1` the two could never match, so the suppression was inert and nobody
noticed. Resolving the operand makes both sides name `ge-0-0-1`, at which point
the suppression must actually fire or one interface gets two conflicting
`ip ospf network` lines. `buildManagedSection` therefore feeds the
interface-settings pass the RESOLVED OSPF set.

**A quadratic-compile guard, which caught my first draft.** The commit-time
advisory originally called `cfg.ResolveKernelIfName` once per declared
interface to build a set of known kernel names.
`TestTunnelNameMapBuildsAreInputSizeIndependent8862` reddened immediately:
`ResolveKernelIfName` rebuilds the tunnel-name map per call, so a per-interface
loop over it is quadratic in the interface count on the tolerant compile — boot
and HA peer-sync. Counts observed: `z=1:4 z=2:6 z=8:18 z=32:66 z=128:258`. The
advisory now indexes declared interfaces by both spellings with no resolver
call at all, and returns before touching the interface set when the config has
no protocol interface references — which is also the correct shape.

## The advisory

`config.validateProtocolInterfaceRefWarnings` warns when a protocol interface
reference names no configured interface, or no configured unit on a configured
interface, and emits a distinct message for `interface all` (legal Junos,
unimplemented here). Advisory rather than gate, per #1960: the tolerant load /
HA config-sync paths must still accept a config whose interfaces the strict set
does not explain, and the failure being fixed is "no signal at all", not "wrong
signal". Silence is asserted for the canonical slash form, the dash form
(#8829) and a RETH unit — the spellings that must keep working.
