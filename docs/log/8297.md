# #8297 — proxy-ARP for a NAT pool address must follow RG ownership

- **Timestamp**: 2026-09-02
  - **Action**: gated the proxy-ARP DESIRED set on redundancy-group ownership,
    mirroring `relayMasterGateOpen` (#2456) and the DDNS per-RG writer gate, and
    bounded convergence at 2s so a failover is followed rather than waiting for
    the 30s reassert beat.
  - **File(s)**: pkg/daemon/proxyarp_rg_ownership_8297.go,
    pkg/daemon/proxyarp_rg_ownership_8297_test.go, pkg/daemon/daemon_proxyarp.go,
    pkg/daemon/daemon_proxyarp_test.go, pkg/daemon/README.md
  - **How it was found**: not by reading. Adding pool-mode NAT to the cluster
    smoke (#8280) made it reachable for the first time — before that no cluster
    config had a pool-mode source-NAT rule, so the question could not be asked.
    `ip neigh show proxy` on both nodes showed `172.16.80.7` on the primary AND
    the secondary-hold, and a WAN capture showed both answering with their own
    per-node RETH virtual MAC.
  - **The discriminating control**, because "pool NAT is broken" has many
    possible causes: same host, same second, same target and port — a source
    matching the interface-mode rule reached 5.95 Gbit/s while a source matching
    the pool rule timed out. ICMP through the same pool worked 3/3, clearing
    translation, routing and the reverse path.
  - **Decision note — why the desired set and not a removal path.** Losing
    ownership is expressed as "no longer desired", and `reconcileProxyARP`
    already sweeps orphans out of the desired set (#4955) and drives the
    per-interface sysctl down. Gating the input therefore buys install AND
    removal with no new deletion code — the same "compose with shipped
    machinery that is simply never reached" shape as #7289 R1.
  - **Decision note — the 2s poll is not a tuning constant.** The 30s reassert
    beat alone leaves a demoted node answering for up to 30 seconds, long enough
    for an upstream to cache its MAC and steer pool return traffic at a node
    that no longer owns the address. The fingerprint poll costs a config lookup
    and an `rgStateMachine` read per entry, takes no netlink and no apply
    semaphore, and only a CHANGE costs a reconcile.
  - **The arm with the widest blast radius is a box with NO redundancy groups.**
    Gating there breaks pool-mode NAT on every standalone deployment — the
    larger population — while passing every cluster test. It and the non-RG
    interface case are checked BEFORE ownership and each has its own cell.
  - **Test note**: four cells, three mutations, each red on the right one.
    Removing the gate (the shipped defect) reds the standby cell; gating
    standalone reds the standalone control; failing to strip the unit suffix —
    which makes every sub-interface resolve to RG 0 and the gate silently inert,
    a mutation that looks exactly like the fix working — reds the resolution
    cell. The headline assertion is that the STANDBY is excluded: asserting the
    owner is included passes on the broken code, where both nodes were.
  - **Owed**: the cluster acceptance. It needs a pool-mode NAT rule on the
    cluster, which is #8280 / PR #8300, so this branch is stacked on it and the
    smoke's traffic-survival assertion is the acceptance test.
