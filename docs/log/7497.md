- **Timestamp**: 2026-09-02 20:45 UTC
  - **Action**: Name the capacity of the two shim maps keyed by the binding
    VALUE's slot field, and refuse at plan time any plan that would mint a
    slot they cannot address. `userspace_bindings` is keyed by the composed
    index `ifindex * 16 + queue` and bounded by `BindingArrayMaxEntries`
    (1,048,576), but `userspace_heartbeat` and `userspace_xsk_map` are keyed
    by `binding.slot` and hold 4,096 entries. `slot` is assigned densely by
    the planner, a plain counter over the bindings it planned, so it is a
    ceiling on the TOTAL BINDING COUNT and the existing guards — checked
    against a bound 256x larger — do not stand in for it. Enforced at plan
    time rather than at `register_xsk_slot`, which runs during bringup after
    teardown; and refusing the whole plan rather than truncating, because an
    unbound queue does not reduce throughput but takes
    `drop_degraded_transit` on every transit packet while the interface still
    reads up. Prerequisite work for the planner change, not a defect
    reachable today: the count is bounded by `16 * interfaces` under both the
    current and proposed rules, so the ceiling is unchanged by #7497.

- **Timestamp**: 2026-09-03 01:10 UTC
  - **Action**: Decline to run an authorised cluster measurement, because the
    experiment as designed was degenerate and the question was answerable from
    source. Inducing EBUSY by holding an AF_XDP socket makes the wedge persist
    exactly as long as the inducer holds it, so "durable" would have been a
    property of the script, not the dataplane. The real answer is in
    `userspace-dp/src/afxdp/bind.rs:506-580`: the bind retries "Device or
    resource busy" specifically, `BIND_RETRY_ATTEMPTS` (20) x
    `BIND_RETRY_DELAY` (250ms) = 5s, before failing. So any EBUSY reaching the
    wedge predicate has already survived 5s of retries and is durable BY
    CONSTRUCTION; the transient case is absorbed upstream and never arrives.
    That disqualified the hysteresis option I had recommended an hour earlier —
    it would have added a third wait behind the bind retry and the existing 5s
    `bindingsBusySince` dwell, filtering transients that do not exist.
    Corroborated: cluster journals show zero "resource busy" and zero
    auto-rebind lines across the retained window (fw1: 1M lines back to Aug 4,
    4092 binding lines as the positive control proving the query would have
    found them).

- **Timestamp**: 2026-09-03 01:30 UTC
  - **Action**: Land blocker 5. The wedge predicate now counts registered+armed
    bindings that are not bound, so a PARTIAL wedge fires it; previously
    `bound == 0` meant one dead queue out of sixteen produced no recovery at
    all, and per #8384 no readiness signal either — a permanent silent failure.
    Because the fault is durable by construction, a global rebind that
    re-EBUSYs would re-trigger every cycle, so consecutive attempts are capped
    at 3 and exhaustion logs `auto-rebind GAVE UP` naming the wedged count and
    that no other signal reports the condition. Three, because the failure a
    rebind can legitimately repair is a teardown race that resolves within one
    retry; the second is margin for a slow quiesce.
    The pre-existing `TestHasBusyBindingsWedgeLocked` passed unchanged under
    both predicates because its fixture has ONE binding, which cannot express a
    partial wedge — its second assertion message ("want false once any binding
    is bound") stated a contract the change makes false, and was corrected
    rather than left to read as still-true.
    Filed #8388: only a targeted per-slot rebind removes the disproportion;
    caps and hysteresis only narrow when the disproportionate response fires.
