- **Timestamp**: 2026-09-02 20:45 UTC
  - **Action**: Name the capacity of the two shim maps keyed by the binding
    VALUE's slot field, and refuse at plan time any plan that would mint a
    slot they cannot address. `userspace_bindings` is keyed by the composed
    index `ifindex * 16 + queue` and bounded by `BindingArrayMaxEntries`
    (1,048,576), but `userspace_heartbeat` and `userspace_xsk_map` are keyed
    by `binding.slot` and hold 4,096 entries. `slot` is assigned densely by
    the planner, a plain counter over the bindings it planned, so it is a
    ceiling on the TOTAL BINDING COUNT and the existing guards — checked
    against a bound 256x larger — do not stand in for it. Enforced at plan
    time rather than at `register_xsk_slot`, which runs during bringup after
    teardown; and refusing the whole plan rather than truncating, because an
    unbound queue does not reduce throughput but takes
    `drop_degraded_transit` on every transit packet while the interface still
    reads up. Prerequisite work for the planner change, not a defect
    reachable today: the count is bounded by `16 * interfaces` under both the
    current and proposed rules, so the ceiling is unchanged by #7497.

- **Timestamp**: 2026-09-02 22:30 UTC
  - **Action**: Measure blocker 3 before designing for it. The live cluster
    reading — `workers 6`, 6 RX queues, 6 threads named `xpf-userspace-w` —
    cannot discriminate: "the knob binds" and "the queue count determines it"
    both predict `min(6,6) = 6`. Executed the planner over a 24-cell
    (workers x queues) matrix instead and counted distinct `worker_id` values,
    which IS the thread count because `plan_workers` keys its map by
    `worker_id` and spawns one worker per key. Result:
    `distinct_worker_ids == min(workers, queues)` throughout, with `workers 1`
    giving one group at every queue count including 16. The knob binds. The
    `workers=6, queues=6` row reproduces the live observation, so the model
    explains the real measurement and predicts the cases that could not be run.
    Did not change config on the shared cluster's secondary — HA config sync
    could overwrite or propagate it.

- **Timestamp**: 2026-09-02 22:50 UTC
  - **Action**: Land the planner change (`min(rx) x interfaces` ->
    `Sum min(rx, 16)`), blocker 6, and the docs. Carry-forward is now keyed by
    `(interface, queue_id)` rather than by slot: slot is a position in the
    minted sequence, so `[A(rx=4), B(rx=2)]`'s slot 5 is `(A,q3)` and becomes
    `(B,q2)` once B grows, and slot-keyed carry-forward attaches one
    interface's state to another's queue. Emitted a deduped worker-group INFO
    naming both counts and the capping knob, because the default poll mode is
    busy-poll and an operator must not learn about extra spinning threads from
    a CPU graph.
