# 9074 — ClearCounters is node-local by design; the design is now asserted

- **Timestamp**: 2026-09-06
- **Action**: no behaviour change. Pin the documented scope so the agreement
  between the handler and the grammar stops being an accident.
- **File(s)**: `pkg/grpcapi/clear_counters_scope_9074_test.go` (new).

## Why no fanout

The issue's own analysis is that the parity argument does not carry, and it is
right:

- **Sessions are REPLICATED**, so a local-only session clear is undone by sync —
  that is the stated reason for the session fanout (#2468). **Counters are not
  replicated**, so a node-local clear is self-consistent and complete. The two
  operations are not analogous, and the fanout is not something ClearCounters is
  missing.
- **The grammar already disclaims scope**, in both CLIs, byte-identically:
  *"this command clears all counters and takes no scope (per-scope clear is not
  supported)"*. `ClearCountersRequest` has no node field.

And a fanout would cost something specific: `ClearCounters` is absent from
`fabricAllowedUnaryMethods`, so it would require **widening that allowlist** —
which #9059 has just argued must be done deliberately, per method, with its own
rationale, rather than as a side effect. Trading a documented node-local scope
for a wider fabric surface is a bad exchange for a behaviour nothing has asked
for.

## What was actually missing

Today's behaviour and today's help text agree, and **nothing asserted the
agreement** — so a future "make it consistent with ClearSessions" change would
have read as a tidy-up. The issue's own acceptance asks for exactly this: *"a
cell asserting the documented scope, since today's behaviour and today's help
text already agree with each other."*

The cells assert the handler does not dial a peer (read from source — a
behavioural assertion would need a two-node harness to prove that **nothing was
sent**, which is an absence a probe cannot establish), that both CLIs still
disclaim scope, and — the part that keeps the reasoning honest — that
**ClearSessions still DOES fan out**. If that ever stops, "sessions are
replicated, counters are not" no longer explains the asymmetry and this file is
wrong rather than merely stale.

If node scoping is wanted later the shape is `node <local|peer|both>` in the
grammar, not a silent fanout, and this cell should be updated in that change
rather than deleted.
