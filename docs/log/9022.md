# #9022 — an anchored deny narrows in the direction nobody notices

- **Timestamp**: 2026-09-05
  - **Action**: documented the anchor asymmetry with a measured remedy. Did NOT
    change enforcement — that needs a decision, recorded on the issue.

    #9022 reports `deny-commands "^show log$"` permitting `show log 100`.
    Reproduced independently through the real path (`cmdtree.Canonicalize` ->
    `CompiledLoginRegexes.Evaluate`):

    ```
    deny "^show log$"   show log denied · show log 100 ALLOWED · show log messages ALLOWED
    deny "show log"     show log denied · show log 100 denied  · show log messages denied
                        show version configuration -> FAIL-CLOSED  (the #8289 property, intact)
    ```

    **This is documented parity, not an enforcement bug — but only half of it
    was documented.** `docs/system-login.md` states matching is partial and
    illustrates it with an ALLOW: `allow-commands "show interfaces"` admits
    `show interfaces terse`. That is the direction operators notice, because it
    is permissive in an obvious way.

    The DENY direction is the one that bites and it was never stated: an
    anchored deny is NARROWER than operators generally intend, and the command
    still runs. `show log 100` invokes the same `journalctl` the denied form
    invokes.

    The remedy is measured rather than asserted: the unanchored spelling
    `deny-commands "show log"` denies all four forms. That works today and
    needs no code change.

    **Deliberately not done**: a commit-time advisory when an anchored deny
    pattern names a node with `AcceptsArgs`. It is the right shape — additive,
    catches configs already committed, changes no enforcement — but it is an
    access-control surface and the choice belongs to someone else. Recorded on
    the issue with the reasoning, including that xpf already deviates from pure
    regex parity by failing closed on unresolvable commands (#8289, "Tier 3 is
    ours"), so an advisory is consistent with the stated posture rather than a
    new deviation.
