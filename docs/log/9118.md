## The wedge, and why nothing re-fires

`rotate()` closes the active file and sets `file = nil` **before** reopening. On
an `openHardenedAuditLog` failure it bumps `failedRotations` and returns with the
handle still nil. Every later `Send` / `SendBinary` / `HandleEvent` then takes the
nil arm and drops.

The self-sustaining part: **`rotate()` is called only from
`if written >= maxSize`, i.e. after a SUCCESSFUL write.** Once wedged, `written`
never advances, so the only caller of the only reopen in the file can never run
again. One transient `openat` failure at a rotation boundary — EMFILE, ENFILE,
ENOSPC, EROFS, EACCES — silences `security log mode event` and `traceoptions`
until the next config commit or a daemon restart.

#3478 made this state observable (counters, a rate-limited WARN, `rotate`
returning an error) and said in the README that it exists. **Observability is not
recovery**, and on an unattended appliance in steady state "until the next
commit" is unbounded.

## Three decisions worth stating

**The reopen lives on the write path**, because that is the only code that still
runs once the writer is wedged. Anywhere else and it inherits the same dead
trigger the existing reopen has.

**`Close()` now records that its nil handle is deliberate.** This is not
defensive clutter: `Close()` also nils the handle, so a nil handle means EITHER
"wedged" OR "shut down on purpose", and reopening on the second reading is worse
than the bug — it recreates an audit file after shutdown, and on the
`ReplaceLocalWriters` path it resurrects a writer the daemon has just retired.
The two states are indistinguishable from the handle alone.

**Rate-limited to one attempt per second.** The failure is usually not transient
in the instant; under ENOSPC an unbounded retry turns every dropped line into an
`openat`, making a full disk a syscall storm on the logging path.

The byte count is re-synced from `Stat()` on reopen: a wedge that began
mid-rotation leaves `written` describing a file that was already renamed aside,
and carrying it forward would fire the next rotation against the wrong size.

## Both writers, separately

`TraceWriter` has the identical wedge and is covered by its own cell rather than
by inspection — the two types open through different helpers (`openTraceFile`
resolves under `traceLogDir` and takes a sanitized basename), so a fix that
compiled for one could be inert for the other.

## Validation

Four cells; the wedge is *induced* (handle closed, `file` nilled, `closed` flag
untouched) rather than simulated, because the seam that would fail
`openHardenedAuditLog` is not exported and inventing one would make the cell a
statement about the seam. The post-condition is what matters and that is exactly
what is reproduced.

| mutant | result |
|---|---|
| local `Send` stops recovering | killed |
| trace `HandleEvent` stops recovering | killed |
| ignore the `closed` flag | killed by the not-resurrected cell |
| drop the backoff | killed by the backoff cell |

One fixture note: the backoff cell first **skipped**, because it chmod'd the
directory read-only before removing the log, so the remove itself was refused. A
skipping cell asserts nothing while looking arranged — the order is now
remove-then-chmod, and it runs.
