# #8876 — the latent-row ratchet keys on MEMBERSHIP, not a count

- **Timestamp**: 2026-09-05
  - **Action**: falsified this guard's own stated design and converted it.

    The table held an INT per edge. The file justified that choice in its own
    words:

    > "a set literal invites `add the new name and move on', which is precisely
    > the non-adjudication this guard is for."

    **That argument does not survive being stated next to its alternative.**
    Bumping `4` to `5` is exactly as cheap as appending a name. What actually
    resists a lazy edit is the failure TEXT and the adjudication it demands,
    not the data type — so the count bought nothing on the axis it was chosen
    for.

    **And it paid for that nothing with a blind spot: a SWAP.** Lose `filter`,
    gain `policer`, and the count is still 4. A new value-carrying leaf appears
    under an edge `compactNormalizeInScope` does not admit — exactly the event
    this ratchet exists to catch — and it passes in silence. A rename is the
    ordinary way that happens.

    Demonstrated rather than argued. The same mutation, both assertions:

    ```
    membership:  FAIL  LATENT ROW "family inet" SWAPPED
                       (lost policer, gained filter)
    count:       ok
    ```

    The count-keyed form does not report a substitution worse. **It does not
    report it.**

    Found while repairing a DIFFERENT ratchet (#8807, in the #8939 IPsec PR),
    whose good-news branch — *"unmeasured rows FELL, tighten the constant"* —
    would have banked a coverage loss as progress. The generalisation is what
    sent me back here:

    > **A RATCHET KEYED ON A COUNT CANNOT SEE A SUBSTITUTION**, and the
    > direction that looks like nothing happened is the one nobody audits.

    The falsified argument is kept in the file AS a falsified argument rather
    than quietly rewritten. The next person to prefer a count over a set
    deserves the counterexample, not just the conclusion.

    No expectation changed: the two edges carry the same six leaves they did,
    now named — `family inet` {address, filter, mtu, unnumbered-address} and
    `pool persistent-nat` {inactivity-timeout, permit}. Failure text now names
    GAINED / LOST / SWAPPED members explicitly. Full pkg/config green.
