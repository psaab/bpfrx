# 9042 — bounding the authorization-denial log without deleting the signal

## The shape of the fix

Five denial sites emitted an unconditional `slog.Warn` PER REQUEST, two of them
on the network-exposed fabric listener. The denial path's rate is
attacker-controlled: `principalForPeer` returns `Unauthenticated` for any
unattributable peer and `PrincipalForUID` returns an empty-Class principal for
any resolvable UID that is not a configured login user, so every local non-root
UID can drive the line at one `Warn` per unary call. `Warn` always ships (the
default level is `Info`) and every record fans out to remote syslog, after which
journald's 10000/30s cap suppresses xpfd's OTHER lines.

The remedy is a per-key dedup window plus a monotonic per-surface counter, on
the template of `pkg/cluster/heartbeat_reject_warn.go`. The five sites:

    pkg/grpcapi/authz.go        denyRPC                            grpc_login_class
    pkg/grpcapi/fabric_auth.go  checkFabricAuth                    fabric_auth
    pkg/grpcapi/server.go       fabricAllowlistUnaryInterceptor    fabric_method_allowlist
    pkg/grpcapi/server.go       fabricAllowlistStreamInterceptor   fabric_stream_allowlist
    pkg/api/crosssite.go        mutationCrossSiteGuard             rest_cross_site

## The counter is the load-bearing half

There was no denial metric anywhere and the audit journal records no
authorization events, so demoting the lines WITHOUT a counter would have deleted
the only signal that a denial happened — a worse outcome than the flood.
`xpf_authz_denials_total{surface}` is always emitted, including at zero, per the
#3464 convention: a counter that appears only once it fires cannot be alerted on
and cannot distinguish "never denied" from "not scraped". Zero is the normal
state here, so it is the reading that must be trustworthy.

The counter advances on EVERY denial including suppressed ones, and each emitted
line carries `suppressed_since_last`. Bounding the volume must not hide it.

## The key space is fixed, and that is a security property

A per-principal map keyed by attacker-supplied identity — a remote address, a
UID, a method — grows without bound. That is the SAME defect class this package
fixes, one level down: a limiter whose key space is attacker-controlled is not a
bound. Hashing into 64 fixed buckets keeps memory constant.

THE COST IS ACCEPTED DELIBERATELY AND STATED AT ITS REAL STRENGTH: two
principals can share a window, so under an attacker occupying every bucket a
legitimate new principal's FIRST denial may be suppressed. That trade cannot be
avoided, only chosen — guaranteeing every new key logs immediately makes the
line count grow with an attacker-controlled key count, which is the flood being
fixed. The bound wins; observability is preserved by the two things that do not
degrade under load (the counter, and the suppressed count on each line). The
test asserts the guarantee that IS made — prompt logging while free buckets
remain — rather than one the design cannot keep.

## Three of my own bugs, and what caught each

1. **`resetForTest` assigned `bucket{}` while holding that bucket's mutex**,
   replacing the mutex itself, so the unlock hit a fresh one: "sync: unlock of
   unlocked mutex", fatal. Caught by running the tests.
2. **The metric was DESCRIBED but never EMITTED.** The neighbouring call site
   reads `defer c.emitAdmissionRefusals(ch)` and my pattern, written without
   `defer`, matched nothing — so the counter that justified demoting the logs
   scraped as absent. Nothing about either file looked wrong. Caught by checking
   the wiring after editing, then pinned by
   `TestAuthzDenialsIsWiredIntoCollect9042`, which is mutation-verified against
   exactly that deletion.
3. **The site guard brace-counted function bodies**, and `interface{}` in the
   two fabric interceptor signatures opened and closed its depth inside the
   PARAMETER LIST — so it read the signature, and reported that two sites which
   DO route through denyaudit did not. A guard that reads the wrong bytes fails
   in the direction that looks like a real finding. Replaced with go/parser.
