## Census first — the defect is exactly 3 examples repo-wide

Rather than fix the three sites the issue names, I walked the whole schema
asking whether each `valueExamples` entry parses in a `set` value position:

    3 valueExamples do NOT parse as written
      system services ssh ciphers  ->  aes256-gcm@openssh.com
      system services ssh ciphers  ->  chacha20-poly1305@openssh.com
      system services ssh macs     ->  hmac-sha2-256-etm@openssh.com

`key-exchange` is named in the issue but its two examples contain no `@` and
parse fine today — the affected set is smaller than the issue implies.

The census is now `TestValueExamplesParseAsWritten8924`. Guarding the invariant
rather than the three sites is what stops a fourth being written.

## Read the value back, don't just parse it

Quoting would be a fix in shape only if the quotes survived into the compiled
value — the operator would get a cipher literally named `"aes256-gcm@…"`, which
sshd cannot match. `TestQuotedExamplesCompileUnquoted8924` asserts the compiled
value carries no quotes **and** satisfies `ValidateSSHAlgorithm`. Verified by a
PRODUCTION mutant: making the lexer stop stripping the opening quote kills both
assertions.

## The fix unmasked two pre-existing silent drops

`TestCompactBlockEquivalenceInventory2419` synthesises its fixtures from
`valueExamples`. Because the ssh examples did not parse, those sites were
**skipped** — "a spelling did not parse or compile" — and had never been
measured. With the examples quoted they became measurable and immediately
diverged:

    block   system { services { ssh { ciphers "aes256-gcm@openssh.com"; } } }  ->  [aes256-gcm@openssh.com]
    elided  system { services { ssh ciphers "aes256-gcm@openssh.com"; } }      ->  []

**Newly visible, not newly broken.** This is the same mechanism as the issue's
own provenance: an unparseable example made a row unrulable, and the
unanswerable verdict hid a real defect underneath.

Both sites are registered `open` in the #8690 exclusion register with the
measurement — including the part that saves the next person a wrong attempt:
**admitting `services ssh` to `compactNormalizeInScope` does NOT fix it** (still
`[]`) and reds other cells. The `ssh` node exists and only the value is lost, so
the cause is the compiler READER (#2419 read-only-`prop.Children`), not the
scope predicate.
