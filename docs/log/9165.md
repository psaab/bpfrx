- **File(s)**: `pkg/logging/syslog.go`, `pkg/logging/syslog_drop_stats_9165.go`,

## Half one — UDP write failures were not counted

The write-failure arm reached `noteDrop` only for stream protocols:

```go
if s.protocol != "udp" { ... noteDrop ... }
```

UDP is the **documented default**. On a box whose collector is down,
`droppedWrites` stayed 0, the rate-limited `slog.Warn("syslog message dropped")`
never fired, and `show` still rendered the configured collector as present —
three instruments reading healthy at once while every message went nowhere.

### Why this looked covered

#9025 had added a UDP arm — for the **deadline expiry it had itself
introduced**:

```go
if isTimeout(err) { pendingWarn = s.noteDrop(dropWrite, err) }
```

That is one failure mode, and not the one an operator hits. A dead collector on
a **connected** datagram socket (`dialUDP`) surfaces as ECONNREFUSED from the
ICMP port-unreachable, which is not a timeout, so it fell straight through.
Measured on this box: a connected UDP socket to a closed port reports the
refusal in **50/50** trials.

Every UDP write failure is now counted, at **both** sites — `Send` and
`SendBinary`. The second carries the RT_FLOW security log; fixing only `Send`
would have left the records an operator most needs uncounted.

No reconnect arm was added: a datagram socket has no connection to
re-establish, so the message is still dropped and the error still returned.
**Only the accounting changed** — which is why the acceptance table asserts a
UDP client leaves `DroppedDials`/`DroppedCooldown` at zero. A fix that grew a
stream arm here would pass a naive "the counter moved" assertion.

## Half two — the counters had zero production readers

`DroppedWrites()`/`DroppedDials()`/`DroppedCooldown()` had **no** non-test
callers. A counted drop reached an operator through exactly one channel, the
≤1/s warning above — so a warning already rate-limited away left nothing behind.
A counter nobody reads is indistinguishable from no counter, which is why this
is half the defect and not a follow-up.

- `EventReader.SyslogDropStats()` snapshots every installed client under the
  same RLock that guards the set.
- `Daemon.syslogDropStats` is the daemon-side reader (nil-safe on both hops: a
  scrape races startup and every commit that rebuilds the client set).
- `api.Config.SyslogDropsFn` carries it to the collector, which emits
  `xpf_syslog_messages_dropped_total{addr,protocol,reason}` **before the
  dataplane gate**. The syslog clients run whether or not the dataplane loaded,
  and a box that failed to load its dataplane is exactly the box whose logs an
  operator needs.

All three reasons are emitted **even at zero**. A series that appears only once
it becomes non-zero has no prior sample for `increase()`, and its absence is
indistinguishable from a scrape that never reached the code.

## The log-level half was NEG and was not touched

`ringbuf.go:839`'s `slog.Debug("syslog send failed", …)` sits in the per-event
fan-out loop, where CLAUDE.md mandates `slog.Debug`. Raising it would
reintroduce the flood that rule exists to prevent. The defect was the missing
counter, not the level — recorded here so a later pass does not "fix" it.

### H is recorded, not excused

`startHTTPServer` builds the `api.Config` literal inline and immediately serves
it; no test reaches it. So the line that names the function in the literal is
unbound, even though the function (G) and the `Config`→field copy (D) are both
bound. **This is not specific to #9165** — that literal carries 46 `…Fn:`
assignments and the same mutation on any of them survives for the same reason.

Filed as **#9443** with the measurement and a fix direction (extract
`buildAPIConfig`, then a reflection walk so hook 47 cannot be added unbound),
rather than either burying it or bolting a per-hook assertion onto this PR that
would rot on the next hook.
