# #9162 — NAT64 embedded-ICMP error match misses non-default routing domains

## Summary

`icmp_embed::parse::embedded_reply_key` hardcoded `routing_domain: 0`. Every
index the resulting key is probed against in an EXACT lookup preserves the
domain, so the probe could not reach any session installed in a routing
instance. `nat64_match.rs` — which has no second, domain-agnostic arm and
never stamped a domain at all — therefore matched nothing in a VRF and the
ICMP error was dropped.

## Scope note

`session_match.rs` is TEST-ONLY: `afxdp/mod.rs:207-208` imports
`try_embedded_icmp_session_match_from_frame` under `#[cfg(test)]` and the
`(area, desc)` wrapper is `#[allow(dead_code)]` with no callers. The brief that
opened this work listed it as a production caller; it is not, and the
correction is #9162's own validation comment. It is fixed anyway — the issue
asked for it in the same change — but by making the domain a required
ARGUMENT rather than plumbing a `ForwardingState` borrow through a path
nothing runs: the next person wiring it into production has to answer the
question at the call site, the way the three real arms do.
