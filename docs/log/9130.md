# #9130 — the deterministic-CGNAT allocator held the map mutex across the whole block probe

- **Timestamp**: 2026-09-06
  - **Action**: moved the linear CAS block probe in
    `allocate_deterministic_v4` / `allocate_deterministic_v6` OUT of the
    allocator's `live` map mutex, so no critical section on the deterministic
    path is longer than O(1).
  - **File(s)**: `userspace-dp/src/nat/allocator.rs`,
    `userspace-dp/src/nat/tests_det_lock_scope_9130.rs` (new),
    `userspace-dp/src/nat/mod.rs`, `docs/deterministic-nat-cgnat.md`

    Both deterministic arms took `lock_live()` FIRST and held it across
    `for p in port_start..=port_end { occupancy[ip_idx].reserve(port) }`, so
    the hold time was O(occupied prefix of the block) — the documented example
    pool uses `block-size 2016`. The sibling round-robin PAT path was
    deliberately restructured the other way in #4676 (`occ.claim()` lock-free,
    mutex only for the tiny reuse/cap/insert section, GC moved off that
    section); #2852's and #4676's remedies never reached the deterministic
    arms. New order:

    1. probe the subscriber's block lock-free on the CAS occupancy bitmap;
    2. **no free port** → take the mutex once, O(1), and check idempotent
       re-entry BEFORE reporting the block full;
    3. **port claimed** → take the mutex once, O(1), for re-entry + the
       flow-table cap + the insert, giving the port back with
       `free_no_recycle` on either refusal.

    **Step 2 is the correctness half, and the issue's stated fix direction
    omits it.** "Probe first, then take `lock_live()` for the idempotency +
    cap check + insert" is exactly right for a block with a free port and
    exactly WRONG for a full one: a live flow's own port is one of the occupied
    ones, so a re-entering flow on a full block finds nothing free and would be
    told `AllocatorExhausted` for a flow that already holds a translation —
    turning a working flow's second packet into a drop. The first draft of this
    fix instead kept a pre-probe re-entry check under the mutex; that is
    *correct* but it re-gates the probe on the mutex, and it was the new
    lock-scope cell that caught it (RED with the fix applied) rather than any
    reasoning. `a_full_block_still_re_enters_its_own_live_flow_9130` pins the
    semantics with `block_size: 1`, the only width where "re-entry was checked"
    and "the probe found a free sibling port" are distinguishable.

    `free_translated_port(ip_idx, port, /* recycle */ false)` on both give-back
    arms: a deterministic port is reusable via its occupancy bit alone and the
    deterministic path never drains the per-address recycle queue, so a
    recycled token is the #5178 leak in a new place.

  - **Measurement**: lock HOLD TIME is not observable from a return value and a
    timing assertion would be flaky, so the scope is bound structurally. The
    occupancy bitmap is CAS-based and lives outside the mutex, so one thread can
    park on `debug_live()` while an allocating worker runs; if the probe is
    inside the mutex the bit can never appear while the guard is held, and if it
    is outside it must. The worker is joined at the end, so "still running" is
    excluded. `debug_insert_live_locked` (new, `#[cfg(test)]`) makes the
    insert-section idempotency race deterministic — without it that arm fires
    once in many runs and a mutation there scores as survived most of the time.
