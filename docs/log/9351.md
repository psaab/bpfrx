## What was measured, before anything was changed

The issue is my own filing from #9323, so the first job was to re-measure at
the current head rather than trust it. It reproduced, and it is wider than the
issue records.

### 1. The reported case reproduces

```
GLOBAL       set protocols bgp group g1 neighbor 10.0.0.1 peer-as 65001
             set protocols bgp group g1 neighbor 10.0.0.1 local-address 10.0.0.2
  AST  [protocols] > [bgp] > [group g1] > [neighbor 10.0.0.1] > [local-address 10.0.0.2]
  ->   neighbor addr="10.0.0.1" peer-as=65001 local-address="10.0.0.2"      CORRECT

PER-INSTANCE set routing-instances VRF-A protocols bgp group g1 peer-as 65001
             set routing-instances VRF-A protocols bgp group g1 neighbor 10.0.0.1 local-address 10.0.0.2
  AST  ... > [group g1] > [neighbor 10.0.0.1 local-address 10.0.0.2]        PACKED
  ->   neighbor addr="10.0.0.1" peer-as=65001 local-address=""              DROPPED
```

Clean commit, no error, no warning. The configured case and the
never-configured case are byte-identical.

### 2. The BRACED spelling was fine the whole time

This is the half the issue did not have, and it is why nothing tripped over
the defect and why no cell saw it:

```
routing-instances { VRF-A { protocols { bgp { group g1 {
      neighbor 10.0.0.1 { local-address 10.0.0.2; } } } } } }
  -> neighbor addr="10.0.0.1" peer-as=65001 local-address="10.0.0.2"        CORRECT
```

The packing is a property of the FLAT-SET walk. `SetPath` resolves a
statement's packed tail through the schema (#8787 / #2419), so an undeclared
keyword ends the walk and the rest of the tokens land on the last node's key.
The hierarchical parser breaks on braces and never consults the schema for
shape. Every fixture in the tree that configures a per-instance protocol
writes braces, so the suite could not have seen this.

### 3. `rip` was worse than `neighbor`, and the issue does not mention it

`rip` is not declared under the per-instance `protocols` node **at all**, so
the packing happens one level higher and the ENTIRE protocol block collapses:

```
set routing-instances VRF-A protocols rip group r1 neighbor ge-0/0/0.0
  AST  [routing-instances] > [VRF-A] > [protocols] > [rip group r1 neighbor ge-0/0/0.0]
  ->   ri.RIP = &RIPConfig{Interfaces:[] ...}      NON-NIL AND EMPTY
```

Non-nil-and-empty is the worse shape: downstream code that branches on
`ri.RIP != nil` reads "RIP is configured" and then finds no interfaces.

### 4. The size of the gap — mechanically, with a denominator

Enumerating every leaf path of the global `protocols` schema and comparing the
flat-set AST that `SetPath` produces at global scope against the one it
produces inside a routing instance:

```
enumerated global protocols leaf paths           122
flat-set AST SHAPE DIFFERS inside an instance     53      BEFORE
                                                  22      AFTER  (all lldp / router-advertisement)
```

And on the schema itself:

```
global `protocols` reachable paths               169
per-instance `protocols` reachable paths          68      BEFORE
                                                 140      AFTER
paths present ONLY per-instance                    0      (before and after)
attribute differences at the 68 shared paths       0
```

A shape difference is an UPPER bound on data loss, not a synonym for it — some
packed tails are read by their compilers. It is the right instrument for the
schema question because packing is exactly what the schema controls.

## The fix

`routing-instances <name> protocols` is no longer a second declaration of the
`protocols` grammar. It is a node whose children are the GLOBAL subtrees,
shared by pointer:

```go
var schemaRoutingInstanceProtocols = &schemaNode{desc: "Protocols configuration", children: map[string]*schemaNode{
	"ospf":  schemaProtocols.children["ospf"],
	"ospf3": schemaProtocols.children["ospf3"],
	"bgp":   schemaProtocols.children["bgp"],
	"rip":   schemaProtocols.children["rip"],
	"isis":  schemaProtocols.children["isis"],
}}
```

Three things about that shape:

**Sharing is what removes the class rather than the instance.** The compiler
already treats the two as one grammar — `compileRoutingInstances`' `case
"protocols"` calls the same `compileProtocols` — so two declarations of one
grammar is the drift, and this defect is what drift looks like. Declaring the
101 missing paths by hand would fix today's instance and leave the mechanism.

**It is an established shape here, not a new one.** `init()` in `schema.go`
already wires `groups <name>` to every top-level node by pointer, so the schema
is already a DAG and every walker already tolerates a shared subtree.

**The member set is the COMPILER's, not a judgement.** It is exactly the five
fields `compileRoutingInstances` copies out of the `compileProtocols` result
(`ri.OSPF/OSPFv3/BGP/RIP/ISIS = proto....`). `lldp` and `router-advertisement`
are compiled by `compileProtocols` and then NOT copied into the instance, so
declaring them would offer completion for a keyword whose value is discarded —
that is why the residual 22 shape differences are correct rather than
outstanding.

### Safety of the swap, measured rather than argued

Before replacing the per-instance literal I compared the two subtrees on both
axes:

- **paths**: 0 present only per-instance (it was a strict subset of global);
- **attributes**: 0 differences at the 68 shared paths, comparing every
  `schemaNode` field except `children`/`wildcard`, with `validator`-style func
  fields compared as nil/non-nil.

The attribute comparator carried a positive control in the same run — the same
routine run against two nodes that genuinely differ (`protocols ospf` vs
`protocols isis`) reported 9 differences — so the zero is a measurement, not a
comparator that prints nothing.

### #8921 was verified, not regenerated

The ratchet's own instruction is "WALK THE SCHEMA AND CHECK EVERY LISTED SITE
before adding a row. Adding it without looking records the debt instead of
paying it." Its concern is that the scope predicate is keyed on
`(container keyword, head)` with no parent context, so an admission can go live
at a site nobody measured — safe only "by coincidence of naming".

For this change that concern is answerable mechanically, because the new sites
are not same-named neighbours: they are the SAME schemaNode reached by a second
path. So the check run before regenerating was, for each pair:

- a WHOLLY NEW pair (34 of them) is safe when all of its declaring sites
  declare the same head node — one declaration, two paths;
- a CHANGED pair (5) is safe when each GAINED site's head node is
  pointer-identical to an already-recorded site's head node.

Result: **34 new and 5 changed, 0 unverified.** The property is not left as
prose — it follows from `TestRoutingInstanceProtocolsShareTheGlobalGrammar9351`'s
pointer-identity assertion, since identical subtree roots make every descendant
identical too. Re-fork the per-instance grammar and that cell reds first.

see: one container armed and one added in the same change leaves 158 == 158 and
the ratchet stays green while a new blind site landed.

**M3 is the one that matters most.** It changes NO behaviour — a shallow copy
shares the children map, so every flat-set and braced cell stays green — and it
is killed by exactly one cell. That is what says the anti-drift property is
BOUND rather than incidental: without that clause, the next person could
re-fork the grammar and every behavioural test in this file would still pass,

**M6 is the anti-vacuity mutant.** Severing the reader made the global positive

cannot report a per-instance verdict on a run where the reader is not
exercised. A control that stays green while its reader is dead would make every
row beneath it unreadable.

M7 removes a scope entry the normalizer pass consults. Both are the CALL SITE,
not the function.

## What I found that the issue does not contain

1. **The braced spelling worked all along.** The issue reports the defect as
   "the identical global spelling works"; the sharper statement is that the
   identical PER-INSTANCE spelling works too, if you write braces. That is
   what makes it invisible: the corpus is braced.
2. **`rip` is lost as a whole block**, not as a leaf, and comes back non-nil
   and empty.
3. **The residual is `lldp` and `router-advertisement`**, which a routing
   instance accepts and silently discards today — a separate defect in the
   same family, filed rather than folded in, because the remedy is a new
   commit rejection.
4. The per-instance subtree was an **attribute-identical strict subset** of
   the global one, which is what makes the pointer swap a provable no-op on
   everything it already covered.
