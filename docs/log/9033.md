# #9033 — the NAT64 reverse companion hardcoded routing_domain 0

- **Timestamp**: 2026-09-06
  - **Action**: the NAT64 arm's reverse session key now carries
    `flow.forward_key.routing_domain` instead of a hardcoded 0, matching what
    its sibling arm has always done.

    `poll_descriptor` builds the reverse companion two ways. The non-NAT64 arm
    calls `flow.reverse_key_with_nat(...)` -> `reverse_session_key`, which
    preserves `routing_domain` verbatim. The NAT64 arm hand-built a `SessionKey`
    with `routing_domain: 0`, so the same flow got a different identity purely
    by taking that branch — and the reply, whose key IS domain-stamped on
    ingress (`poll_descriptor/mod.rs`, the #7160 stamp site), missed the
    installed companion.

    **The `routing_domain: 0` convention is real but belongs elsewhere, and
    checking that was the whole job.** `session/key.rs` deliberately zeroes the
    domain in `reverse_wire_key` / `reverse_canonical_key` — reverse-MATCH INDEX
    keys — because "a reply may legitimately arrive in a different routing
    domain than the forward direction resolved", and `reverse_match_key` zeroes
    an arriving probe the same way so the two halves cannot drift. That pairing
    is self-consistent and independent of what an INSTALLED session carries.
    This site installs a companion, so it takes the installed-key rule, which
    the sibling arm already encodes.

    **Scope: `routing_domain` only.** The same literal also zeroes
    `discriminator`, and that is left alone — NAT64 is v6<->v4 translation
    rather than tunnelling, and the embedded-ICMP discriminator erasure is
    #9031's subject, which needs the quoted GRE header PARSED rather than a
    field copied.

    **The obvious controls were VACUOUS, which is why a new cell was needed.**
    Every NAT64 cell in the tree runs on a snapshot with no routing-instance
    membership, where `routing_domain` is 0 on both sides and the defect is
    invisible; the four `nat64_icmp_error_*` cells pass identically with and
    without this fix. A green suite therefore said nothing. The new cell puts
    every interface in routing instance 7, drives a real NAT64 flow through
    `txn_run_descriptor`, walks the session table with `iter_with_origin` and
    asserts the v4 reverse companion carries 7 — with two fixture preconditions
    (a session was installed at all; a v4 companion exists) so it cannot pass
    over an empty or wrong-shaped table. Reverting the literal reds it.

    **On #9162, which warns that fixing this breaks the NAT64 ICMP V4->V6 arm:
    not refuted and not confirmed.** The code argument above says the coupling
    does not reach an installed key, and the full suite is green — but that
    green is VACUOUS for the question, because no cell combines NAT64 + an ICMP
    error + routing domains. Recorded here rather than resolved; whoever takes
    #9162 or #9031 should build that combination.
