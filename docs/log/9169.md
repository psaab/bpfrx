# #9169 — the event-stream `producer_seq_lock` is the #4800 model's FOURTH site

## Defect, re-verified at the base commit (`c525bb966`, `origin/master`)

Read out of `git show origin/master:...`, not from the issue body:

- `userspace-dp/src/event_stream/mod.rs:197` — `producer_seq_lock: Mutex<()>`
  lives on `EventStreamShared`, i.e. process-global across every producer
  thread. Constructed at `:276`.
- `:521-527` — `send_sequenced` takes `producer_seq_lock.lock()`, then
  `let seq = self.next_seq()`, then `let frame = encode(seq)` — the ENCODE is
  inside the critical section — then `try_send_frame`. `push_delta` and
  `push_delta_lossless_within` (what the worker loop calls for every session
  delta, Open included) both route through it; the lossless path re-takes the
  lock on every retry attempt (`:583`).
- `docs/userspace-newflow-ceiling.md` says **"Three cross-worker
  synchronization points sit on that path"** and its table has three rows.
  POSITIVE CONTROL for the absence grep: `publish_shared_session|
  replicate_session_upsert|live mutex` hits lines 23-24 (the site rows);
  `producer_seq|event_stream` returns nothing. So the absence is a property of
  the document, not of my grep.

This is a proven static cost bound, not a measured bottleneck, and #9169's own
acceptance is an INSTRUMENT rather than a remedy: the remedy needs design
(`F: FnOnce(u64) -> EventFrame` consumes the seq, so encoding first means
allocating first, which reintroduces the #3878 F-152 ordering and F-153
rollback hazards the lock exists to close).

## A FALSE CLAIM in the inherited text, corrected

The inherited doc, README, Rust cell header, Go comments and Python docstrings
all asserted, **in the past tense**, a measurement nobody made:

> A run bound by that mutex **produced** a real new-flows/sec plateau with all
> three named sites COLD

`docs/userspace-newflow-ceiling.md`'s own status line — two screens above that
sentence — says the loss-userspace-cluster run has **not** been performed for any
site. So the document contradicted itself, and the shape of the error is the one
that propagates: a counterfactual written as a result gets cited as a result. It
had already reached my own commit message and PR body before I caught it.

Every occurrence is now conditional and says so explicitly (7 sites:
`docs/userspace-newflow-ceiling.md`, `event_stream/README.md`, the Rust cell
header, `pkg/dataplane/userspace/protocol_status.go`,
`pkg/api/metrics_descriptors_userspace_session.go`, and two in
`test/incus/newflow_ceiling_analyze.py` plus one in its test). What IS
established is the static bound and the absence of a counter — which is exactly
what #9169 claims for itself ("a proven static cost bound, not a measured
bottleneck").

Positive control on the grep that found them: `produced a real|reported a
plateau` returns nothing after the fix, and returned 7 hits before it.

## Wire / protocol

The #8892 snapshot-shape gate covers the DAEMON -> HELPER direction
(`ConfigSnapshot` and friends); this change touches only HELPER -> DAEMON
`ProcessStatus`, so the digest is unmoved and no `ProtocolVersion` bump is
owed. The addition is `serde(default)` / `omitempty` in both directions, and
the mixed case (new daemon, old helper) is handled explicitly rather than
silently: the analyzer's `_scalar` RAISES on an absent series, and the doc says
in words that a zero denominator on a loaded run is a BUILD statement, not a
measurement.
