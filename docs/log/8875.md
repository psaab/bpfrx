# #8875 — the security stanza is lost when the top-level brace is elided

- **Timestamp**: 2026-09-05
  - **Action**: admitted the three top-level `security` containers
    (`policies`, `screen`, `zones`) to `compactNormalizeInScope`. The stanza
    admitted NO children at all, while the children's own pairs
    (`policies from-zone`, `policies global`, `zones security-zone`) were
    already admitted — so the fold could never reach them, because it reaches a
    child only after `security -> <container>` has created the container. That
    single missing admission dropped the entire zone-pair policy set, the global
    policies, the zones and the screen profiles, silently, on both the strict
    and tolerant paths.
  - **Severity**: an outage, not a breach, and measured rather than reasoned.
    Losing the policy set sends traffic to the default policy, which compiles to
    DENY. Stated explicitly because `PolicyPermit` is `iota` — the zero value of
    `DefaultPolicy` — so a dropped set landing on a zeroed field *looks* like
    permit-everything until it is read back.
  - **File(s)**: pkg/config/compact_normalize_8662.go,
    pkg/config/security_toplevel_elision_8875_test.go,
    pkg/config/compact_scope_blind_pairs_8852_test.go
  - **Follow-up landed here**: a guard pinning that the unconfigured default
    policy is DENY *because the compiler sets it explicitly*, not because the
    field defaults to it. `PolicyPermit` is `iota` (the zero value), so dropping
    the explicit set — or reordering the enum — would silently turn a
    fail-CLOSED outage into a fail-OPEN breach. The assertion is on "not the
    zero value" rather than only "== PolicyDeny", because that is the property
    which stops holding the moment the explicit set is removed, whichever order
    the enum is in. Mutating `compiler.go:721` to `PolicyPermit` reds it.
