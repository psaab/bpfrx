# #9331 — `xskLivenessProven` is BOX-WIDE, so one live queue disabled wedge detection for every other queue

- **Timestamp**: 2026-09-06
  - **Action**: removed the box-wide `xskLivenessProven` term from the
    busy-binding wedge predicate, leaving `xskLivenessFailed` (which is
    correctly box-wide) and the predicate's existing per-binding terms.
  - **File(s)**: `pkg/dataplane/userspace/binding_wedge_recovery.go`,
    `pkg/dataplane/userspace/binding_wedge_masking_9331_test.go` (new),
    `pkg/dataplane/userspace/process_napi.go`,
    `pkg/dataplane/userspace/binding_wedge_giveup_9043.go`,
    `pkg/api/metrics_dataplane_silent_skips_9019.go` (three stale claims)

    On any box where at least ONE queue ever proved live — every healthy box —
    wedge detection was off for EVERY queue. Combined with #8384 a masked queue
    had no detection, no recovery and no readiness signal.

  - **THE ISSUE'S PROPOSED SHAPE IS WRONG, AND THE MEASUREMENT SAYS SO.** It
    asked for per-binding liveness, "so the gate answers 'has THIS queue ever
    been live' instead of 'has any queue'". Both readings of that fail:

      * **Reported per-binding RX is VACUOUS.** `zero_unbound_slot`
        (`userspace-dp/src/afxdp/coordinator/refresh_bindings.rs:331`) sets
        `binding.rx_packets = 0` on every unbound slot. A binding that is
        registered+armed+unbound therefore ALWAYS reports RX 0, so a
        "has this binding received" term is false for every binding the
        predicate can count — dead code that reads as a fix.
      * **Remembered per-binding liveness is HARMFUL.** A map that survived the
        unbind would exclude precisely the binding that WAS live and went
        RX-dead — the exact case #9331 exists to detect — re-creating the mask
        in a new place with the same shape.

    What actually answers "is this queue live" was already in the loop and is
    per-binding by construction: `Registered && Armed && !Bound`. An unbound
    binding is not receiving; no liveness term can say more. So the fix is to
    stop the box-wide flag from overriding it, not to add a second liveness
    notion beside it.

    `TestAWedgedBindingIsAWedgeWhateverRXItReports9331` pins the consequence, so
    that if anyone later adds an RX-keyed exclusion — remembered or reported —
    it reds. Mutant V3 applies exactly that shape and is killed by it.

  - **`xskLivenessFailed` STAYS, and stays box-wide**, because it is a different
    claim: XSK is proven broken for this box, so a rebind cannot repair anything
    and firing one only tears down whatever still works. Without a cell for that
    half, the change reads as "delete the gate" and the next reader cannot tell
    which half was deliberate — `TestProvenBrokenXSKStillSuppressesRecovery9331`
    is that cell, and mutant V2 (drop it too) is killed by it.

  - **Trap 1 (do not churn a legitimately idle standby) is avoided by terms that
    were already there, and the cell proves it rather than asserting it.** A
    standby's queues receive nothing by design, and
    `shouldAutoProveIdleStandbyXSKLocked` requires `allBindingsBound` — so a
    healthy idle standby has NO registered+armed+unbound binding, `wedged` is 0,
    and the predicate is false whatever the liveness flag says. The cell asserts
    it for BOTH values of the flag, so it cannot pass because the flag happened
    to suppress.

  - **Trap 2 (`maxConsecutiveAutoRebinds`) re-derived rather than inherited.**
    The derivation survives and its COST term gets stronger. What a rebind can
    repair is unchanged (a teardown race, resolved within one retry); what
    changes is what an attempt costs. Before #9331 the predicate could only fire
    while the box had proven nothing, so a rebind tore down bindings not yet
    known to work. Now it can fire on a box with fifteen healthy queues and one
    wedged one, and the rebind is GLOBAL — it tears down all sixteen. So three
    is if anything generous rather than tight.

    The budget is per-BOX and per-EPISODE, not per-wedge, and that is right
    under per-binding detection: the rebind is one global action whatever set is
    wedged, so N simultaneous wedges consume one attempt per cycle, not N. What
    per-binding detection does change is how often the predicate stays TRUE — a
    durable single-queue wedge now holds it true instead of being masked, so the
    counter reaches the cap, gives up once, and stays given-up until it clears.
    That is intended, and the #9043 counter keeps it observable
    (`TestTheGiveupCounterMovesForAPreviouslyMaskedWedge9331`).

  - **Three stale claims corrected in the same change.** `process_napi.go`,
    `metrics_dataplane_silent_skips_9019.go` and `binding_wedge_giveup_9043.go`
    each cite the box-wide masking as live. Each is corrected in place rather
    than deleted, because the CONCLUSION each was supporting survives for a
    different reason: a queue with no NAPI probe target BINDS fine and is merely
    never woken, so it is not a wedge the predicate can see at all — which is
    why #9019's counter is still the only signal for its case.

    the next person to "improve" it into the defect.
