# PR #8881 — counted ratchet: admitted pairs whose container cannot split a packed run

> Logged under the PR number, not an issue number. This ratchet has no issue of
> its own — it is the CLASS that #8880 (truncation) and #8883 (injection)
> instantiate. It was briefly logged as `8880.md`, which collided with that
> issue's own fix log; the number had been picked before the issue existed.

- **Timestamp**: 2026-09-05
- **Action**: Landed a counted ratchet over `(container, leaf)` pairs that are
  ADMITTED to the brace-elision scope but whose container cannot split a
  multi-statement packed run, so the second statement is lost or corrupted.

  **Live member, adjudicated:**

      system { name-server 1.1.1.1 name-server 8.8.8.8; }
        packed  1.1.1.1 | name-server | 8.8.8.8
        braced  1.1.1.1 | 8.8.8.8

  The second statement is not merely dropped — the multi leaf absorbs the
  following statement's KEYWORD as one of its own values, leaving a resolver
  literally named `name-server`. `system domain-search` behaves identically.

  **Counts, deterministic over three runs at master 947633533:** 95 pairs at
  `args >= 2`, 462 at `args >= 1`; of the 462, 454 have a resolvable remedy
  (86 multi, 368 not) and 8 qualify with different multi-ness on different
  schema paths.

  **The remedy is not uniform, and the guard says so.** `packedStatements` is a
  candidate fix for the 368 non-multi members and is MEASURED INSUFFICIENT for
  the multi ones: giving `system` the opt-in does not fix `name-server`, because
  a multi leaf absorbs the rest of the run in `consumeNodeKeys` so the split
  still yields one statement.

  **Three instrument defects were found and fixed while building it**, each of
  the class this campaign keeps meeting:
  - the census did not descend into `wildcard` nodes, hiding
    `("peer","allowed-ips")` entirely — found because lane-8526 could not
    reproduce the number and refused to adjudicate a set they had not derived;
  - the adequacy control was anchored on `("address-book","address")`, which is
    admitted only on the still-open #8866, so at master it could never fire —
    a control that cannot fail;
  - the multi/non-multi split was NON-DETERMINISTIC (87 then 93 on one
    unchanged tree) because conflicting pairs were resolved by Go's map order.
    The stability assertion had been written over the headline counts only, so
    it passed while a reported number drifted.

  **Not #8876.** That census is missing parent EDGES, so the container is never
  created; this one is containers that ARE reachable and admitted and fold a
  multi-statement run into one. A row drifting between them makes both
  unfalsifiable.

  **The number is an over-approximation** — a pair is only actually broken if a
  multi-statement packed run reaches that container in a config someone writes,
  which the census does not model.

  **Adjudication by lane-8526 found TWO failure modes, splitting on the
  predicate's own disjunction:** `multi` leaves INJECT the repeated keyword as
  a list value (packed has MORE members, one a phantom named after the
  keyword); `args >= 2` compound keys TRUNCATE later instances (packed has
  FEWER). A cell comparing LENGTHS scores injection as increased coverage, so
  every comparison here is on rendered contents. A truncation member is kept
  beside the injection ones so no reader generalises from a single mode.

  **Severity is not a property of the mode** — injection is SILENT in a NAT
  pool and the resolver list, REJECTED for a WireGuard peer, WARNED for an
  address-set. It depends on whether an unrelated downstream validator trips
  over the phantom, so the gate verdict is per pair.

  **A `STRICT-REJECTS` verdict only means "handled" if the BRACED arm was
  ACCEPTED** — the liveness rule pointed at reject verdicts rather than at
  equality ones. Each member asserts its braced reference first.

  Counts moved 462 -> 460 at `e2018595f` when #8868 and #8874 landed: containers
  that gain `packedStatements` leave the population. Tightened rather than
  loosened.
