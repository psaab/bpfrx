# #7174 M13 — bound the NAT recycle FIFO's length and per-claim cost

- **Timestamp**: 2026-09-02
  - **Action**: verified the row at `origin/master` first (the issue's line
    numbers have drifted twice already, and three of this cohort's rows were
    fixed by the time someone looked). `claim` at
    `userspace-dp/src/nat/allocator.rs` still drained and restored the whole
    per-address recycle FIFO with no bound, and `reserve()` still left an
    out-of-band-reserved port's token queued.
  - **Re-priced the pathology before choosing a fix**, per the analysis already
    on the issue: retained tokens go to the BACK, so K reserved tokens ahead of
    the free ones cost O(K) ONCE and then sit behind them — the HA-churn spike
    amortizes itself. The unamortized case is the EXHAUSTED address: with no
    free tokens left, every claim popped all K, retained all K, allocated a
    K-element retain buffer and returned `None`, and `None` is the CORRECT
    answer there so nothing self-corrected.
  - **Two bounds shipped**, neither changing which port is handed out:
    an exact `occupied == range` short-circuit in `claim` (cost), and a
    `RecycleRing` dedup bitset so a port holds at most one token (length).
  - **File(s)**: userspace-dp/src/nat/allocator.rs,
    userspace-dp/src/nat/tests_pool.rs, userspace-dp/README.md
  - **Decision note — why not a scan budget, and why not eager removal.**
    The issue named three candidate shapes. A bare scan budget returns `None`
    on budget exhaustion, which callers read as "this address is full", so
    under exactly the condition the row describes it converts a slow allocation
    into a spuriously DROPPED NAT translation. The issue's own analysis said a
    budget needs a way to tell "scanned enough" from "genuinely full";
    `occupied == range` IS that discriminator — every set bit is an offset
    `< range`, so the equality holds iff no port is free — and once you have it
    the budget is unnecessary for the case that motivated it. Eager removal at
    `reserve()` was rejected on two counts: it moves a one-time cost onto the
    HA-sync path to delete tokens that are not the recurring cost, and a port
    released through the deterministic `free_no_recycle` path pushes no
    replacement token, so removing its token eagerly would strand the port.
  - **Exactness note**: `free_recycle` now clears the occupancy bit AND queues
    the token under one acquisition of the per-address recycle mutex, which is
    the mutex `claim` holds when it reads `occupied`. That makes the
    short-circuit exact with respect to the ring the claimer is about to walk
    rather than a hint: a free that has not yet taken the lock has not pushed a
    token either, so a full scan would miss it identically.
  - **Test note**: the fix is invisible to a test that reads the return value —
    an exhausted address returns `None` with or without it — so the cost
    assertion reads a `#[cfg(test)]` scan-pop seam, and the fixture contains a
    genuinely exhausted address rather than a merely churned one. Mutation
    evidence: deleting the short-circuit reds the exhausted-address cell (96
    pops against an asserted 0); deleting the dedup reds the duplicate-token
    cell (`[1025, 1025]` against `[1025]`); moving the gate one port early — the
    false-exhaustion direction — reds THREE cells including the
    partially-occupied control; dropping the counter's decrement reds the
    counter/bitmap agreement cell.
