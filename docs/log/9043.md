## Claim 1 — definitively wrong, and the tree says so

`userspace-dp/README.md` said *"Generic-XDP fallback consumes UMEM frames
permanently on mlx5"*. Wrong twice:

- A generic-XDP interface binds **`COPY_ONLY_BIND_FLAGS`**
  (`bind.rs`, the `interface_uses_generic_xdp` branch; virtio_net is the one
  exception, taking AUTO), and the umem README states copy mode's `XDP_PASS`
  *"operates on kernel DMA buffers, not UMEM frames"*. **The generic fallback
  cannot consume a UMEM frame at all.**
- *"on mlx5"* is incoherent besides: mlx5 supports native XDP and does not take
  the generic fallback.

Corrected, with the true half kept: the cpumap redirect is real and shipped.

## Claim 2 — cannot be settled here, so it is marked, not deleted

The umem README asserted as fact that zero-copy `XDP_PASS` on mlx5 permanently
consumes a fill-ring frame. **Nothing in the tree corroborates it and two
independent readings contradict it** — `mlx5e_xsk_skb_from_cqe_linear` copies
into a fresh SKB and reuses the frame, and a verifier checking a neighbouring
claim reached the same conclusion by a different route.

It stays, marked UNVERIFIED, because the decisive check is outside the repo: one
flood test on a zero-copy mlx5 bind, or one read of the running kernel's
`mlx5e_xsk_*` path. **Deleting it would be as unfounded as asserting it** — I
have not measured it either.

The harm being addressed is not the mitigation, which is cheap and shipped
either way. It is that **a claim steering a design decision had never been
measured and was written as fact**, so the next decision made on its strength
inherits the confidence without the evidence.

## Why a cell for a documentation fix

The correction is now documentation, and a documented fact with nothing
asserting it is how the wrong version got written. `generic_xdp_binds_copy_only_9043`
pins the bind decision the corrected sentence rests on; if that ever stops being
copy-only, the README becomes false and the cell fails. It carries a second
assertion that AUTO and COPY_ONLY actually differ — without it the first is
vacuous.

### Item 2 — no counter on the give-up arm. Fixed here.

`binding_wedge_giveups_total`, incremented in the **same branch** as the give-up
log so the two cannot drift — a counter keyed on a different condition than the
message beside it is worse than no counter, because the number then describes
something else.

Why it matters more here than in most places is written in the arm's own
message: *"the affected queues will not forward and no readiness signal reports
them."* Per #8384 readiness cannot see a bound-but-dead queue, so once automatic
recovery stops there is **no other signal**. What existed was a single
`slog.Error`, emitted once per wedge by design — and a log line that fires once
is the hardest kind to alert on: gone from the ring buffer by the time anyone
looks, and its absence indistinguishable from a box that never wedged.

Always emitted including at zero, per the #3464 convention and for #8312's
reason: a counter that appears only once it fires cannot be alerted on and
cannot distinguish "never happened" from "not scraped".

### Item 1 — box-wide liveness masking. Split out as its own issue.

`xskLivenessProven` is **box-wide**, so one live queue disables wedge detection
for every other queue. The tree already says so in two files written for other
work (`metrics_dataplane_silent_skips_9019.go:31`, `process_napi.go:95`), and
combined with #8384 a masked queue has **no detection, no recovery and no
readiness signal**.

It is filed separately rather than fixed here because the fix is a design change
(per-binding liveness, with the idle-standby case carried over and the rebind
budget re-derived), and because **this issue's title is about two README claims
and would never lead anyone to it**.

### The fixture caught itself

My first cell used a bare `&Manager{}` and measured nothing:
`hasBusyBindingsWedgeLocked` returns false on the nil proc, which RESETS
`consecutiveFailedAutoRebinds` and returns before the give-up branch. It failed
loudly rather than passing vacuously. The cell now asserts the wedge
precondition explicitly, so a fixture that stops reaching the branch says so
instead of going green.
