## Two ordinary commits got past #7530

**Hole A — an unrecognised protocol spelling silently dropped the whole
stanza.** `compileSNMPv3Users` switches on the exact keyword and has **no
default arm**, so `authentication-sha512` — a real protocol this agent does not
implement, and the obvious thing to type — left `AuthProtocol` EMPTY. #7530's
gate fires on `AuthProtocol != "" && AuthPassword == ""`, so it *cannot* fire:
there is no protocol to be missing material for. The operator asked for
authentication and committed a bare noAuthNoPriv user.

**Hole B — privacy without authentication.** USM has no privacy-only level (RFC
3414 defines noAuthNoPriv, authNoPriv, authPriv — there is no noAuthPriv), and
**both** keys are derived with the AUTH hash function, so this user derives no
privacy key either. #7530's privacy arm requires `PrivPassword == ""` and a
password *is* present, so it does not fire.

## The floor was keyed on the wrong thing

`pkg/snmp/v3.go` read `user.authKey != nil` / `user.privKey != nil`. A key is
derived only from a password, so **any configuration that named a protocol but
produced no key had no floor at all** and was answered at whatever level the
request asked for. A key-derivation failure degraded to clear.

Keyed on the configured protocol it fails closed. The commit gates and the floor
are not redundant: gates tell the operator at commit time, and the floor refuses
to serve a config already on disk or arriving by peer sync — the population that
reaches `Store.Load` / `Store.SyncApply`, which no commit gate can reach. That
is also what makes the tolerant downgrade safe.

## A survivor I extracted rather than excused

Inline, the two "configured but no key" arms **survived mutation**: with the
flags set, the downstream auth check and `decryptPDU` already refuse, so nothing
could observe the difference. They are not decoration — they are the only place
that names WHICH user and WHICH protocol, and a silent drop is the shape an
operator cannot diagnose — but a guard whose rejected input cannot be driven is a
guard nobody can check.

Pulled out as `usmUserServableAtLevel9155`, every arm is drivable from a table
and **both mutants now die (2 cells each)**. Same repair as #9123's
`ipv4Bytes9123`, and the second time today that extraction turned an
unfalsifiable claim into a tested one.
