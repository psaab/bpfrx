# #9072 — an lo0 reject term with an explicit protocol emitted a dead rule

## The defect

`applyMatches` latches `l4Val` from the term's own protocol (`l4protoSet` →
`needL4proto` for a single value), so the following `a1.needL4proto(protoTCP)`
saw `l4Val != 6` and appended a **second, contradictory** `meta l4proto`
compare: `l4proto==11 && l4proto==06`. Dead by construction.

| term | r00 | r01 |
|---|---|---|
| no protocol | `l4proto==06` → tcp-reset | (bare) → icmpx | *(both live)* |
| `protocol udp` | `==11 && ==06` → **dead** | `==11` → icmpx |
| `protocol tcp` | `==06` → tcp-reset | `==06` → icmpx, **unreachable** |
| `protocol icmp` | `==01 && ==06` → **dead** | `==01` → icmpx |
| `protocol [udp icmp]` | `set && ==06` → **dead** | `set` → icmpx |
| `protocol [tcp udp]` | `set && ==06` → correct | `set` → icmpx |

Note the dead rule **moves** between r00 and r01 depending on the protocol —
which is why fixing only the `needL4proto` end would have left the TCP-only case
untouched.

## Waste or shadow? — the question asked at dispatch

**Waste.** Enforcement is not affected, and this does not claim otherwise. The
icmpx rule always carried the correct family-agnostic reject for the specified
protocols in every case, including the mixed `[tcp udp]` one. Cost was ≤1 dead
rule per explicit-protocol reject term, evaluated as a single failing compare.

Verified rather than taken on trust: `TestRejectTermStillRejectsEveryNamedProtocol9072`
asserts, per protocol case, that a live reject of the right kind survives. That
is the assertion a dead-rule check cannot make, and the one a "fix" that simply
emitted fewer rules would fail.

Filed and fixed anyway because the emitted ruleset is operator-visible in
`nft list ruleset`, where a self-contradictory rule invites misdiagnosis.

## Fix

Emit only the rules the term's protocol can reach:

- **tcp-reset** when TCP is among the protocols, or none are named.
- **icmpx** unless the term is TCP-ONLY, in which case the tcp-reset rule
  already matches everything it could.

The second arm is symmetric with the first rather than an afterthought, because
the table above shows the dead rule moving ends.

## The goldens were silent, not contrary

Checked for contrary evidence rather than assuming its absence:
`TestGoldenRejectTermPair` and the `reject-term` scenario both pin a term with
**no** `Protocols`, and `netlink_lo0_proto_icmp_6806_test.go` never touches
`reject`. So the goldens pin only the no-protocol case. That case is byte-identical
after the fix, and `TestRejectTermWithNoProtocolIsUnchanged9072` pins it here too
— a behaviour change smuggled in beside a cosmetic one is exactly what a
low-severity cleanup is at risk of.

## Mutation matrix

| # | Mutant | Built | Result | Killed by |
|---|--------|-------|--------|-----------|
| M1 | always emit both rules (pre-#9072) | yes | **KILLED (2)** | contradictory-rule + enforcement cells |
| M2 | never emit the tcp-reset rule | yes | **KILLED (2)** | enforcement + no-protocol-unchanged |
| M3 | never emit the icmpx rule | yes | **KILLED (2)** | enforcement (none/udp/icmp/udp+icmp) |
| M4 | `tcpOnly` ignores the other protocols | yes | **KILLED** | enforcement `tcp+udp` |
| M5 | unresolvable protocol decides emission | yes | **SURVIVED — equivalent** | — |

M1, M2 and M3 were **void on their first attempt**: setting the branch condition
to a constant left `tcpReachable`/`tcpOnly` declared-and-not-used, which does not
compile and emits no `--- FAIL`. Re-run with the variables referenced, all three
kill.

**M5 is an EQUIVALENT mutant and its survival is correct.** The
`len(protos) == 0 && err == nil` arm is unreachable: `lo0Protocols` returns one
entry per token or a non-nil error, and `len(t.Protocols) > 0` is already
established. On the `err != nil` path the plan has already failed CLOSED (#6806)
so no rules are installed either way. The arm is kept as a defence against a
future `lo0Protocols` that can legitimately resolve to nothing — and is now
LABELLED as unreachable in the code, so it does not read as load-bearing to the
next person who mutates it.

M4 is the one that matters most: it kills only on `[tcp udp]`, the single case
where both rules are genuinely needed. A `tcpOnly` that ignored the other
protocols would drop the icmpx reject for UDP — a real enforcement change,
introduced by a fix whose whole premise is that enforcement does not change.

## Validation

- 4 cells (13 sub-cases); `go test ./...` — **0 failing packages**.
- No doc file changed: `pkg/nftables/README.md` documents the reject pair's
