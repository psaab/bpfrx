# #9237 — a proxy-ARP responder that dies is never noticed

## Defect

`syncProxyARPResponders` keeps `d.arpResponders.running[name]` as the sole
record of a live responder. A responder goroutine that returns on its own —
socket error, interface removed underneath it, any early return — signals its
exit by `close(r.done)`. In production **nothing read that channel.** The death
signal already existed and had no consumer.

The consequence is not a crash. The map entry survives, so on every subsequent
reconcile the responder takes the *running* branch: its address snapshot is
swapped, the interface is reported as served, and nothing restarts it. The
responder owns no socket and answers no ARP. The only exits are removing
proxy-arp from the config or restarting the daemon.

That failure is invisible in exactly the way that matters: a check that fails
to a value indistinguishable from healthy. `show`-level state and the startup
log both keep saying "started".

## Fix

A generation-scoped eviction sweep at the top of `syncProxyARPResponders`,
under the `d.arpResponders.mu` the function already holds:

- non-blocking `select` on `r.done` identifies corpses;
- the map is re-read and the pointer compared before deleting;
- evicted names are collected and logged **once, aggregated** (`slog.Warn`
  with a count and a sorted iface list) rather than once per responder per
  reconcile — proxy-ARP reconciles run on every commit;
- the loop below then treats the interface as unstarted and restarts it, but
  only if the config still wants it. A death must not re-arm retry debt for an
  interface that is gone.

## Mutation matrix

Every mutant was checked for BUILD before scoring — a build failure emits no
`--- FAIL` and reads exactly like survival. M1 was void on its first attempt
(removing the sweep orphaned the `sort`/`strings` imports) and was re-run with
the imports dropped so it was a valid mutant.

| M1 | remove the sweep entirely (the pre-#9237 code) | yes | **KILLED** (2) | `TestDeadResponderIsEvictedAndRestarted9237`, `TestNoCorpseSurvivesASweep9237` |
| M2 | drop the `<-r.done` check — evict unconditionally | yes | **KILLED** (2) | `TestLiveResponderIsNotEvicted9237` + sibling |
| M3 | drop the pointer-identity comparison | yes | **SURVIVED — expected** | — (see below) |
| M4 | neuter the `reconcileProxyARP` -> `syncProxyARPResponders` **call site** | yes | **KILLED** (2) | `TestReconcileStopsRespondersWhenProxyARPIsRemoved8621`, `TestTheEarlyReturnStillStopsResponders8621` |

M4 is the wiring column. The new cells drive `syncProxyARPResponders` directly
— `reconcileProxyARP` resolves interface names through netlink, which a unit
test cannot reach — so on their own they would not notice the worker being
disconnected from the reconcile path. Mutating the call site shows two
**named, pre-existing** #8621 cells red, so the wiring is bound even though the
new cells do not bind it themselves.

### M3 survives, and that is the correct result

The identity comparison is **defensive and not reachable as written**: the
sweep re-reads the same map it is iterating, under the mutex it already holds,
so the compared pointers cannot differ. A mutant dropping it therefore
survives. It is kept because the invariant is what matters and the locking that
currently supplies it is incidental — if eviction ever moves off this path
(into the responder goroutine, or behind a shorter critical section) a dead
responder deleting a *replacement* under the same name becomes reachable
immediately, and that race presents as an intermittently missing responder
rather than as a crash.

An earlier version of `TestNoCorpseSurvivesASweep9237` claimed to exercise this
comparison and was **vacuous**: it placed only the replacement in the map, so
the sweep never reached a dead entry at all and the check was never evaluated.
M3 is what exposed that. The cell was rewritten to assert the invariant it can
actually observe, and both the cell and the production comment now state that
the comparison is unexercised rather than implying coverage.
