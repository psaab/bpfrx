# #9070 — the deterministic-NAT reverse lookup rendered a prefix BASE as a host

- **Timestamp**: 2026-09-06
  - **Action**: added `ReverseResult.InternalPrefixLen` — the DETERMINISTIC
    UNIT's prefix length — and carried it onto all three surfaces: the `show`
    render (now `Internal prefix: <base>/<len>`), REST
    (`internal_prefix_len`) and gRPC (proto field 14, regenerated).

    The reverse direction reconstructs the 32-bit subscriber WORD, so its answer
    is the network base of a deterministic unit, not a host. Rendered bare under
    `Internal host:` it read as an exact `/128`.

    **The obvious annotation is arithmetically wrong, and avoiding it was the
    substance of the change.** The unit is the configured prefix PLUS the
    reconstructed word: `/32`-configured -> `/64` unit, `/64`-configured ->
    `/96` unit. Echoing the configured pool prefix would replace an ambiguous
    answer with a confidently wrong one. The value is therefore derived from
    `p.wordOffset` as `(off + 4) * 8`, never from the configured length.

    This is the shape the #9071 note warns about: `detParamsForPool` already
    returns something called `prefixLen` that is 32-or-64 — the CONFIGURED pool
    prefix — sitting a few dozen lines away and answering a similar-sounding
    question. The two are never equal. The new field is named
    `InternalPrefixLen` and its doc comment says explicitly that it is not that
    value, so the next reader does not reuse the wrong one.

    `ForwardResult.Render` is deliberately NOT changed. It shares the
    `InternalHost` field name and the identical render line — the assert that
    caught it fired because the line appears twice — but there the value is the
    exact host the operator supplied, not a reconstructed base.

    Three mutants, each on its own arm, each built before scoring and each
    restore verified by reading the file back: echoing the configured pool
    prefix (`off * 8`) reds the /32 row at 32-want-64; dropping the computation
    reds it at 0-want-64 (the original defect); giving IPv4 a prefix reds the
    IPv4 control. The /64-configured row is the load-bearing one — an assertion
    that merely checked "a prefix is present" would pass the wrong value, so the
    cell asserts `!= 64` with its own message before asserting `== 96`.

    Docs: `docs/deterministic-nat-cgnat.md` gains the configured-prefix ->
    unit table, since the doc previously described the subscriber word without
    saying what the reverse answer's granularity is.
