## Three ratchets spoke, and each said something different

Typing the leaf made its value survive a compile for the first time, which moved
three recorded measurements. None of them was a regression I introduced; all
three were pre-existing facts the broken leaf had made unmeasurable.

1. **#8939 flat-set chain census** — `protocols ospf [passive |
   reference-bandwidth]` entered the loser list on the **OPERATOR** channel.
   Cause: `SetPath` nests the second leaf under the first, and the direct-children
   loop never saw it. Previously scored `vacuous` because the leaf compiled to 0
   in BOTH spellings. **Fixed** with `expandFlatRun`, not registered; the fixture
   now records `walked` 84 -> 85, `vacuous` 45 -> 44, loser list unchanged.
2. **#9156 leaf-run differential** — the two `[reference-bandwidth -> router-id]`
   rows stopped differing (good direction) and `[router-id ->
   reference-bandwidth]` started (the mirror). Both resolved by the same
   `expandFlatRun` fix; the two register rows were **removed**.
3. **#7484 spelling-gate coverage** — both reference-bandwidth leaves fell out of
   `compared` into `unreachable`, because every value pair the gate carries is
   below the 1 Mbps floor (largest: 40962 bits/s). Remedy is the one the test
   itself names and the `pcp` / `ospfnet` pairs already set the precedent for:
   **give the gate a valid pair** (`100m`/`1g`) rather than raise a blind-spot
   ceiling over a leaf that is genuinely comparable.

## Not done, and why

The NAT64/interface-style "accept and truncate" option was rejected: FRR cannot
express a fractional Mbps, and truncating 1.5 Mbps to 1 Mbps changes every
interface cost silently — the same class of failure the leaf already had. The
value is refused with a message naming the unit instead.

## A fourth and fifth signal, from `go test ./...` rather than the touched packages

Neither is in `pkg/config` or `pkg/frr`, and neither would have been seen by a
gate scoped to the diff's own packages.

4. **`TestSnapshotShapeIsPinnedToProtocolVersion8892`** (`pkg/dataplane/userspace`)
   — `ConfigSnapshot` embeds the whole `config.Config` under
   `json:"config,omitempty"`, so renaming `ReferenceBandwidth` moved the wire
   digest. A rename is stronger than the two prior "v10 STANDS" additions (the
   field has no json tag, so its Go name IS its wire key), so the invisibility
   was **measured, not assumed**: the Rust side models the whole subtree as one
   opaque `serde_json::Value` (`userspace-dp/src/protocol/snapshot.rs`), naming
   no field inside it; `grep -rn "reference_bandwidth\|ReferenceBandwidth"
   userspace-dp/src/` returns zero hits; and the field's only consumer is
   `pkg/frr`, Go-side and compiler-checked by the rename. ProtocolVersion is
   deliberately NOT bumped — the handler gates on exact equality, so a bump
   would make a mixed-base pair refuse every snapshot in exchange for a change
   no helper can observe.
5. **`TestTouchedFileCrossedModularityThreshold`** (`pkg/refactoraudit`) —
