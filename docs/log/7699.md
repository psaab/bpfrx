# #7699 — the PPTP control-segment dispatch (stage 2's remaining half)

- **Timestamp**: 2026-09-03
- **Action**: Built the packet-path dispatch — the production JOIN between the
  #8396 control-channel parser and the #8390/#8392 association table. Verified
  the premise from the code first, with positive controls: at `origin/master`
  `learn_from_control_segment` had zero non-test callers, while the same grep
  shape found `gre_keyed_session_flow` wired at `poll_stages.rs:372` and
  `pptp_mut()` wired at `session_glue/mod.rs:904`.

  Shape: `stage_parse_flow_and_learn` recognises a TCP flow with 1723 on EITHER
  side and copies the payload into a shared `PptpControlInbox` reached through
  `WorkerContext` (the `dynamic_neighbors` pattern, under the identical
  constraint its doc states — the caller does not need the learned value for the
  same packet). The worker's periodic drain parses, installs locally and
  broadcasts. Frame and session table are never co-located, which is why neither
  "recognise in `loop_body`" nor "thread `&mut SessionTable` into a stage" works.

  Three decisions worth recording:
  - the interval gate lives inside `PptpControlInbox::take_pending`, not at the
    call site — the caller runs at packet rate, and a call-site gate is one edit
    from per-poll work (the #8399 defect);
  - the drain installs LOCALLY **and** broadcasts: `peer_worker_commands`
    excludes this worker, so a broadcast alone teaches everyone except the
    worker that saw the segment;
  - the inbox is node-shared rather than per-worker, because one drain teaches
    every worker anyway and a per-worker inbox buys only N duplicate parses.

  **Found while doing this and reported rather than silently absorbed:** the
  DATA-channel resolve is also unbuilt. `PptpAssociations::resolve_and_touch`,
  `forget_control_channel` and `note_unassociated` have no production caller,
  and `gre_discriminator.rs:451` returns `None` for
  `TunnelDiscriminator::Pptp(_)`, so a GRE version-1 packet never consults the
  association table. The issue body names only the dispatch as outstanding from
  stage 2. Corrected the two `pptp.rs` doc comments that said the data path
  "reaches this once the packet-path dispatch lands" — true when written, and
  hollowed by this change.

  Validation: 14-mutation table over the five touched production files, all
  killed, no survivors. Full `cargo test` (5191+ cells) and `make test-go`.
