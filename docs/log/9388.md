## Census of the shape

Four production sites build a `SourceNatFlowKey` from a `SessionKey` with
`dst_ip: nat.rewrite_dst.unwrap_or(key.dst_ip)`:

| site | domain | verdict |
|------|--------|---------|
| `nat/source/release.rs:211` | source NAT | **FIXED** — allocate site is `policy_dst_port` (#9034) |
| `nat/source/synced.rs:228` | source NAT | **FIXED** — same record's reserve half |
| `nat64.rs:1482` (`release_nat64_allocation_with_mode`) | NAT64 | **correct as-is** |
| `nat64.rs:1759` (`reserve_synced_nat64_allocation_with_holder`) | NAT64 | **correct as-is** |

The two NAT64 sites are NOT the same defect and must not be changed: the NAT64
allocate site (`poll_descriptor/mod.rs:2482`) passes
`flow.forward_key.dst_port` — the ORIGINAL wire port — and
`Nat64State::forward_decision` (`nat64.rs:1423`) hard-sets
`rewrite_dst_port: None` and is ASSIGNED (`decision.nat = ...`), not merged, so
the NAT64 branch can never carry a moved destination port. Applying the same
edit there would be a no-op today and a latent skew if that ever changed;
leaving it keeps each domain's key derived from its own allocate site.
