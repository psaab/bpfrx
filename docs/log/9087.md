# #9087 — proxy-ARP sweep listed the wrong kernel table

- **Timestamp**: 2026-09-07
- **Action**: Root-caused mechanically. `ReconcileProxyARP` listed existing
  entries with `netlink.NeighList`, which sends `Ndmsg{Family, Index}` with
  `Flags: 0`. The kernel keeps proxy entries in a SEPARATE pneigh table and
  dumps it only for a request carrying `NTF_PROXY` — that is
  `netlink.NeighProxyList`. So `existing` was always empty.
- **File(s)**: `pkg/dataplane/proxyarp.go`

    `ip neigh show proxy` still returned `172.16.80.7 dev ge-7-0-2.80 proxy`.
    The stale-removal loop iterates `existing`, so it removed nothing, ever.
  - fw0 (owner): `proxy-arp reconciled added=1 removed=0` every 30 seconds,
    indefinitely, with the entry demonstrably already installed. A converged
