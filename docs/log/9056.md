- **Timestamp**: 2026-09-07
- **Issue**: #9056 — "83 divergent brace-elision sites are invisible to the #2419
  census BY CONSTRUCTION"
- **Base commit**: `1748e11a2` (`origin/master` at the time of the re-measurement)

## Channel measured

Every number below names its channel, because the four disagree.

| claim | channel |
|---|---|
| the divergence itself (braced vs elided compiled config) | `config.CompileConfigLenient` — the #2419 census's own channel |
| the family converges after the fix | `CompileConfigLenient` AND `config.CompileConfig` (STRICT), asserted separately in `TestSecurityFlagElisionStrictGateAgrees9056` |

| "the elided spelling is silent" (admission precondition) | `CompileConfig` for the accept/reject verdict, `CompileConfigLenient` for the warning count |

`configstore.CheckText` was not used: it wraps the strict compile plus the
schema walk, and the sites in this family are all inside `security`, where the
strict compiler gate is the discriminating layer. The issue body's own table was
measured through `CheckText`; the re-measurement reproduces the same verdicts on
`CompileConfig`.

## Re-verification at the base commit

Live, identical to the issue for the two leaves it was filed on:

```
security { flow { allow-dns-reply; allow-embedded-icmp; } }   dns=true  icmp=true
security { flow allow-dns-reply; flow allow-embedded-icmp; }  dns=false icmp=false
security flow allow-dns-reply;                                dns=false
security { zones { security-zone z1 tcp-rst; } }              tcpRst=false  (braced: true)
security { flow { tcp-session no-syn-check; } }               noSynCheck=false (braced: true)
```

**Two of the issue's claims are STALE at this base and are recorded as such:**

- `security screen ids-option <p> tcp land` (and the other screen flags) are
  **NOT divergent** any more — both spellings compile `land=true`. The screen
  subtree was normalized between the issue's verification SHA (`9bb0e8f11`) and
  this base.
- The count is **93**, not 83. The tree moved; the shape did not.

**The context claim carried into this lane was REFUTED.** A prior lane reported
that a valueless boolean flag "cannot satisfy the `compactNormalizeInScope`
table's admission precondition". Measured by running the pass with a recording
predicate, `security { flow allow-dns-reply; }` asks the predicate
`("flow", "allow-dns-reply")`, and adding that pair converges the site. The
blindness is the CENSUS's (`collectCompactSites`), not the scope table's. The two
are different mechanisms and conflating them would have sent the fix at the wrong
file.

## The measurement

A schema walk over exactly the excluded shape (`args == 0 && wildcard == nil &&
children == nil && !multi`), with the same scaffolding the census uses and
presence/absence as the discriminator:

```
flag sites total = 511
under groups 209   uncompilable 4   unobservable 57   equivalent 148   DIVERGENT 93
```

The standalone probe and the gate's own accounting agree exactly once the arm is
added (`checked 786 -> 1094`, `divergent 50 -> 143`, i.e. +93). Where two
accountings differ, neither number is usable; here they do not.

## Remedy

Two halves, both required.

1. **The instrument.** `collectCompactSites` gains a fourth arm (`flagLeaf`) and
   `compactSite` gains a `flag` field; `runCompactBlockCensus` probes a flag site
   by PRESENCE (`stanza { flag; }` vs `stanza { }`) instead of by two values.
   `synthPair` now REFUSES the flag shape — it used to fall through to the
   `ValueAny` arm and hand back `"xpfaaa"`, producing the non-spelling
   `allow-dns-reply xpfaaa;` — which keeps the other fourteen consumers of
   `collectCompactSites()` on exactly their prior populations while the four
   censuses that can rule on a flag branch on `s.flag`.
2. **The behaviour.** The nineteen `security`-subtree flag sites are admitted to
   `compactNormalizeInScope` (18 pairs; `gateway no-nat-traversal` covers both
   `security ike gateway` and `security ipsec gateway`). Every one was measured
   individually to the rule every earlier family obeys: drop shape `empty`
   (nothing consumes the packed tail today) and SILENT (strict accepts both
   spellings, lenient emits no warning admission would quiet).

The remaining 74 divergent flag sites are recorded in
`testdata/compact_block_divergences_2419.txt` with their drop shape and
classified in `testdata/compact_block_permanent_exclusions_8690.txt`:
65 `open`, 5 `partial` (the wildcard-named `interfaces <if>` flags, which are also
pair-unreachable), 4 `gate-open-question` (the policy terminal actions).

## Found on the way, NOT fixed here

The `SPELLING BOUND` note on the pre-existing `interfaces <if> unit <n> family
inet …` entries in the exclusion register is **STALE**. It says the pass "never
traverses into a braced multi-key container" and that
`family inet { filter input f4; }` is UNREACHABLE to a (container, head) rule,
with `pairsAsked=[]`. Re-measured at `1748e11a2` with a recording predicate,
#8763 closed that gap: `family inet { sampling input; }` asks
`("sampling","input")`, `family inet sampling input;` and
`family { inet sampling input; }` ask `("inet","sampling")`. Every losing
spelling is now pair-reachable. The new entries this change adds carry a
re-measured bound; the older ones still carry the stale one. Filed as issue 9446.
