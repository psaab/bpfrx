# 9055 — an elided routing-instance body was read as the instance's properties

- **Timestamp**: 2026-09-06
- **Action**: re-dispatch an elided body-bearing keyword through the same
  readers the braced spelling uses.
- **File(s)**: `pkg/config/compiler_routing.go`,
  `pkg/config/routing_instance_body_keyword_9055_test.go` (new),
  `pkg/configstore/routing_instance_elision_9055_test.go` (new).

## The shapes, dumped rather than inferred

```
braced   [routing-instances] > [ri1] > [routing-options] > [static] > [route ...]
elided   [routing-instances] > [ri1 routing-options] > [static] > [route ...]
```

The elided spelling puts the keyword's NAME on the Keys tail and its BODY in
Children — so the property loop saw `static` / `ospf`, matched no case, and
dropped it. Both spellings are ACCEPTED, with no error and no warning, through
`configstore.CheckText`.

| keyword | braced | elided |
|---|---|---|
| `routing-options` | `static=1` | **`static=0`** |
| `protocols` | `ospf=true` | **`ospf=false` AND `ifs=[ge-0/0/1.0]`** |

**The `protocols` row is not a plain drop — it is keyword theft.** The OSPF
area's interface token fell through to the `interface` case and was bound as a
VRF member, so one accepted statement produced two wrong outcomes: OSPF
vanished, *and* an interface silently changed routing table. That is an
isolation change, not only a routing one.

## Re-dispatch, not a second reader

The elided body is wrapped in a synthesized node named after the keyword and fed
through the **existing** braced property loop. The alternative — adding elided
cases for `routing-options` and `protocols` — is how this defect started: #8787
created the hand-rolled loop and stopped at three of the eight keywords its own
admission helper names. Two implementations of one keyword is how a switch
drifts a second time.

## A guard that was inert, made exercisable rather than excused

A mutation making **every** keyword body-bearing **survived** the end-to-end
cells. It is inert there for a specific reason: the Keys loop has already
consumed a value keyword's value before the property loop runs, and a value form
carries no Children for the re-dispatch to mis-route. So over-application costs
nothing today — and would cost something the moment a value keyword could carry
a body.

Rather than writing "this mutation survives, correctly" into the source, the
predicate is pinned as a unit in `pkg/config`, where both directions can be
driven. The mutant dies there. *Whether a guard is reachable through its only
caller today is a different question from whether it is right.*

## Validation

Cells drive `configstore.CheckText` — the commit gate — never `CompileConfig`.
This is an operator-reachable divergence, and a cell on `CompileConfig` measures
the tolerant Load/SyncApply channel while reporting on `commit`.

Every assertion compares **elided against braced** rather than against a
hardcoded expectation, so the cells stay true if the braced spelling's own
behaviour legitimately changes.

| mutant | result |
|---|---|
| never re-dispatch (the original defect) | killed by 2 cells |
| drop `routing-options` from the body set | killed |
| treat EVERY keyword as body-bearing | killed **after the predicate cell** |

`go test ./...` green.
