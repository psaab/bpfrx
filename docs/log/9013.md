# #9013 — zeroize unlinked a SYMLINK and reported a clean wipe

- **Timestamp**: 2026-09-06
  - **Action**: refused, rather than unlinked, every factory-reset erase target
    whose final path component is a symlink, and surfaced the skipped paths
    (with their targets) as a typed `*configstore.FactoryResetSymlinkError`.

    Measured at `f37079b8e`, surviving BYTES rather than reasoning from the
    `RemoveAll` docs. Both reported shapes reproduced: a symlinked archive dir
    returned `nil` with 83 bytes and the PSK intact on the target, and a
    symlinked `.configdb` returned `nil` having DESTROYED `master.key` while
    leaving `active.json` (97 bytes, PSK intact). Encryption is conditional on
    `system master-password` (`maybeEncryptTreeJSON` returns plaintext when
    unset), so on a default box that surviving body is the full cleartext
    config and the key-first guarantee buys nothing.

    **Censusing the remedy rather than the two reported shapes found six, then
    seven.** Every erase target leaks the same way: `.configdb`, the live
    config, the rescue config, the audit journal, the numbered rollback slots,
    the INVERSE `master.key`-as-symlink (real key survives, ciphertext erased),
    and — only on the production path — `tls/key.pem`, the device HTTPS private
    key, which the issue never mentions. A control with no symlink anywhere
    confirmed the probe discriminates.

    **The reachability check changed the fix.** `configstore.FactoryResetConfigDir`
    has NO non-test caller: `pkg/grpcapi`'s `zeroizeConfigDir` is a near-identical
    twin and is what production runs, via `PerformZeroizeWipe` (gRPC, and the
    console through the `zeroizeFullWipe` seam). A guard written only against
    the configstore copy — which is where the issue points — would have been an
    inert security fix. The predicate (`configstore.SymlinkTarget`) is therefore
    exported and SHARED, so the guard cannot land on one of the pair again.

    Refusal, not resolve-and-erase: a link may point at a shared, remote or
    compliance volume that is not xpf's to destroy, matching
    `ValidateFactoryResetRoot`'s stated fail-CLOSED doctrine. A skipped erase
    outranks a failed one (#7173's doctrine — only a failure announces itself),
    and the two are `errors.Join`ed so neither is swallowed.

    Eight PRODUCTION mutants, all killed, one per assertion arm: M1 (predicate
    always false) / M2 (`Stat` instead of `Lstat`) / M3 (skips collected but
    never returned) red the refusal arm; M4 (predicate always true) reds the
    CONTROL in BOTH packages — the arm proving the guard did not simply break
    ordinary zeroize; M5 (skip recorded without its target) reds the
    operator-detail arm; M6 (`master.key` checked AFTER its removal) reds the
    ordering arm; M7 (the #7173 ownership skip returning the new type) reds the
    distinct-type arm; M8 (console returning `%v` instead of `%w`) reds the CLI
    wrapping arm.
