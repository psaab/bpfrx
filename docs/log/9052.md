# 9052 — four gates that reported a clean board for subjects they never examined

Shared acceptance: *a gate that did not examine its subject must not report a
clean board*, proved by **mutating the production subject** and confirming the
verdict flips — deleting a gate is a no-op by design and proves nothing.

All four claims re-verified at head before any change. Item 4's count had
drifted 310 → **318**; the other three were exact.

## Item 1 — `test-shim-run` was a prerequisite of nothing

`make test` is `test-go test-rust`, and `test-shim-run` appeared in no
prerequisite list, no ledger row, no adapter and no doc. The only behavioural
coverage of the shim's control flow was reachable solely by someone remembering
its name — the #7766 shape.

**Not made a prerequisite of `test`**, deliberately: it needs root, and a
`make test` that fails without privilege makes the ordinary gate unusable. The
fix is the pair — a named root-capable aggregate (`make test-root`) **and** an
announcement printed by `make test` naming what it did not examine. Silence was
the defect; a green run that says "the shim was not examined" is not a clean
board.

The announcement also states why the #1864 verifier gate is not a substitute:
it is a HEADROOM instrument, and two distinct WRONG fixes of #7494 both pass it.

## Item 2 — the cold-path-flooder crate, and a census blind by construction

44 `#[test]`s reached by nothing: outside both cargo workspaces, no root
`Cargo.toml`, `make test-rust` pinned to `userspace-dp`, and not declared in
`HARNESSES.unreached`. Wired exactly like the sibling out-of-workspace crate
`newflow-gen`, whose pattern already existed one target away. **43 passed, 1
ignored** on the first run — they were all green and nobody could have known.

The census over Rust `#[ignore]` could not see the crate **by construction**:
`SCAN_DIRS` named only the two dataplane crates, so it reported a clean board
over a population it had never looked at. Widened — and it immediately redded
on the bare `#[ignore]` at `src/main.rs:2297` that the issue predicted. **That
red is the positive control**: the widened census failed on the subject it had
previously been blind to, before I fixed the marker.

## Item 3 — a merge criterion citing CI that does not exist

*"Squash merge once CI is green"* was **vacuously satisfiable**: `.github/`
holds only `instructions/`, and the Makefile says there is no CI twice. Replaced
with the actual gate list and when to run each — including the two that get
skipped and whose subjects nothing else examines (`sudo make test-root`,
`make test-failover`). A criterion that cannot be unsatisfied is not a criterion.

## Item 4 — the Go skip census

318 skip call sites, no census, nothing counting them, while censuses already
existed for Rust, shell and python. `scripts/go-skip-census.sh` is the missing
sibling, in their shape: per-bucket counts, floors in a declared file, reds in
BOTH directions.

**The finding the census produced on its first run.** The privilege-dependent
set is split by DIRECTION, and the split is the result:

- **26** cells skip because privilege is **absent**;
- **10** skip because it is **present**.

**No single run examines all 36.** Running the suite as root does not close the
gap — it swaps which subjects go unexamined. Folded into one "root-gated" total
that is invisible, and the obvious remedy ("just run it as root") reads as a fix
when it is a trade.

**The load-bearing design decision is the `unparsed` bucket.** Sites the census
counts but cannot classify — `t.SkipNow()` (no message by construction) and
non-literal messages — are REPORTED with their own floor rather than dropped. A
census that silently drops what it cannot read is blind exactly where somebody
wrote something unusual, and the failure mode is not a wrong number but a number
that looks complete. This is the #9088 lesson applied ahead of time: a row left
the census as `unmeasured` when a strict validator rejected its placeholder, so
the instrument was blind precisely at the containers someone cared enough to
gate. `unmeasured` is not neutral, and neither is `unparsed`.

It deliberately does NOT judge whether a skip is justified: no marker convention
exists on Go skips, so the verdict would be a guess off prose, and a census whose
verdict is a guess trains people to argue with it.

## Three method errors of my own, caught by the work

1. **My selftest's positive controls passed for the wrong reason.** `ROOT`
   resolved one directory short, so the census script was missing, every
   `rc != 0` control fired on the missing file, and three cells reported PASS.
   The MESSAGE assertions beside them are what caught it — an rc-only control
   cannot tell "the gate rejected the fixture" from "the gate never ran". A
   guard now fails the whole selftest if the script is absent.
2. **The census silently read the wrong tree.** It hard-`cd`'d to its own repo
   root, so `GO_SKIP_DIRS=pkg` invoked from a fixture directory scanned the
   REAL tree and reported its 315 sites while the selftest asserted against a
   5-site fixture. `GO_SKIP_ROOT` makes the scan root explicit.
3. **My selftest matched exact column spacing** (`"priv-absent    1"`), which is
   itself the unsound-match shape this census exists to find. Now
   whitespace-tolerant regexes.
