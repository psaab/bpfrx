# 9073 — the sshd validation-failure arm counted nothing

- **Timestamp**: 2026-09-06
- **Action**: count an `sshd -t` failure on the retry path, on its own series.
- **File(s)**: `pkg/daemon/daemon_service_reload_debt.go`,
  `pkg/daemon/sshd_validate_failure_counter_9073_test.go` (new).

## The defect

The validation-failure arm logged and fell through without any counter, so under
a persistent `sshd -t` failure the count stayed **flat** while the retry owner
was running and failing every pass — precisely the distinction the counters were
built to make. Their own contract, where they are declared:

> whether the retry owner is RUNNING and failing (count climbing) or wedged
> (count flat)

Severity is Low, as filed: the operator is not blind. `ManagedServiceReloadOwed()`
stays true and both a WARN and an ERROR fire every pass. Only the **metric**
channel was blind.

## The obvious fix was wrong, and an existing cell said so

My first version called `noteSSHDReloadResult(err)`. That red
`TestReassertRedrivesTheOwedSSHDReload6800`, which states its reason:

> a validation failure is not a reload ATTEMPT, so it must not inflate the
> reload failure count beyond the one the apply already recorded

**A prior decision speaking, and a correct one.** A failing *reload* means
systemd or sshd rejected a config that **passed** validation — a different fault
from one that never got that far. Folding them would have bought this issue's
distinction by deleting #6800's.

## Three states need three signals

| state | `sshd` | `sshd-validate` |
|---|---|---|
| wedged (owner not running) | flat | flat |
| reload failing | climbing | flat |
| validation failing | flat | **climbing** |

`sshdValidationFailures` is exported as a new **series** on the existing
per-service map rather than a new accessor, so it reaches the same Prometheus
surface with no new plumbing — the metric is per-service-labelled and this is one
more label value.

It deliberately does **not** touch `sshdReload`: the debt is already outstanding
(this arm only runs when `sshdReloadOwed()` is true) and nothing was reloaded, so
nothing is paid and nothing needs re-latching. It is purely the missing
observation.

## A fixture note

All three cells failed on the first run — including the two asserting **existing**
behaviour. `reassertServiceReloadDebtOnce` returns early without an `applySem`,
so every arm was passing or failing for that reason rather than the one under
test. The rows asserting behaviour that already worked are what caught it; a
cell that only tests the new thing would have read the early return as the fix
not working.
