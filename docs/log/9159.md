# #9159 — a prefix-scoped `destination-nat off` is never withdrawn from the enclosing translate prefix

## Defect, confirmed at the base commit (`3eec995e5`)

`destination_ips_scoped` (`userspace-dp/src/nat/destination.rs`) builds its
withdrawal set from the EXACT-HOST map only:

```rust
let exact_off: Vec<(&DnatKey, &DnatEntry)> = self
    .entries                               // <- exact-host map
    .iter()
    .flat_map(|(key, entries)| entries.iter().filter(|e| e.off).map(move |e| (key, e)))
    .collect();
```

A prefix-scoped `off` lives in `prefix_entries`, where the registration loop only
does `if slot.entry.off { continue; }`. That suppresses the `off` slot's OWN
registration and withdraws nothing from an enclosing translate prefix, whose
bounded host expansion re-registers the same addresses as firewall-local
proxy-ARP/ND targets.

Meanwhile `match_prefix_slots` is longest-wins, so the `/26 off` DOES win the DNAT
match. The two views disagree: the exempt hosts are not translated and are
simultaneously treated as addresses the firewall owns, so their inbound traffic is
LocalDelivered instead of routed to the real host. The operator's `show` of the
NAT rules looks correct.

This is #6025's defect at a different container. All four of #6025's tests use
`/32`, which is why the prefix arm was never exercised.

## The remedy, and the part that is not a copy of #6025

Withdrawal is only correct for an `off` that **WINS the match**. Withdrawing one
that loses is the same defect with the sign flipped: the address is genuinely
translated, and dropping its registration blackholes working DNAT for every host
in the range.

`match_prefix_slots` decides prefix-vs-prefix by two rules, and **both** are
reproduced in `off_prefix_scope_superset`:

1. **SAME ZONE TIER.** `best_in_tier(true)` (zone-specific) runs to exhaustion
   before `best_in_tier(false)` (zone-wildcard), so a zone-wildcard `off` never
   beats a zone-specific translate prefix. The condition is equality of the zone
   strings.
2. **STRICTLY LONGER.** Within a tier the longest prefix wins, and
   `match_prefix_slots` keeps the FIRST slot among equal lengths.

Rule 1 is the interesting one. `off_scope_superset`'s zone clause is
`off.from_zone.is_empty() || off.from_zone == slot.from_zone` — **sound for an
exact-host `off` and unsound for a prefix one**. Exact-host entries are probed
before ANY prefix (`lookup_with_counter_scoped`), so an exact `off` wins whatever
tier the translate slot is in; a prefix `off` does not. Same clause, different
admissibility by call site. Reusing it here would blackhole a zone-scoped
translate.

On rule 2, an `off` of EQUAL length may or may not win depending on insertion
order, so it is **not** withdrawn. That under-withdrawal leaves the #9159
blackhole standing only for an ambiguous overlap, which is the safe direction:
over-withdrawal breaks working DNAT for every host in the range, while
under-withdrawal preserves the pre-existing behaviour for a configuration whose
outcome was already order-dependent.

The protocol / port / interface / routing-instance / source / L4 clauses are
**factored** into `off_scope_superset_common` rather than duplicated. A
hand-copied second list is a third artifact that can drift from both, and a clause
missing on one side is either a blackhole or a broken DNAT depending on which side
lost it.

## Acceptance table

| Cell | Asserts | Control that distinguishes fixed from broken |
|---|---|---|
| `dnat_prefix_off_inside_broad_translate_prefix_not_local_9159` | three hosts inside a `/26 off` within a `/24` translate are NOT firewall-local | a PREMISE that the `/26 off` really wins the match (else the verdict is about a host the firewall legitimately owns), AND **the host outside the `/26` must REMAIN local** — the leg that reds a "withdraw everything it contains" fix |
| `a_broader_prefix_off_does_not_withdraw_a_narrower_translate_9159` | a `/24 off` must NOT withdraw from a `/26` translate | a premise that longest-wins gives the match to the `/26` translate; this is the cell a naive `off_slot.contains(addr)` reds |
| `a_zone_wildcard_prefix_off_does_not_withdraw_a_zone_scoped_translate_9159` | a zone-wildcard `/26 off` must NOT withdraw from a zone-specific `/24` translate, even though it is longer | a premise that the zone-specific tier is evaluated first; this is the cell that reds if `off_scope_superset`'s permissive zone clause is reused |
| the 8 existing `dnat_off` cells, incl. `dnat_off_exemption_shadowing_broad_translate_prefix_not_local` and its `_v6` sibling | the `/32` case and the negative-scope cases are unchanged | all 8 green — the `/32` positive control the issue names |

The second and third cells exist **separately** on purpose: one mutant covering
both losing-`off` shapes could not show which control is load-bearing, and they
fail for different reasons (length vs tier).
